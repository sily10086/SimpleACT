# Codex 项目记忆

本 Skill 将本机记忆插件与项目内可审查记忆连接起来。插件是可选后端，项目规则和 `.agents/memory/` 才是稳定的工作流边界。

## 会话开始

仅在任务需要历史上下文且对应插件工具可用时，请求记忆插件的会话上下文；普通任务不要求每次查询：

```text
session_start_context(project="<项目名>", platformSource="codex")
```

上下文不可用、插件未安装或返回错误时，回退读取当前项目的 `.agents/memory/` 和相关规则文件。不得因为回退成功就声称插件已完成自动注入。

## 查询历史

插件工具可用时遵循分层检索，避免直接读取大量原始记录：

1. `search`：按主题、项目、类型或文件筛选并获取记录 ID。
2. `timeline`：围绕候选 ID 查看前后文，确认记录是否属于当前问题。
3. `get_observations`：批量读取最终选中的记录。
4. 只有摘要不足以回答精确命令或原始输出时，才使用 `get_tool_uses`。

查询插件记录时优先传入 `platformSource="codex"`，避免混入其他客户端的上下文。

## 文件记忆读取

插件不可用时，先按主题查找 `.agents/memory/<主题>/MEMORY.md`，再读取相关条目；没有索引时，直接查找相关记忆文件。不要一次读取全部主题。

不得假定 `MEMORY.md` 会自动注入会话。用户明确要求回忆时执行相关检索；没有找到记录时说明结果，不补造历史。记忆与当前代码或用户最新指示冲突时，以当前证据为准，并更新或移除过时条目。

## 记录边界

- 经用户确认、对后续任务仍有价值的项目事实、协作偏好或决策背景，写入 `.agents/memory/<主题>/`。
- 用户明确要求记住信息时，按下述格式保存；要求遗忘时，移除对应项目文件条目和索引链接。只有文件记忆被更新时，不得声称插件中的自动观察记录也已删除。
- 不保存可直接从当前代码、规则、Git 历史推导出的内容；项目 `AGENTS.md` 要求的 references 与实际 API 冲突问题仍按“问题记录”规范处理。
- 不保存当前会话的临时状态、未经确认的猜测、密钥或完整工具原始输出。
- 插件的自动观察记录保留在本机数据目录，不复制数据库、日志或 node_modules 到仓库。

## 文件格式与索引

每条长期记忆保存为一个 Markdown 文件，使用以下 frontmatter（填写与内容相符的值）：

~~~yaml
---
name: 重构范围偏好
description: 用户确认的代码简化范围与协作偏好
type: feedback
---
~~~

type 取值为 user（与协作有关的用户背景或偏好）、feedback（用户确认的工作方式）、project（项目事实或决策背景）、reference（外部资料的位置与用途）。反馈和项目决策正文说明规则或事实、原因及适用场景；涉及日期时使用绝对日期。

保存前检查同主题已有条目，优先更新，避免重复。随后在该主题目录的 `MEMORY.md` 中添加相对链接和简短说明。索引只保存链接与摘要，不使用 frontmatter，也不承载完整记忆正文。更新或删除条目时同步维护索引。

## 跨电脑迁移

项目不得写死插件缓存目录或用户目录。换电脑时：

1. 在新电脑安装 Codex，并重新安装/启用 Codex 兼容的记忆插件。
2. 需要保留完整历史时，迁移旧电脑用户目录下的 `.claude-mem` 数据目录；该目录属于本机数据，不提交 Git。
3. 只需要项目长期事实时，直接克隆仓库即可，`.agents/memory/` 继续可用。
4. 插件不可用时继续使用文件记忆，不阻塞正常开发。

插件的具体缓存路径、版本目录和密钥由 Codex 用户级配置管理；项目文件只依赖插件提供的工具协议，不依赖绝对路径。

## 与项目规则的关系

- 本 Skill 只负责历史上下文和记忆边界，不改变任务分级、修改确认、测试授权或 Unity 操作规范。
- 代码、配置和资源的当前状态始终以仓库实际内容为准；历史记忆只能提供线索。
- 发现记忆与当前代码冲突时，采用当前代码，并按项目规则记录需要修正的知识。
