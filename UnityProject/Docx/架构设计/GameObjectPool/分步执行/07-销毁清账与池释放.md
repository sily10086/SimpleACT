## 2. API 合同

| 操作 | 空闲实例 | 借出中（含归还回调期间） | 配置 | 资源引用 |
|---|---|---|---|---|
| ClearUnused | 释放 | 保留 | 保留 | 保留 |
| ReleasePool(force=false) | 无占用时释放 | 有任一占用则整体拒绝，不部分清理后假成功 | 保留 | 随池释放归还 |
| ReleasePool(force=true) | 释放 | 强制销毁 | 保留 | 随池释放归还 |
| UnregisterPool(force) | 按 ReleasePool 规则 | 释放成功才继续 | 删除运行时配置 | 随池释放归还 |
| Shutdown | 全部释放 | 全部销毁 | 全部清空 | 全部归还 |

未创建运行池但配置存在时，ReleasePool 可视为无实例需释放的成功；UnregisterPool 仍删除配置。未知名称返回明确失败，不创建空池。

**自动整池过期（07-F）不是第四个公共入口**，它是模块内部行为，最终调用 `ReleasePool(name, force: false)`：只释放、不注销，配置与 SO 定义保留，下次 `Spawn` 通过 `TryGetPoolOrCreate` 懒建同名新池并分配新世代。不因为自动过期删除配置——那会让后续按名字借出永久失败。自动过期也**不得**使用 `force: true`：强制语义只属于用户显式操作和模块 Shutdown。

资源引用只跟随池的生命周期：ClearUnused 只销毁空闲实例、不动引用；只有池被真正销毁时才把该引用交给 UnloadAsset 一次。UnloadAsset 只做引用计数归还，不保证资产立刻从内存卸载——真正的 AssetHandle.Dispose 由资源池的容量与过期策略驱动。模块没有"单独卸载某池资源"的入口，也不提供手动 UnloadAsset 的公共 API。

强制关闭/外部销毁不伪造正常 OnPoolDespawn：该回调是正常归还契约。业务自身 OnDisable/OnDestroy 仍需承担销毁时释放外部资源的职责。

## 3. 设计思路

后台/延续任务不会因为 GameObject 销毁自动失效；先提高池世代/模块生命周期并取消任务，再销毁实例。所有任务和通知必须带身份，防止包装记录被 MemoryPool 复用后命中另一个对象。

OnDestroy 只能通知，不能在底层池迭代或 Unity 销毁调用栈中修改同一集合。模块 Update 或安全 API 边界集中消费队列；加入“正在消费”防重入标记，不在回调内部递归 Flush。

引用归还的顺序是"先销毁实例、后归还引用"：Object.Destroy 是帧末销毁，同帧立即 UnloadAsset 会让仍在销毁队列里的克隆体失去材质与贴图来源。因此池关闭分两步提交——先销毁全部实例，在实例销毁完成后的安全点再把池保存的那个预制体引用交给 UnloadAsset 并置空字段；字段为空即表示已归还，不重复调用，也不为"万一没释放"再加一层判断。

DestroyedNotice 是 readonly struct，只存捕获的记录/marker 引用和身份数值；普通值入队、按值读取。不在结构体中放销毁行为，也不用 in/out/ref 传递通知。

## 4. 逐目标伪代码

### 07-A、07-B：外部销毁清账

~~~text
EnqueueDestroyed(record, marker, instanceIdentity):
  queue.Enqueue(不可变通知)

FlushDestroyed():
  若已经在 flush -> return
  while queue 非空:
    notice = Dequeue
    若 record 当前身份与 notice 不匹配 -> 忽略旧通知
    CancelDelayedPlan
    capture wasActive = record.IsSpawned
    若后端仍占用:
      调整本层状态到可释放
      backend.Unspawn(record)  // 无激活/业务回调
      根据 identity 重新查询记录
      若已被同步释放 -> 若 wasActive 则 ExitActive()；continue
    backend.ReleaseObject(仍匹配的 record)
    失败则诊断并保留可再次处理的清账状态，不能假装释放成功
    wasActive -> ExitActive()   // 借出对象被外部销毁，等价于归还，必须减池级计数
~~~

**`wasActive` 这一段是池级计时的关键补丁**：业务直接 `Destroy` 掉一个借出对象时，对象不会再走第 06 步的 `ReturnCore`，如果这里不减 `ActiveCount`，池会永远停在"有 1 个占用"，整池过期永远不触发，而监控面板上看起来"池一直有人用"。这是本功能最容易遗漏、且最难在测试中发现的一类静默泄漏。

`ExitActive` 必须在清账确认之后调用，不能在入队时调用：通知可能是旧世代的、可能指向已被复用的记录，只有身份核对通过、后端确实不再占用时，那个"取消一个占用"才是真的。

实际使用记录或 target 参数取决于现有 IObjectPool 签名；适配层应集中此差异。对象销毁后不访问 transform/name，只用提前缓存的诊断字段。

### 07-B：从未激活实例兜底

~~~text
TryAcquire 命中空对象 -> 清账并继续
每次手动 ClearUnused 前处理已知失效项
模块以有界游标抽样检查全实例索引中的 Unity-null 项
发现失效 -> 入同一队列
~~~

有界扫描防止从未激活的预热对象没有 OnDestroy 通知而长期保留统计；不每帧全量 GetComponents。空闲记录数量大时统计可能短暂滞后，应在快照注明状态更新时间；不承诺所有外部销毁同帧反映。

### 07-C：释放与注销

~~~text
ReleasePool(name, force):
  // 不需要处理"正在建池"：建池是同步的（第 04 步），ReleasePool 插不进 TryGetPoolOrCreate 中间
  读取已存在池，禁止触发建池（不得调 TryGetPoolOrCreate）
  非 force 且有任何占用状态 -> false
  pool.MarkClosingAndIncrementGeneration()
  取消该池所有延时和预热请求
  从模块的预热队列（`_prewarmPools`）移除该池      // 建池预热已落地，队列要一起清
  从可访问 pools 字典移除
  后端 DestroyObjectPool -> 每个包装统一注销并销毁
  清理池容器
  实例销毁完成后的安全点 -> Resource.UnloadAsset(池持有的预制体引用)，引用字段置空
  保留 configs[name]

UnregisterPool(name, force):
  ReleasePool 不成功 -> false
  configs.Remove(name)
  不修改源 SO
~~~

引用归还只写在一处，避免 ReleasePool / Shutdown / 异常清理各自调用一次。若归还过程中资源模块抛出异常（传空、引用已被销毁、或该引用不在资产池里都会抛 GameFrameworkException），记录明确诊断并继续释放其他池，不吞掉异常来源；未归还的引用由 Shutdown 兜底处理并计入交付记录。

建池失败时要分清归还责任，否则很容易多还一次：`LoadAsset` 在地址无效或资源加载不到时返回 null，此时池没有拿到引用，**不得调用 UnloadAsset(null)**（会抛 Target is invalid.），直接返回失败即可。同步加载下不存在"取消"这个失败分支，也就没有"加载内部已 Dispose 句柄"这种情况需要区分。底层重名由 `CreateSingleSpawnObjectPool` 自己抛异常，本层不接、也不归还此前取到的引用（见 04 §6.2 第 14 条）。

关闭标记应先于任务取消，避免取消回调中再次借出。容器毁掉不能代替每条记录清账。

### 07-D：模块关闭

~~~text
Shutdown():
  // 不写提前返回：configs 始终非空（readonly + Clear），root 为 null 时销毁是空操作
  // 幂等靠"每一步本身就是可重入的空操作"，不靠状态位判断
  root 置 null 前先摘下引用                       // 跨帧的预热任务恢复后据此作废（建池已同步，不在其中）
  终止任务；不接受新请求
  拍运行池引用快照后依次强制关闭
  清空队列、索引、配置
  销毁模块拥有的根节点
~~~

关闭集合遍历使用稳定列表或移除循环，避免释放回调修改正在枚举的字典。若清理某实例失败，记录并继续释放其他实例，最终明确报告；不要一个异常中断全部关闭。

### 07-F：整池空闲过期（自动释放）

由第 03 步的 `Update` 在 `FlushDestroyed` 与预热推进之后调用，每个池按自己的 `PoolAutoReleaseInterval` 判断是否到了检查点。检查时刻 `LastPoolExpireCheck` 是运行池自己的状态字段（单调秒），不进配置、不进资产。

~~~text
TryExpireIdlePools(now):
  candidates.Clear()
  for 每个运行池:                                   // 只读判定，遍历中不移除字典元素
    if pool.IsClosing -> skip
    if pool.PoolExpireTime <= 0 -> skip          // 该池未开启整池过期
    // 每个池按自己的间隔节流：到点才用本池的 PoolExpireTime 判定一次
    if now - pool.LastPoolExpireCheck < pool.PoolAutoReleaseInterval -> skip
    pool.LastPoolExpireCheck = now
    if pool.IdleStartSeconds < 0 -> skip             // 有借出，或有在途预热
    if now - pool.IdleStartSeconds < pool.PoolExpireTime -> skip
    candidates.Add(池引用 + PoolName + PoolGeneration + IdleStartSeconds)
  for 每个候选:
    复核 池仍是同一对象、世代未变
    复核 ActiveCount == 0 且 _pendingPrewarmCount == 0
    复核 now - IdleStartSeconds 仍 >= PoolExpireTime   // 收集后可能已有新借出
    成功 = ReleasePool(name, force: false)
    失败 -> 记录诊断并保留该池，下一个检查点再试，不在同帧重试
~~~

各处不可省略的理由：

1. **先收集再处理**：直接在 `foreach` 里调用 `ReleasePool` 会移除 `pools` 字典元素，破坏枚举。必须用稳定快照或先收集。
2. **候选是 readonly struct**：按值保存池引用、名称、世代、空闲起点，不使用 in/out/ref。池的可变生命周期状态仍在 `GameObjectPool` 里，不为结构体偏好复制管理对象。
3. **二次复核不可省**：收集与处理之间虽然在同一帧，但前一候选的释放会取消任务、可能触发回调并改变其他池状态；同时 `IdleStartSeconds` 可能已被新的归还或预热改写。
4. **只走 `force: false`**：走到这里时 `ActiveCount` 与预热计数都已为 0，非强制释放本就应当成功。若仍失败（例如存在未清账的外部销毁通知），说明条件尚未真正满足，保留池并等下个检查点，不能改用强制释放"确保成功"。
5. **到期不等于立即销毁**：`now - IdleStartSeconds >= PoolExpireTime` 只是获得候选资格，真正释放发生在检查点，最长延迟一个 `PoolAutoReleaseInterval`。

## 5. 场景边界

无 parent 的对象在自己的池节点下，场景切换不自动回收；业务应在玩法结束归还。若 parent 属于场景，其销毁导致实例外部销毁，模块清账即可，不在 OnDestroy 时尝试重挂挽救。第一版不新增按场景自动迁移实例的规则。
