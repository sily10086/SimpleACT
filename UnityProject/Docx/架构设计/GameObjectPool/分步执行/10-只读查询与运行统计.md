## 2. 快照字段与口径

| 池字段 | 含义 |
|---|---|
| PoolName、AssetName、IsPoolCreated | 逻辑配置与运行池是否建立；建池进行中仍为 false |
| Capacity、MaxInstanceCount、ExpireTime、AutoReleaseInterval、Priority | **实际运行快照**参数 |
| TotalCount | 当前仍受管的全部实例记录 |
| SpawnedCount | `IsSpawned = true` 的记录数，和 Unity 激活状态独立；归还回调期间仍计入 |
| IdleCount | `IsSpawned = false` 的记录数 |
| PeakSpawnedCount | 本运行池世代的借出峰值 |
| CreatedCount | 本世代累计成功创建数量，不随清理减少 |
| ReusedCount | 曾被借出并归还的实例再次成功借出次数；第一次从预热池借出不计复用 |
| FailedSpawnCount | 该池实际借出尝试失败数量；未知池名用模块诊断，不虚构池统计 |
| DelayedCount | 当前有效延迟计划数 |
| PrewarmTarget / PendingPrewarmRequests | 有效预热目标与在途请求数（后者即池级计时的预热阻碍项） |
| PoolExpireTime / PoolAutoReleaseInterval | 池级过期配置值；前者为 0 表示该池未开启整池过期 |
| ActiveCount | 当前借出占用数，与 SpawnedCount 同源：`IsSpawned = true` 的记录数 |
| IdleSeconds | 已连续空闲秒数；存在阻碍项时为 `-1` 或不适用值，由 `IdleExpireBlocked` 解释 |
| IdleExpireBlocked | 不可整池过期的原因：`Disabled`（配置为 0）/ `ActiveLease`（有借出）/ `PrewarmPending`（预热中）/ `None` |
| SnapshotTimeSeconds | 生成快照时的模块单调秒，用于判断"多久前取的数据" |

**`IdleSeconds` 与实例快照里的延时剩余必须共用同一时间基准**（模块单调秒），不能一个用 `realElapseSeconds` 累加、另一个用 `DateTime.UtcNow`，否则面板上会出现"已空闲 3 秒但池总寿命 100 秒"这种自相矛盾的数据。

`IdleExpireBlocked` 存在的意义是把"还剩 12 秒释放"和"因为还有 1 个借出所以永远不会释放"区分开。只给一个数字而不给原因，用户会误以为倒计时在走、只是数字没更新。

实例快照包含 GameObject 引用、InstanceID、`IsSpawned`、LeaseVersion、是否存在延时计划、剩余时间。不得暴露内部 marker、取消源或可修改记录。

`Total = Idle + Spawned` 恒成立——两个桶就是全部记录，没有第三个桶（`PooledInstanceState` 已于 2026-10-25 18:10 删除，不再有准备中 / 归还中的独立计数）。正在销毁但未 Flush 的外部失效项可能暂时滞后，不把数据称为原子级实时视图。

## 3. 设计思路

运行统计由模块生命周期维护，Inspector 只读取。配置存在与运行池存在分开，查看某个"尚未使用的配置"不得触发建池或预制体加载；没有运行池的配置一律按"未建池"返回。建池是同步的，查询侧不存在"正在建"这个中间态。

快照是值拷贝，填充方法使用调用者传入 List，避免每次刷新强制新建集合；结构含字符串/Object 引用，并非深克隆。读取及填充都限定 Unity 主线程。

两个快照使用 readonly struct，构造函数一次赋值；属性仅 get，不使用 internal set。FindPoolInfo 按值返回 GameObjectPoolInfo?，不存在返回 null；Nullable 值类型本身不要求装箱。数据结构体不实现多态接口，不转 object，不使用 in/out/ref 参数。列表内部使用泛型元素，修改统计后重新构造快照而非修改已发布快照。

查询不 Flush 销毁队列来“顺便修复状态”；清账属于 Update 或变更 API 安全点。这样单纯查看不会引发 Destroy、业务回调或计数变化。

## 4. 逐目标伪代码

### 10-A、10-C：池级查询

~~~text
FindPoolInfo(name) -> GameObjectPoolInfo?:
  configs 中无名称 -> return null
  若有运行池 -> return new GameObjectPoolInfo(运行状态值)
  否则 -> return new GameObjectPoolInfo(IsPoolCreated=false, 全部计数0)
  不触发建池、不加载资源
  池级过期字段：
    IdleSeconds = (IdleStartSeconds >= 0) ? Max(0, now - IdleStartSeconds) : -1
    IdleExpireBlocked = PoolExpireTime <= 0 ? Disabled
                     : ActiveCount > 0 ? ActiveLease
                     : _pendingPrewarmCount > 0 ? PrewarmPending
                     : None
  读取 IdleStartSeconds 只是值拷贝，不写回、不触发结算、不改变计时

FillPoolInfos(output):
  output.Clear()
  遍历配置，将已建/未建池均转换为快照
  不返回 _pools.Values 等内部容器视图

ContainsConfig(name): 只查 configs
HasPool(name): 只查 pools，且要求未 closing
~~~

### 10-B、10-C：实例与归属查询

~~~text
IsManaged(go):
  查 InstanceID
  核对真实 GameObject/marker 身份（Marker 已被摘除即为不受管）

IsSpawned(go):
  IsManaged 且记录的 IsSpawned 为 true

FillInstanceInfos(name, output):
  output.Clear()
  若运行池不存在 -> 返回空
  遍历该池当前记录，复制 IsSpawned/引用/租约
  延时剩余 = Max(0, request.deadline - 同一真实时间基准)
~~~

快照保留 HasDelayedDespawn 区分“没有计划”和“即将到期”。

### 10-D：统一计数变更

~~~text
EnterActive(record) / ExitActive(record):
  唯一的 ActiveCount 变更入口，必须与 record.IsSpawned 同时提交
  不在外层 API 再重复计数
  // 没有"状态转换表"可查：实例级只有 IsSpawned 一个布尔（04 步已删 PooledInstanceState）

OnSuccessfulSpawn(record):
  更新峰值
  若 record 曾被成功借出 -> ReusedCount++
  标记已成功借出

OnInstanceRegistered / OnInstanceReleased:
  调整 Total 和累计创建
  Release 身份已注销 -> 幂等，不重复减
~~~

如采用按记录统计部分字段，明确哪些是累计计数、哪些是快照计算，避免维护两套可能不一致的总数。第一版不统计没有依据的内存字节数。

- [ ] 10-A 池级字段口径清楚，可表示未创建池。

- [ ] 查询 API 不依赖 UnityEditor 或 Monitor。
