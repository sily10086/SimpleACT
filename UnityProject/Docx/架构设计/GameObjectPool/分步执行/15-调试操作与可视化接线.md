## 2. 操作合同

| 按钮 | 调用能力 | 用户可见结果 |
|---|---|---|
| 定位配置/资源/实例 | Editor Ping/Selection | 只定位，不改变借出状态 |
| 预热到目标总量 | PrewarmAsync | 显示完成/拒绝/取消/关闭，不展示虚假成功 |
| 清空该池闲置 | ClearUnused(name) | 只处理 Idle，仍借出实例保留 |
| 清空全部闲置 | 逐池清理或模块对应 API | 只处理当前有效池，不创建未用池 |
| 释放池 | ReleasePool(false) | 无占用才释放，配置保留 |
| 强制释放池 | 显式确认后 ReleasePool(true) | 明确将销毁借出与瞬态占用对象 |

**"释放池"按钮与自动整池过期的关系**：两者调用同一个 `ReleasePool(false)` 入口，区别只在触发者与时机。手动释放立即执行、不看空闲时长；自动过期要等两个阻碍项归零并达到 `PoolExpireTime`，且在下一个检查点才生效。因此调试时手动点击释放，无论池是否"过期"都应成功（只要无占用），不能因为计时未到而被拒绝。

反过来说，自动过期不会碰 `force: true`。用户点击强制释放是显式危险操作，需要确认文案；系统自动过期绝不允许升级成强制销毁，否则会出现在无人察觉的时刻销毁业务正在使用的对象。

第一版不提供“任意实例强制归还”按钮，避免面板基于过期快照误操作新租约；若以后增加，命令需包含租约条件。

## 3. 类型与设计思路

命令只携带 Kind、PoolName、PoolGeneration、目标数、快照生命周期等数据，使用 readonly struct 和 enum。不要为每次点击创建捕获可变 record 的 Action 闭包；统一 ExecuteCommand 按枚举转发。

Inspector 自身作为行为对象使用 class。异步操作完成源和取消状态有生命周期，不能简单改为可复制结构体；复用运行模块公开 API，不另建编辑器预热循环。

所有修改命令在当前快照枚举结束后执行，防止点击按钮时边画边删集合。点击时与执行时都可能存在状态变化，执行前核对模块和池世代。

## 4. 逐目标伪代码

### 15-A、15-B：命令入队与执行

~~~text
绘制池按钮时:
  点击 -> pendingCommand = new readonly Command(kind, poolName,
                                  moduleVersion, poolGeneration, target)
绘制所有列表结束:
  若有 pendingCommand:
    重新查询现有模块
    生命周期/池身份不匹配 -> 显示“状态已变化，请刷新”
    否则 ExecuteCommand(command)（结构体按值传入）
    请求刷新
~~~

~~~text
ExecuteCommand(command):
  Prewarm -> 提交独立请求；显示忙碌/结果，不阻塞 OnGUI
  ClearUnused -> 调运行 API
  Release:
    当前存在占用 -> 显示占用数与强制释放确认
    用户取消 -> 无动作
    用户确认后重新读取状态:
      若身份或占用范围已变化 -> 刷新并重新确认
      否则 force=true
  Ping -> 对有效 Object 执行定位
~~~

确认文案必须明确“销毁仍借出的对象”，不能仅写“释放内存”。这里是工具运行时用户点击危险操作的产品交互，不是让 AI 每次普通编辑都额外询问权限。

Inspector 关闭只取消它发起的预热等待/请求，不 Shutdown 模块，不清空业务预热请求。已创建的预热实例按模块合同保留。
