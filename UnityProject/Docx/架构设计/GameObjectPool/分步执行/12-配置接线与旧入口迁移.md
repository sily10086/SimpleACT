# 第 12 步：配置接线与旧入口迁移

前置：第 01—11 步运行功能完成，配置类型已可供 Unity 使用。  
本步完成后：主功能从配置到玩法形成闭环，旧入口迁移结束，才开始新的编辑器功能。  
状态：待实施；Unity 资产操作和编译/运行验证是不同授权范围。

## 1. 目标与改动内容

| 目标 | 路径/对象 | 改动与功能 |
|---|---|---|
| 12-A | 现有 Assets/TEngine/Settings/GameObjectPoolSetting.asset | 解决脚本引用与配置字段，优先复用 |
| 12-B | Assets/TEngine/Settings/Prefab/GameEntry.prefab 的 Settings（只读核对） | 已绑定唯一 Setting；只核对引用未断裂，不重做绑定、不保存 prefab |
| 12-C | 真正需要池化的候选资源与调用方 | 配置池名、YooAsset 地址与数量，按新 API 和坐标语义迁移 |

| 12-E | 本组文档状态与第 01 步迁移表 | 记录主功能完成门槛 |

本步不添加 Monitor，不制作配置 Inspector；默认 Inspector 足以接线。可序列化配置项使用普通 struct，字段更改通过 Unity 序列化属性或完整值写回，不修改集合元素的临时副本。

## 2. 设计思路

现有 Setting.asset 已存在，不能无条件再建一份。先核对 m_Script 与 GameEntry 引用。若恢复类型时丢失旧脚本 GUID，通过合法 Unity 资产流程修复；不手写 YAML/GUID 伪造绑定。

配置资产固定在 `Assets/TEngine/Settings/GameObjectPoolSetting.asset`，**不移动**：GameEntry.prefab 已按 GUID 引用它，移动只会制造一次引用断裂。全工程只有这一份主配置，不新建第二份；`Assets/GameSettings/` 是 wiring 工具的过时路径常量，不按它建目录。

## 3. 逐目标操作与伪代码

### 12-A：资产复用

~~~text
现有资产类型和脚本引用正常 -> 复用
现有资产失联 -> 先恢复/迁移引用，不用新资产掩盖问题
确实无可用资产 -> CreateAssetMenu 创建一份
~~~

手工操作在 Unity 可用且 C# 无编译阻断时执行：

1. Project 定位现有 Setting.asset，确认 Inspector 能识别类型。
2. _pools 暂时为空也合法；每帧预热与整池自动释放间隔都是条目字段，新增条目时填默认值 4 / 5。
3. 有真实业务资源时逐条填名称、YooAsset 地址（AddressByFileName：文件名去扩展名）、预热、容量、硬上限及清理参数。
4. 池级过期 `PoolExpireTime` 默认留 0（关闭）。只为确实需要回收内存的池开启，并注意它会把运行池连同空闲实例一起销毁，下一帧首次借出要重新建池（含预制体加载）。
4. 预热目标不得超出当前保留能力。没有候选资源时不把 UI 资产随意填入；地址必须能在资源包内定位到预制体，否则建池时会明确失败。
5. 保存目标资产，不全局保存无关场景。

GameEntry.prefab 的 Settings 组件**已经**序列化 `gameObjectPoolSetting`，指向 guid `6f84142c2e191eb44a0c7aa34a3f5b0a`（第 01 步 §6.5 实测，prefab 第 355 行）。所以本步只核对：

~~~text
打开 GameEntry.prefab 的 Prefab Mode（只读查看）
核对 Game Object Pool Setting 指向 6f84142c2e191eb44a0c7aa34a3f5b0a
核对 Audio Setting / Procedure Setting / Update Setting 原引用未变
核对全工程只有一份 GameObjectPoolSetting 资产、不存在第二个匹配节点
不拖入资产、不保存、不添加 Monitor 节点
~~~

只有核对发现引用断裂（Missing）时才需要修复，且修复方式是恢复对**同一份资产**的引用，不是新建资产或改 GUID。

### 12-C：迁移调用方

~~~text
for 第 01 步发现的调用方:
  根据用途选 Spawn(World) / SpawnLocal
  CreatePool -> RegisterPool
  预热入口按启动顺序前移，避免玩法中首次建池加载
  延时入口 -> 新租约安全方法，处理取消/失败
  查询 -> IsManaged / IsSpawned / FindPoolInfo
  结构体结果按值读取；不用 in/out/ref 传递
  明确 parent 的场景生命周期和玩法退出归还时机
~~~

无实际调用方时记录检索范围，不创建无需求的演示业务，也不声称所有外部程序集都已迁移。

### 12-D：处理旧代码

~~~text
源码/反射/序列化引用均已分类:
  不再需要 -> 合规移除旧脚本和对应 meta
  暂不能迁移 -> 窄适配层仅转发到新模块
适配层不得保留第二套池字典、根节点、资源加载和定时任务
~~~

仅移除对象池对 TbPoolMap/ConfigSystem 的依赖，不删除其他 Luban 系统。新旧实现不能同时持有同一实例的所有权。
