## 2. 行为合同

- Spawn(name, position, rotation, parent) 使用**世界坐标**。
- SpawnLocal 使用局部坐标。薄重载不能隐式切换空间。
- 无 parent 时实例留在自己的池节点下（建池时就挂在那里，借出不搬迁父节点）；有 parent 时挂到调用方给的父节点，包括处于禁用层级的 parent。
- 设置 parent 后恢复预制体初始 localScale（从池持有的预制体读取，不用克隆体当前值）；不承诺在带非均匀缩放父节点下保持固定世界缩放。
- Spawn/TrySpawn 不建池：池未建时直接返回明确失败，不隐式加载。建池点由调用方显式决定——`SpawnAsync` 原本是为了 `await` 跨帧建池，建池改同步（第 04 步，2026-10-25 18:25）之后它已取消，借出统一走同步的 Spawn / TrySpawn。
- Spawn<T> 获取根节点上的 T；找不到时失败，不擅自搜索子节点替调用者选组件。
- 借出对象即使 activeInHierarchy=false，仍是 Spawned，不能被当空闲实例。
- 达到 MaxInstanceCount 且没有有效空闲实例时 TrySpawn 返回 Success=false 的结果，不抢占现有借出对象。
- 业务回调可准备刚体、粒子、事件等；核心只保证生命周期，不自动推断所有组件复位方式。

PoolSpawnContext 建议是 readonly struct，提供 PoolName、GameObject、目标 Parent、LeaseVersion、是否首次借出。不得把可修改的内部记录传给业务。

PoolSpawnContext 使用普通值参数：OnPoolSpawn(PoolSpawnContext context)，不使用 in/out/ref。TrySpawn 按值返回 readonly PoolSpawnResult，泛型版同理；成功标志和实例引用通过构造函数赋值，不使用输出参数，不以 object/接口存取而装箱。

## 3. 设计思路

将“取得占用权”和“激活”分开。后端 TrySpawn 只完成包装的占用；上层先设变换并调用准备回调，再激活。这样 OnEnable 能看到最终变换。

首次在 inactive 层级创建时，Awake/Start 不一定已按业务预期执行；准备回调应使用序列化引用或自行保证初始化，不能默认依赖 Awake。接口注释必须写明这一点。

Unity API 和业务回调都可能触发重入。记录会被释放甚至复用，因此跨回调捕获 marker、实例身份、池世代和租约；不能只检查 record 非空。

## 4. 逐目标伪代码

### 05-A、05-B：集中取得实例

~~~text
TrySpawn(name, worldPosition, worldRotation, parent):
  return SpawnCore(World, ...)

SpawnLocal(...):
  return SpawnCore(Local, ...)

TryAcquire(pool):
  尝试 backend.Spawn(池名)      // 必须带名字，无参重载按空名字分组，永远命中不了
  while 取得候选但 GameObject 已失效:
    走失效清账路径（第 07 步），继续寻找
  无可用候选:
    Total >= 非零 MaxInstanceCount -> 失败
    CreateInstance(spawned = true)
  返回占用中的记录
~~~

硬上限判断放在“需要创建新实例”之前；有闲置时即使总量等于上限也允许复用。

### 05-C、05-D：准备后激活

~~~text
Spawn(name, position, rotation, parent):
  要求模块 Running
  池未建 / 已关闭 -> 明确失败（Spawn 不触发加载，建池走 TryGetPoolOrCreate）
  return SpawnCore(pool, ...)  // 资源在建池时就已就绪，这里不访问资源模块

SpawnCore(pool, ...):
  要求模块 Running
  池未建 / 已关闭 -> 明确失败（Spawn 不触发加载）
  record = TryAcquire(pool)
    // 空闲复用 -> IsSpawned = true；无空闲 -> CreateInstance(true)，创建时已按占用注册
  capture identity = (poolGeneration, marker, instanceIdentity)
  EnterActive()          // ActiveCount++；IdleStartSeconds = -1，本轮池级空闲计时作废

  若请求泛型组件:
    component = clone.GetComponent<T>()
    缺少 -> 归还未进入业务准备的记录并失败

  record.BeginLease()
  capture lease = record.LeaseVersion
  clone.SetActive(false)
  若 parent != null:
    clone.SetParent(parent, false)   // 无 parent 时本来就在池节点下，不搬父
  检查 identity/lease 是否仍有效
  按 space 写 position/rotation
  clone.localScale = 池持有的预制体初始 localScale
  按缓存顺序调用 OnPoolSpawn(context)
  每次回调后核对当前身份仍归本次操作
    // 回调里若自己归还了，IsSpawned 已被清掉，本次借出直接判失败

  clone.SetActive(true)
  再核对身份、lease、占用状态
  匹配才返回本次借出的 GameObject/组件
~~~

`EnterActive()` 在**取到实例的那一刻**调用：复用空闲与新建两条路径都在 `Spawn` 里合流，占用标志与 `ActiveCount` 由它统一加一次（`CreateInstance` 本身不动计数，否则预热创建也会被算成占用），与第 06 步提交为空闲时调用的 `ExitActive()` 严格配对。**2026-10-25 18:10 起不存在"准备阶段不计入 `ActiveCount`"的中间态**：04 步已定"借出扩容必须直接按占用注册"，否则 `Capacity = 0` 或已达上限时空闲注册会当场释放手里的实例、借出方拿到死引用。所以占用标志与计数从取到实例时就成立，准备失败的回滚必须配对 `ExitActive()`，不能"什么都不做"。原文担心的"漏一条回滚就让池永远停在有占用"这条风险仍成立，只是它现在由 `05-E` 的每条路径显式承担——回滚的含义是"把占用标志与计数一起退回去"。

SetParent 等可能触发 Unity 消息的边界也需要核对。OnEnable 中若已经归还/销毁/再次借出，本次 Spawn 应失败，不能把新的租约当作自己的结果返回；也不能错误回滚新的租约。

### 05-E：回滚规则

~~~text
缺泛型组件（尚未调用业务准备）:
  清掉占用标志并 backend.Unspawn（已 EnterActive 过则配对 ExitActive）
  不调用业务 OnPoolDespawn
  返回失败；Unspawn 后不再盲用 record

准备回调抛异常:
  只在同一身份/租约仍归本次操作时执行回滚
  对已进入的回调做配对清理，包括抛出前部分执行者
  丢弃本次失败实例，确保从索引和后端移除
  已 EnterActive -> 走 ExitActive 配对，不能少减
  记录池名/回调类型，保留原异常
  清理异常单独记录，不覆盖最初异常

准备阶段尝试回收自身:
  当前仍是本次借出的占用态 -> 明确拒绝并诊断
  不进入普通归还路径
~~~

回滚中如需强制销毁，复用第 07 步统一入口；不要为回滚另建一套索引删除逻辑。
