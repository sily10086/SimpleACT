# SimpleACT 美术、音频与反馈

日期：2026-10-24；分析稿 v0.1。对应原文 §1.4、§9–10；依赖 D15–D17。本稿定义技术制作方式，正式素材数量、尺寸和音频文件规格仍待美术/音频启动后确认。

## 1. 系统分工

FeedbackModule订阅已提交事件，映射至音效、音乐状态、粒子、着色、镜头脉冲和手柄震动。每项效果有EventId去重，不反向改变战斗/奖励。CameraDirector独占相机最终变换，反馈仅提交效果请求，避免多脚本同时写Transform。

统一事件：TierChanged（原因含升级/技能掉档/落地）、TimeStopStarted/Ended、DodgeSucceeded、ParrySucceeded、EnemyKilled、SupplyTaken、PlayerDied、RunCleared、StaminaExhausted。技能掉档不能错误播放完整落地清零效果。

## 2. 几何水彩制作

| 元素 | 视觉规范 | 技术制作 |
|---|---|---|
| 玩家 | 暖亮胶囊，最高饱和 | 占位Sprite→清晰实色轮廓+内部水彩纹理；Visual缩放不改碰撞 |
| 敌人 | 冷暗胶囊，次级饱和 | 前摇和攻击范围优先可读，身体接触致死规则待D15 |
| 地刺/子弹 | 尖三角 | 危害轮廓清晰，逻辑形状与视觉偏差有上限 |
| 岛 | 横长方形 | 顶面支撑明确；落地反馈不能隐藏支撑边缘 |
| 补给 | 圆形、温暖 | 拾取事件后淡出/回池，重复播放不重复加耐力 |
| 背景 | 低饱和云层 | 单独Sorting Layer、无逻辑碰撞，视差不决定关卡几何 |

URP14/2D Renderer已由资源引用确认。首版优先Sprite材质内部颗粒和边缘处理，不直接增加全屏昂贵水彩滤镜。正式RendererFeature需要核对URP14接口；[Unity Graphics](https://github.com/Unity-Technologies/Graphics)是源码参考，不能用Unity6示例的RenderGraph接口照搬。

时停“世界灰、玩家彩”推荐给角色/环境共用材质加分组饱和度参数：非玩家材质读世界饱和度，玩家不读该值。这样不必先上双相机。若天空/粒子/UI等不共用该材质，需逐类明确排除；后期全屏方案则需要player mask/stencil，不能全屏降饱和后声称玩家自动保彩。

死亡通过Visual溶散/水彩扩散；判定在死亡Tick已关闭，不能等动画结束才去掉碰撞。击杀碎片、升档粒子、闪避尾迹都为池化View；回收时清粒子/拖尾/材质状态，后续新实例不继承上次时停褪色。

## 3. 分层音乐

原文“6层”实际上列出0档静音+1–5档五个stem，静音不是音频文件。建议5个同长度/同拍号/同起点stem同步播放，通过音量控制层数。音频负责人需确认BPM、循环样本数、前导静音与尾音处理，单纯同调性不足以无缝叠加。

现有AudioModule可播放音效，读取AudioAgent发现内部调用AudioSource.Play，未发现已实现多stem共同DSP起点。新增DynamicMusicController管理专用AudioSource组，加载仍走GameModule.Resource；各轨共享一个未来dspTime，使用PlayScheduled而不是逐条Play。Unity2022.3的[PlayScheduled文档](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/AudioSource.PlayScheduled.html)支持按DSP绝对时间安排播放。

```text
LoadStemsAsync -> 检查格式/循环长度一致 -> 确定共同DSP起点
所有stem同一时刻启动，未启用层音量为0
TierChanged: 改变目标音量，不把新增stem从第0秒重新播放
TimeStopStarted: duck音乐，保留效果音
TimeStopEnded: 恢复“当前档位”的目标，而非旧档位
ExitSession: 停源 -> 解除引用 -> UnloadAsset(AudioClip)
```

升档五声音阶采用独立短音，不为播放音阶重启BGM。落地骤停与从第一层重进、0档静音的冲突由D16确认；方案可以执行静音/恢复状态，不替策划选择最终音乐规则。

死亡音乐不停为原文待定项，推荐继续同一DSP相位并抑制强烈层，重试是否重置曲目需确认。暂停可暂停组或继续底乐，但恢复所有stem必须保持对齐；不能单独用逻辑时停冻结AudioSettings时钟。

## 4. 反馈表与强度控制

| 事件 | 音效 | 画面/镜头 | 去重/结束 |
|---|---|---|---|
| 升档 | 对应五声音阶 | 刻度/轻粒子/目标镜头更新 | 每次真实TierUp一次 |
| 弹刀/精准闪避 | 高频叮+余韵 | 灰世界、彩玩家、短推近 | 同一时停只启动一次 |
| 砍弹 | 较轻确认音 | 较短时停，配置倍率 | 不与弹刀重复叠奖 |
| 落岛 | 短闷响 | 轻下沉/褪色 | 只响应落地边沿 |
| 死亡 | 圆润滴落 | Visual扩散 | 清理旧震动/时停效果 |
| 补给 | 温暖短音 | 圆形消失与资源提示 | supplyId一次 |
| 通关 | 收尾旋律 | 结果过渡 | 结算幂等，展示可重复刷新 |

手柄震动是可关闭的表现。设备断开、暂停、退出、对象销毁时停止马达；旧Attempt的异步震动不能在新局继续。震屏强度/减少闪烁设置建议提供，范围由产品确认。

Tween可参考 [LitMotion](https://github.com/AnnulusGames/LitMotion) 的取消与生命周期绑定；不是已安装依赖，也不用于精确攻击帧。少量效果可直接用统一反馈计时器，是否引库由重复需求决定。

## 5. 制作目标与未来验收

- [ ] 定义FeedbackProfile及事件映射，区分掉档原因和效果优先级。
- [ ] 占位阶段：基础音效/颜色/粒子可读，先不等待正式水彩素材。
- [ ] 正式材质：世界/玩家分组、死亡溶散和粒子一致性。
- [ ] DynamicMusicController：异步载入、DSP对齐、音量层控制和恢复。
- [ ] 资源与手柄生命周期：退出停止、回池复位、取消旧任务。

未来验收：高速仍认得敌人/地刺；时停玩家保彩且UI可读；stem连续升降档不失拍；时停落岛结束后恢复到新档位；死亡无刺耳重复音；震动退出必停。未运行视觉、音频或设备测试。
