## 1. 游戏概述

### 1.1 一句话好玩假设

> **这游戏好玩的核心是：玩家用“不落地”当赌注，把速度越滚越大，速度再兑换成能力和生存——每一步都在拿风险换力量。**
> 

写不出来这句话，这个项目就不立项。现在写出来了，往下走。

### 1.2 游戏定位

| 项 | 内容 |
| --- | --- |
| 品类 | 横版跑酷 + ACT（平台跳跃 × 一击必杀战斗） |
| 平台 | PC，键鼠/手柄 |
| 用户 | 休闲大众（低难度可通关）＋ 操作硬核玩家（高难度竞速） |
| 单局 | 约 15 分钟 |
| 变现 | 买断制单机（独立游戏定位），无内购 |

### 1.3 游戏特征（别人没有的东西）

1. **一招定生死**：玩家和敌人都是 1 滴血，碰到即死。没有血条博弈，只有决策博弈。
2. **不落地引擎**：玩家唯一的管理资源是耐力；不落地则速度档持续上涨，档位越高耐力消耗越低、回得越快、能力越多；落地瞬间清零。
3. **速度 = 自我难度**：速度档越高，镜头锚点越靠左、回退空间越小、视野越大——高速少退路，玩家自己选择玩多难。
4. **地刺地图**：地面几乎全是地刺，可站立的“岛”只占一小部分，落岛是主动的保命决策而非失败。
5. **成就式领奖点**：高难度关卡不设检查点，改设“完成挑战即领奖”，死亡不回收已领奖励。
6. **水彩几何视觉**：圆方三角胶囊的形状语言 + 水彩上色，高速下靠形状认敌，不靠细节。

### 1.4 游戏风格（画面与音乐的直观感受）

- **画面**：简单几何（圆/方/三角/胶囊）拼出世界，水彩上色，参考 GRIS / NEVA 的大面积水彩色块云层作背景。看着像治愈小游戏，玩起来一招定死——画风与硬核的反差本身是卖点。
- **音乐**：原声乐器（木吉他/钢琴）+ 电子节拍。音乐随速度档分层叠加，落地清零瞬间全部抽空；升档是一串五声音阶。
- **整体感受**：柔和的外表，尖锐的内核。

### 1.5 设计支柱（不可妥协的五条）

之后每一个决策，用这五条过审；冲突时以序号小的为准：

| # | 支柱 | 含义 |
| --- | --- | --- |
| P1 | 一招定生死 | 玩家与敌人均 1 滴血，不做血条、不做伤害数字 |
| P2 | 只管理耐力 | 玩家界面上只需要关心一条耐力条，其他信息用视听反馈替代 |
| P3 | 不落地换速度 | 滞空是核心赌注，速度档是唯一“变强”通道 |
| P4 | 同一张图，多种活法 | 高手全程不落地，新手靠岛保命，没有唯一正解 |
| P5 | 挫败感有出口 | 任何失败都必须留下可见的收获（挑战奖励/进度梯度），禁止“白跑” |

## 2. 核心机制（设计意图层）

> 本章给主策、制作人、美术、音乐看，讲“为什么这样设计”。程序直接看 §3。
> 

### 2.1 核心循环（三层钩子）

| 层 | 时长 | 循环 | 玩家此刻在做什么决策 |
| --- | --- | --- | --- |
| Moment-to-moment | 0–30 秒 | 飘 → 看刺 → 弹刀/精准闪避 → 升档 → 继续飘 | 这一刀挡不挡？这个闪避按不按？ |
| Session loop | 5–30 分钟 | 攒档 → 冲挑战 → 落岛保命 → 领奖 → 下一局 | 现在落岛还是再撑十秒？这局带什么模组？ |
| Long-term | 小时–周 | 掉模组 → 配 build → 刷种子竞速 → 挑战高难度 | 我的build 下一步缺什么？这张图能不能再快 10 秒？ |

### 2.2 三系统咬合图（文字版）

```
     耐力（唯一资源）
       ↑ ↓ 消耗/恢复
速度档（动量引擎） ←—— 不落地就涨，落地清零
       ↓ 每档降低消耗、每升一档回耐力
能力解锁（3 档以上解锁时停）
       ↓
战斗（弹刀/精准闪避进时停，时停回耐力）
       ↓
岛 + 补给（唯一活地：安全 + 回油 + 清零档位）
```

三个系统互相咬合，缺一个另外两个就散：没有速度档，耐力只是普通的蓝条；没有耐力，速度档没有成本；没有岛，新手没有活路。

### 2.3 难度的自适应哲学

难度不做成“数值加码”的滑轨，而是**四个参数联动的风格档位**：

| 参数 | 低难度 | 高难度 |
| --- | --- | --- |
| 岛密度 | 多 | 少 |
| 起步速度档 | 0 档 | 2 档 |
| 敌人前摇（出手预备时间） | 长 | 短 |
| 挑战池 | 松 | 紧 |

高难度不是“同样的游戏但更烦”，是**拿稳妥换爽快的另一门生意**：一起步就在高速上飞，但落地后更难找到活地。低难度服务大众，高难度服务拼刀的人。

同时玩家还有第二条难度轴：**速度档本身**。高手全程挂 5 档（少退路、纯拼刀），普通玩家主动落岛清零降速（换走位空间）——落岛从惩罚变成玩家主动按下的减速键。

## 3. 程序核心模型

> 本章给程序。先建数据模型，再立主循环，最后是必须遵守的确定性铁律。
> 

### 3.1 核心数据结构（伪代码）

```
Level（一关/一局的完整数据）
├── seed: int                    # 地图种子，保留可重玩同一张图
├── difficulty: enum {EASY, NORMAL, HARD, EXPERT}   # 难度档位
├── width, height: float         # 关卡世界尺寸
├── islands: [Island]            # 岛（落脚点）
├── spikes: [Spike]              # 地刺
├── walls: [Wall]                # 空气墙（边界与地形）
├── enemies: [Enemy]             # 敌人
├── supplyPoints: [SupplyPoint]  # 补给道具挂点（挂在岛上，非每岛必有）
└── challengeSlots: [Challenge]  # 本局挂上的挑战（开局按难度抽）

Island（岛）
├── id, x, y, w, h: float
├── hasSupply: bool              # 是否带补给道具
└── supplyTaken: bool            # 补给是否已被吃

Enemy（敌人）
├── id, type: enum {MELEE, RANGER}
├── x, y: float
├── state: enum {IDLE, TELEGRAPH, ATTACK, DEAD}
├── telegraphFrames: int         # 前摇帧数（随难度变化）
└── attackFrames: int            # 出手帧数

Player（玩家，运行时状态）
├── x, y, vx, vy: float          # 位置与速度
├── stamina: float               # 耐力（当前值）
├── staminaMax: float            # 耐力上限（可被模组修改）
├── speedTier: int               # 速度档 0–5
├── airTime: float               # 本次滞空累计时间（秒）
├── jumpsLeft: int               # 剩余跳跃次数（含二段跳）
├── airDodgesLeft: int           # 剩余空中闪避次数
├── dodgeCooldownFrames: int     # 闪避 CD 剩余帧
├── dodgeChainCount: int         # 连续闪避计数（用于递增消耗）
├── dodging: {framesLeft, invincible: bool}
├── attacking: {framesLeft, phase: enum {STARTUP, ACTIVE, RECOVERY}}
├── wallJumpLock: [wallId]       # 已蹬过的墙（同墙只能蹬一次）
├── modules: [ModuleInstance]    # 本局装备的模组（最多 8）
└── alive: bool

RunState（一局的进度状态）
├── progress: float              # 关卡完成度 0.0–1.0（跑图跑了多远）
├── challengesDone: [challengeId]# 本局已完成挑战
├── rewardsClaimed: [moduleId]   # 本局已领取奖励
├── checkpointProgress: float    # 死亡时记录的进度（用于耐久消耗结算）
└── cleared: bool                # 是否通关
```

### 3.2 主循环伪代码（60 FPS 固定步长）

```
每帧（fixed 1/60s）：
  1. 输入采样 → 输入缓冲（见 §3.3）
  2. 更新玩家状态机：
     - 若 dodging.framesLeft > 0：
         framesLeft -= 1
         invincible = (剩余帧来自前 15 帧段)   # 前15帧无敌，后15帧无无敌
     - 若 attacking.framesLeft > 0：按阶段推进
  3. 处理动作请求（跳跃/二段跳/闪避/攻击/蹬墙跳）：
     - 检查耐力是否足够 → 扣除 → 执行 → 进入冷却
     - 耐力不足 → 拒绝执行 → 播放“油不够”反馈（见 §4.1）
  4. 物理更新：
     - 空中移动：stamina -= 1 * dt（每帧扣，按速度档乘消耗系数）
     - 重力、跳跃、蹬墙弹射按各自速度参数
  5. 速度档结算：
     - 若 airborne 且 speedTier < 5：airTime += dt；每 [待定：2] 秒 speedTier += 1
       升档时：stamina += 10（不超过上限）；触发升档视听反馈
     - 若 landed（碰到岛/地面）：speedTier = 0；airTime = 0；触发清零反馈
  6. 战斗判定：
     - 攻击判定框 vs 敌人/子弹 → 命中处理（见 §4.5）
     - 敌人攻击判定框 vs 玩家 → 玩家死亡（一招定死）
     - 玩家无敌帧期间的判定 → 跳过
  7. 岛与补给判定：落岛回油；补给拾取回油
  8. 挑战进度检查：本帧完成的挑战 → 立即发放奖励（死了也不收回）
  9. 相机更新（见 §7.2）
  10. 死亡判定：地刺/子弹/敌人触碰且非无敌 → 进入死亡流程（§4.8）
```

### 3.3 确定性铁律（必须遵守）

| 规则 | 内容 |
| --- | --- |
| 帧数制 | 所有动作时长、判定窗口、冷却，一律以帧为单位定义。同一套输入在同一帧数制下结果必须一致 |
| 固定步长 | 物理与逻辑固定 60FPS 步长；渲染插值。高帧率显示器不得改变游戏结果 |
| 种子确定性 | 同一种子 + 同一难度 + 同一串玩家输入，必须产生逐帧一致的结果。这是“保留种子竞速”功能的生命线 |
| 输入缓冲 | 按键输入进缓冲区，缓冲窗口 [待定：6] 帧。缓冲期内不因“动画没放完”吞操作 |
| 随机数 | 掉落随机、挑战抽取、地图生成，全部走可复现随机数（种子驱动），禁止用系统时钟做种子 |

### 3.4 状态机总览（玩家）

```
[地面/岛上] --跳跃--> [空中]
[空中] --二段跳--> [空中]
[空中] --蹬墙--> [空中]（反方向弹射）
[空中] --闪避--> [闪避中]（前15帧无敌 / 后15帧可受伤）
[任意] --攻击--> [攻击中]（前摇/判定/后摇）
[任意] --撞地刺/子弹/敌人且非无敌--> [死亡]
[死亡] --重开--> [本局重新开始]（已领挑战奖励保留）
```

落地（碰岛）不改变“地面/岛上”之外的任何状态，但执行清零三件套：`speedTier = 0`、`airTime = 0`、触发清零视听反馈。落岛的回复见 §4.6。

## 4. 规则实现规格

> 每个系统固定四件套：**设计意图**（为什么）/ **实现要求**（按什么→发生什么→看到什么）/ **边界条件**（满/空/同时触发）/ **失败态**（坏了长什么样）。数值凡未经试玩的一律标 `[待定]`。
> 

### 4.1 耐力系统

**设计意图**：玩家唯一需要管理的资源。耐力条就是“这条命还能折腾多久”的具象化；做对事自然回，做错事（乱按）加速见底。

**实现要求**

| 事件 | 耐力变化 | 说明 |
| --- | --- | --- |
| 空中移动（持续） | 每秒 -1 | 按当前速度档乘消耗系数（见 §4.2） |
| 跳跃 | -5 `[待定]` | 起跳一瞬扣除 |
| 二段跳 | -8 `[待定]` | 比一跳贵，逼玩家算计 |
| 闪避 | -6 `[待定]` | 精准/普通同价，区别在时停回报 |
| 攻击 | -4 `[待定]` | 便宜，鼓励主动打 |
| 蹬墙跳 | -5 `[待定]` | — |
| 升一档 | +10 `[待定]` | 不超过上限 |
| 触发一次时停 | +15 `[待定]` | 弹刀/精准闪避/砍子弹的回报 |
| 落岛 | +40 `[待定]` | 见 §4.6 |
| 吃补给 | +25 `[待定]` | 见 §4.6 |

**边界条件**

- 耐力为 0 时：所有主动动作拒绝执行；玩家进入**自由落体**（下落不耗油），直到落岛/落地。
- 耐力回复类事件（升档/时停/补给/落岛）不得使耐力超过上限，超出部分丢弃。
- 耐力上限可被模组修改（如 +20 上限），结算时以当前上限为准。

**失败态**

- 耐力空了玩家直接坠落撞刺——这是设计内的死亡，不是 bug。
- bug 长相：耐力条显示与实际扣除不一致（同一数据源，只允许 HUD 读、逻辑写）。

### 4.2 速度档系统（动量引擎）

**设计意图**：不落地是赌注，速度档是赔率。档位同时管四件事：耐力消耗、耐力回复、能力解锁、镜头视野——玩家追求的目标只有一句话：别落地，往上升。

**实现要求**

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 档位范围 | 0–5 档 | `[待定]` 是否开放 6 档以上（模组扩展） |
| 涨档条件 | 滞空累计，每 [待定：2] 秒 +1 档 | 落地即清零，重新计时 |
| 封顶 | 5 档 | 到顶不再涨 |
| 每档耐力消耗系数 | 100% / 85% / 70% / 55% / 40% / 30% `[待定]` | 档位越高，同样的动作越便宜 |
| 升一档回复 | +10 耐力 `[待定]` | — |
| 能力解锁 | 3 档以上：精准弹刀/精准闪避可进时停 | 其余档位能力由模组提供 `[待定]` |
| 落地清零 | speedTier = 0，airTime = 0 | 无任何例外 |

**边界条件**

- 升档瞬间若耐力已满：回复量丢弃，但升档的视听反馈照常播放（玩家要知道档位在涨）。
- 落地清零的同时如果正处于时停：时停不打断，档位照清零（时停是已结算事件）。
- 使用技能掉档（“使用一些技能会丢失 1 到 3 档”）：每个技能/模组在配置表里标 `tierCost`（0/1/2/3）。掉档后档位不低于 0；掉档不触发“落地清零”的完整反馈，只播放掉档提示。**时停本身不掉档**——否则时停惩罚太重。

**失败态**

- bug 长相：落岛了档位还在；或升档时没回油；或掉档把玩家打到 0 档还播放落地音效。

### 4.3 动作系统

**设计意图**：六个动作全部耗油——移动不是免费的，活着就要花钱。每个动作的帧数决定手感，手感决定这个游戏成不成立。

**实现要求（帧数表，60FPS 基准）**

| 动作 | 前摇 | 判定/生效 | 后摇 | 耗油 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 移动（空中） | — | 持续 | — | 1/秒 | 横向速度 [待定：400px/s]，每档 +[待定：15]% |
| 跳跃 | — | 起跳帧 | — | 5 `[待定]` | 垂直初速 [待定：600px/s] |
| 二段跳 | — | 起跳帧 | — | 8 `[待定]` | 需 jumpsLeft > 0 |
| 闪避 | — | 全时段 30 帧 | — | 6 `[待定]` | 前 15 帧无敌（精准段），后 15 帧无无敌（普通段） |
| 攻击 | 8–10 帧 `[待定]` | 判定帧 [待定：4 帧] | 10–12 帧 `[待定]` | 4 `[待定]` | 判定框见 §4.5 |
| 蹬墙跳 | — | 起跳帧 | — | 5 `[待定]` | 反方向弹射，弹射速度 [待定：500px/s] |

**闪避 CD 与递增消耗**：

- 闪避 CD：30 帧。CD 结束时按下，正常价。
- CD 内连按：重置 CD，消耗递增 6 → 8 → 10 → 14 → 20 → 28 `[待定]`。
- 停手 1 秒，连击计数清零。
- **试玩重点盯防**：空中被弹幕逼着连闪的玩家，会不会觉得被 CD 欺负。若差评集中在这一点，把前三次递增拉平（6/6/8/10）。

**蹬墙跳规则**：

- 方向：**往身后跳**（反作用力弹射），不是往上爬。
- 同一面墙只能蹬一次（`wallJumpLock`），蹬过即锁，直到下次落地重置。
- 蹬墙不重置二段跳（重置途径只有 §4.4 那四条）。

**边界条件**

- 二段跳次数：空中基础 1 次二段跳 + 1 次空中闪避，可被 §4.4 重置。
- 攻击后摇中不接受新攻击输入（进输入缓冲，后摇结束即放）。
- 闪避中不能攻击，攻击中不能闪避（各自状态锁）。

**失败态**

- bug 长相：后摇能取消掉伤害判定（变成无责连打）；闪避无敌帧错位（前 15 帧反而能受伤）。

### 4.4 二段跳重置规则（弹匣机制）

**设计意图**：耐力是油（总量），档位是弹匣（次数补充）。四种重置途径覆盖四种玩法风格——反应快的靠精准闪避，技术好的拼刀，爱进攻的杀人，想保命的用普通闪避（但有 CD 加价惩罚）。同一张图，四种活法。

**实现要求**

| 重置途径 | 触发条件 | 附带回报 |
| --- | --- | --- |
| 精准闪避 | 闪避前 15 帧内成功无敌掉一次致死判定 | 时停（3 档以上）+ 回 15 耐力 |
| 弹刀 | 武器对武器相交，命中判定窗口（±[待定：3] 帧） | 时停（3 档以上）+ 回 15 耐力 |
| 击杀敌人 | 攻击判定框击杀任一敌人 | [待定：回 3 耐力]（基本回本） |
| 普通闪避 | 闪避后 15 帧段成功走位（无无敌，躲开即算） | 仅重置；CD 递增消耗见 §4.3 |

**边界条件**

- 同一次闪避不能同时算“精准”又算“普通”——以按键按下后的帧位判定，前 15 帧=精准，后 15 帧=普通。
- 重置的是**次数**（二段跳 + 空中闪避各 1），不是耐力。耐力照耗。
- 落岛/落地时，次数自然回满，无需等重置。

**失败态**

- bug 长相：玩家在一直按闪避刷重置，油表却不见掉（CD 递增没生效）。

### 4.5 时停与战斗判定

**设计意图**：3 档以上的精准操作进时停——这是高技术玩家的专属节奏，也是全游戏最响亮的反馈。“世界停摆、唯我独醒”用画面演出来：时停期间除玩家外全部褪成黑白，玩家保留全彩（水彩风格独占优势，像画里只有一滴颜色是活的）。

**实现要求**

| 项 | 规则 |
| --- | --- |
| 触发条件 | 3 档以上 + ①精准弹刀 ②精准闪避 ③武器砍中子弹 |
| 时停时长 | 20–30 帧 `[待定]` |
| 时停期间 | 敌人、子弹完全静止；玩家以 [待定：0.3] 倍速可操作 |
| 时停回报 | +15 耐力 `[待定]` |
| 砍子弹 | 给较短时停（时长 ×0.6 `[待定]`）+ 较少回复（×0.6）——拼刀是技术，砍子弹是手快，回报分档 |
| 镜头 | 时停瞬间推近至 105%，恢复弹回 |

**判定框细则**

- 攻击判定框：起手第 8–10 帧进入 ACTIVE，持续 [待定：4] 帧，随角色朝向翻转。
- 弹刀窗口：敌人武器判定帧前后各 [待定：3] 帧，玩家挥刀命中即弹刀；窗口外=挡空（无惩罚也无奖励，但会暴露后摇）。
- 玩家受击判定框：全身，无怒气/无霸体，碰到就死（一招定死）。
- 无敌帧优先：玩家无敌帧内的任何敌方判定直接跳过，不触发死亡也不触发弹刀。

**边界条件**

- 时停期间击杀敌人：照常击杀，重置次数，但不再触发二段时停（防连锁刷时停）。
- 时停期间落岛：不清零档位（时停是已结算事件，见 §4.2 边界）。
- 3 档以下精准弹刀：只算普通命中（击杀但不进时停、不回 15 耐力）——档位不够，技术兑现不了。

**失败态**

- bug 长相：时停里敌人还在动；时停可以无限连锁；3 档以下也能进时停。

### 4.6 岛与补给（唯一活地）

**设计意图**：岛是这个世界的空气。玩家主动落岛 = 用“清零档位”换“安全 + 回油”。高手把岛当路过的风景，新手把岛当保命符——同一张图两种活法，就靠岛实现。

**实现要求**

| 岛的功能 | 规则 |
| --- | --- |
| 站立 | 安全：站台上无任何持续伤害 |
| 清零 | 落岛瞬间 speedTier = 0、airTime = 0 |
| 回油 | +40 耐力 `[待定]`（分帧平滑回复而非瞬扣，防“落地满油飞天”的割裂感）`[待定：60 帧内回复完]` |
| 次数回满 | 二段跳、空中闪避次数回满 |
| 蹬墙锁重置 | 所有 wallJumpLock 清空 |

**补给道具**

- 挂在岛上，**不是每个岛都有**（生成器决定，密度 [待定：30–50%]）。
- 吃了 +25 耐力 `[待定]`，吃了就没了。
- 视觉：圆形（形状宪法，圆=友好可吃），吃到有温暖音效。

**边界条件**

- 落岛回油分帧发放期间，玩家起跳：剩余回复量作废（防“落地秒起跳还能领满回复”）。
- 岛面积有下限（生成器保证，见 §5.1），防“针尖大的岛根本落不上去”。

**失败态**

- bug 长相：落岛不清零档位；补给刷在刺上；回油瞬发导致玩家原地弹射起飞。

### 4.7 敌人与子弹

**设计意图**：敌人不是血条沙包，是“逼你做精准操作”的考题。1 滴血对 1 滴血，接得住就赚，接不住就死。

**实现要求**

| 类型 | 行为 | 难度差异 |
| --- | --- | --- |
| 近战（MELEE） | 站桩/巡逻，前摇后挥刀，武器判定框致死 | 前摇帧数随难度变化（低难度长、高难度短）`[待定：EASY 40 帧 / EXPERT 18 帧]` |
| 远程（RANGER） | 前摇后发射子弹（三角），子弹直线飞行，可被砍掉 | 同上；子弹速度 [待定：300px/s] |

**共同规则**

- 敌人 1 滴血，玩家攻击判定命中即死。
- 敌人武器/子弹对玩家：碰到即死（无敌帧除外）。
- **威胁只从右侧或上方来**（与镜头盲区规则配套，见 §7.2）。生成器负责执行。
- 击杀反馈：敌人碎成同风格小色块粒子；击杀重置二段跳次数（§4.4）。

**边界条件**

- 敌人被时停冻结时，其判定框全部停算。
- 子弹被砍掉：子弹消失 + 进时停流程；砍不掉（砍空）无惩罚，暴露后摇。
- 玩家死亡时敌人继续按 AI 运行（死亡流程不管敌人）。

**失败态**

- bug 长相：子弹从左边来（玩家看不见）；敌人贴岛站立（露头就死无反应机会）。

### 4.8 死亡与重生

**设计意图**：一招定死的游戏，玩家一局死十几次。**死亡必须便宜、圆润、有收获**——死一次像泡泡破掉，不配刺耳失败音。已领的挑战奖励死了也不收回（P5：挫败感有出口）。

**实现要求**

| 步骤 | 规则 |
| --- | --- |
| 死亡瞬间 | 播放水彩滴落音效 + 角色晕染扩散消失；音乐不停（停音乐会放大挫败）`[待定]` |
| 死亡结算 | 按死亡时 progress 结算本局消耗的模组耐久（见 §6.2） |
| 奖励保留 | 本局已完成的挑战奖励、已击杀的进度，全部保留 |
| 重新开始 | 从关卡起点重开，progress = 0，速度档 = 0，耐力 = 满，次数回满 |
| 挑战保留 | 本局挂上的挑战槽位不变（同一难度同一局内不重抽）`[待定]` |

**边界条件**

- 死亡结算只发生一次（重开后再死，按新的一局重新结算）。
- 死亡瞬间正在生效的时停：立即解除，无额外结算。

**失败态**

- bug 长相：死了挑战奖励被收回；死亡后耐力/档位没重置；连死时耐久重复扣。

## 5. 关卡与生成器

**设计意图**：15 分钟一局、无限重玩、还能竞速——手工关卡做不到，程序生成是唯一答案。但生成器不是随机撒料，是**带着硬规矩生图**。种子保留让“同一张图比高低”成为社交钩子。

### 5.1 生成器硬规矩（生图时必须满足，不是生完再查）

| # | 规矩 | 违反后果 | 实现方式 |
| --- | --- | --- | --- |
| G1 | 任意两岛间距 ≤ 最慢速度下的最大续航距离 | 必死局，玩家无法通关 | 生成时按间距约束摆岛 |
| G2 | 岛数量 ≥ 难度下限（EASY 多 / EXPERT 少） | 高难度无活路 | 按难度参数控制 |
| G3 | 敌人不得贴岛站立（岛缘外 [待定：80px] 内无敌人生成） | 露头就死，无反应机会 | 敌人生成时做岛邻域排除 |
| G4 | 不得用地刺堵死必经之路 | 鬼打墙，关卡不可解 | 生成后做连通性校验 |
| G5 | 威胁只从右侧/上方进入玩家视野 | 镜头盲区杀人，玩家觉得是镜头杀了自己 | 子弹/冲撞敌生成方向约束 |
| G6 | 关卡左右上下边界外各留一个镜头身位 | 镜头拖出世界看到虚空 | 边界留空带 |
| G7 | 岛面积 ≥ 下限（[待定：宽 120px × 高 40px]） | 针尖岛落不上去 | 岛尺寸下限约束 |

**校验优先级**：G1/G4 是“图能不能玩”的底线，生成失败必须重roll；G2/G3/G5/G6/G7 是“图好不好玩”的约束，允许降级满足。

## 6. 局外系统

> 局内玩家只管飞和砍，局外才管这些账。这个分配是健康的：核心循环不被系统复杂度污染。
> 

### 6.1 模组配置（8 槽）

**设计意图**：给玩家“我的 build 我做主”的 agency。开局配一次，每局带着打。8 个槽是深度，分类限制防唯一最优解。

**实现要求**

| 项 | 规则 |
| --- | --- |
| 槽位 | 8 个，按风格分类 [待定：攻击/机动/生存/特殊 各 2 槽] |
| 装备 | 开局前在模组界面拖拽装备；局内不可更改 |
| 基础模组 | 每风格 1 个永久模组（共 4 个），永远拥有、不烧耐久，保证永不裸奔 |
| 起始库存 | 新账号赠送 12–16 个模组（约两套） |
| 模组效果 | 每个模组在配置表里登记效果字段（效果类型/数值/tierCost），效果必须带 trade-off [待定：逐模定] |

**边界条件**

- 同类槽位放满才允许溢出到其他类 [待定：是否允许跨类混装]。
- 耐久耗尽的模组不可装备。
- 局内装备锁定，死亡重开不换装（换装只在结算界面和开局前）。

**失败态**

- bug 长相：8 槽能塞 8 个同效果模组；耐久 0 的模组还能装备。

### 6.2 模组耐久消耗

**设计意图**：模组是弹药不是传家宝。最优解会因使用持续磨损，玩家被迫轮换 build，池子自然盘活。烧多少看这局跑了多远——认真打完才烧一半，早死不亏。

**实现要求**

| 项 | 规则 |
| --- | --- |
| 耐久单位 | 绝对值：满耐久 = 100 点 |
| 消耗公式 | 本局消耗 = max(10, progress × 50) 点/个。progress = 跑图完成度 0.0–1.0 |
| 最低保底 | 每局每个上阵模组至少烧 10 点（进场保底，防摆烂磨耐久） |
| 消耗时机 | 死亡或通关时一次性结算，从每个上阵模组的耐久扣除 |
| 耐久归零 | 模组报废，进入“已耗尽”列表 |
| 进度可见 | 局内 HUD 显示本局已跑进度；结算界面显示每个模组烧掉的点数 |

**公式推导（给数值策划）**：

- 打满一局（progress = 1.0）：每模组烧 50 点 = 满耐久的 1/2，一套 8 个共烧 400 点。
- 跑到 70% 死：每模组烧 35 点（70% × 50）。
- 进场就死（progress ≈ 0）：每模组烧 10 点保底。
- 含义：**一个满耐久模组，打满能用 2 次**。想省着用？可以，但每局至少认真开始。

**边界条件**

- 同一模组多实例（如果有）各自独立结算。
- 结算时耐久不足以扣除：扣到 0 即报废，不产生负耐久。
- 断线/强退不结算（单机游戏，重开即新局）`[待定]`。

**失败态**

- bug 长相：连死时耐久重复扣；progress 显示与实际结算不一致。

### 6.3 挑战系统（成就式领奖点）

**设计意图**：高难度不设检查点重生——那会废掉“落地清零”的惩罚。改设挑战：完成挑战当场领奖，死亡从头跑但奖不收回。玩家一路有收获，输也输得不冤。

**实现要求**

| 项 | 规则 |
| --- | --- |
| 每局挂载 | 3–4 个，按难度从对应池随机抽取 |
| 梯度保证 | 每局至少 1 个“人人能完成”的简单挑战（如吃到 1 个补给） |
| 风格分池 | 飞天党 / 拼刀党 / 苟命党 / 综合 四池，同池挑战指向同一打法，不惩罚风格 |
| 完成判定 | 实时检测，完成即发奖，死亡不收回 |
| 奖励 | 每完成 1 个 = 1 个随机模组（掉落规则见 §6.4） |
| 局内不变 | 一局挂上的挑战槽位，死亡重开不重抽 [待定] |

**挑战池第一版（口径即判定规则，全部进配置表）**

| 池 | 挑战 | 达成口径 |
| --- | --- | --- |
| 飞天党 | 累计滞空 3 分钟 | 从最后一次落地起算，落地清零 |
| 飞天党 | 单次滞空 60 秒 | 中间不能碰任何地面和岛 |
| 飞天党 | 单局不吃补给 | 补给计数为 0 通关 |
| 拼刀党 | 精准弹刀 15 次 | 只在 3 档以上状态计数 |
| 拼刀党 | 时停累计 20 秒 | 时停期间正常计时 |
| 拼刀党 | 3 档以上弹刀 10 次 | 触发时的档位为准 |
| 苟命党 | 单局吃 5 个补给 | 重复吃同一个岛的补给算 1 次 |
| 苟命党 | 耐力没见底 | 耐力条全程没空过 |
| 综合 | 通关 | 到达终点，不限姿势 |
| 综合 | 一局完成 5 个挑战 | 含领奖点发的 |
| 简单（每局保底 1 个） | 吃到 1 个补给 / 弹刀 1 次 / 到达进度 25% | 三者按难度轮换 |

**边界条件**

- 简单挑战是保底管道：任何玩家 15 分钟内大概率能完成，保证每局至少 1 个模组进账。
- 挑战互斥检查：同局不得出现口径冲突的组合（如“不吃补给”与“吃 5 个补给”）——抽取时做互斥过滤。
- 完成 5 个挑战的计数包含挂载槽位之外的挑战 [待定：是否开放隐藏挑战]。

**失败态**

- bug 长相：死了奖励被收回；同局出现互斥挑战；一局 4 个全是地狱难度。

### 6.4 掉落经济

**设计意图**：一局的收入 = 挑战表现 + 通关大奖，全部随机，高稀有低概率。系统不偷看玩家连败、不藏保底计数——干净随机，盼头留给下一局。

**实现要求**

| 项 | 规则 |
| --- | --- |
| 挑战奖励 | 每完成 1 个挑战 = 1 个随机模组 |
| 通关奖励 | 通关 = 2 个随机模组 |
| 随机规则 | 全体模组池按稀有度加权：普通 70% / 精良 25% / 稀有 5% `[待定]` |
| 难度加权 | 高难度掉落池品质更好、稀有率加权 `[待定：EXPERT 稀有 +?%]` |
| 无补偿 | 无连败保护、无隐藏保底计数（pity），纯随机 |

**经济账（验收时复核用）**

| 一局情形 | 掉落 | 消耗 | 净 |
| --- | --- | --- | --- |
| 打满（3 挑战 + 通关） | 5 个 | 4 个满耐久当量 | +1 |
| 半盒饭（1–2 挑战，中途死） | 1–2 个 | 约 2.8 | -1 到 -2 |
| 进场就死 | 0 | 0.8 | -0.8 |

结论：熟练玩家每局净赚，新手期稳定净亏——**新手流失风险集中在前五局**。试玩若确认，第一手段是加起始库存，**不准改掉落规则**（改了经济全盘重算）。

**失败态**

- bug 长相：通关只发 1 个；稀有度权重写死导致精良绝迹；发放的模组耐久不是满值。

## 7. 界面与镜头

### 7.1 HUD（局内界面）

**设计意图**：P2 支柱——玩家只需要关心耐力条。其余信息用视听反馈替代，UI 能少则少。

| 元素 | 显示内容 | 位置 | 说明 |
| --- | --- | --- | --- |
| 耐力条 | 当前/上限 | 角色头顶附近（不挡视野）`[待定]` | 全游戏唯一的“管理条” |
| 速度档 | 档位指示（非数字，用刻度/音阶可视化） | 耐力条旁 | 让玩家凭刻度就知道自己在几档 |
| 挑战槽 | 本局 3-4 个挑战 + 完成状态 | 屏幕右上角 | 死亡不收回，常驻提醒 |
| 进度 | 本局跑图进度 % | 屏幕顶部细条 | 玩家随时知道耐久会烧多少 |
| 模组快捷状态 | 已装备模组的可用/冷却 | 屏幕右下角 `[待定]` | 局内不可换装 |

**禁止项**：不显示敌人血条（1 滴血，没有血条）、不显示伤害数字、不显示连击计数UI（连击用音效和画面演出）。

### 7.2 镜头（摄像机系统）

**设计意图**：跑酷式镜头——角色锚点偏左下，右侧与上方留给反应空间。速度档直接驱动镜头：速度越高，锚点越靠左、镜头越远、回退空间越小——**“高速少退路”画在屏幕上，玩家看角色站哪儿就知道自己还有多少余地**。

**横向规则（四段死区模型）**

| 区段 | 用途 |
| --- | --- |
| 1-24（左段） | 高速锚点区。5 档时角色落点 15-20；左界 1-2 为摄像机左拖临界 |
| 25-49（左中段） | 常态锚点区。1-4 档角色落点 35-40 |
| 50-74（右中段） | 前冲自由区。角色加速前冲时摄像机稍滞后，角色可临时进入 |
| 75-100（右段） | 威胁入口 + 右拖临界。新敌人/子弹从缘外进场；角色冲到这摄像机必须立即右拖 |

**摄像机行为**：

1. 角色在死区内活动：摄像机锁定不动。
2. 角色冲出死区：摄像机朝对应方向移动，把角色拉回死区边缘。
3. 摄像机有世界边界（关卡左右缘）：**没到边界极限就继续按规则移动；到了边界极限就停住**，此时角色相对屏幕滑动，直至贴上关卡边界的空气墙。
4. 锚点随速度档连续插值左移：1 档 40% → 5 档 17%（每档约 -5.75 个百分点），不跳变。

**纵向规则**：锚点在下 1/3 一带，死区 20%–70%。角色在死区内上下移动镜头不动；冲出死区平滑跟进；拖到关卡上下缘停。纵向上方保留反应空间。

**缩放**：1 档 100% → 5 档 85%。高速拉远 = 视野更大 = 白送反应时间。视野大小即档位的视觉代言——**UI 会撒谎，视野不会**。

**特殊时刻镜头语言**：

| 事件 | 镜头动作 |
| --- | --- |
| 时停触发 | 推近至 105%，恢复弹回 |
| 蹬墙弹射 | 快速甩镜 + 轻微抖动 |
| 落地清零 | 轻微下沉 + 水彩褪色反馈 |

**边界与失败态**

- 摄像机不得拖出关卡世界边界（G6 已由生成器保证留空）。
- 关卡左右边界为空气墙：角色贴上即停，**不死亡**。这游戏死亡只来自地刺、敌人、子弹，不来自“被镜头拖出世界”。
- bug 长相：高速时锚点跳变（一顿一顿）；角色贴左缘时镜头抽搐；边界处镜头露黑边。

## 10. 音乐音效需求

> 方向已定，资源未启动。本章写给音乐/音效：给方向与事件清单，**文件清单留空**（见 §10.4）。
> 

### 10.1 音乐方向

原声乐器（木吉他/钢琴）+ 电子节拍。休闲但不催眠，硬核但不吵。

**两个必须做的设计**：

1. **音乐随速度档分层叠加**：不落地攒档，音乐一层层加（档位越高鼓点越密、旋律越满）；**落地清零瞬间音乐全部抽走，只剩一声闷响，从第一层重新来**。听觉上把“清零”的爽和疼同时放大。
2. **升档即音阶**：每升一档弹一个音，五档连起来是一支五声音阶（宫商角徵羽）。攒档的过程像在演奏，玩家耳朵直接被奖励。

### 10.2 音效清单（按优先级）

| 事件 | 声音 | 要求 |
| --- | --- | --- |
| 升档 | 上行音阶的一音 | 随档位升高，五声连起来成曲 |
| 精准弹刀/闪避 | 高频“叮” + 风铃般余韵 | 时停的听觉信号，干净、不糊 |
| 落地清零 | 低沉闷响 + 音乐骤停 | 短促，别拉长，长了像嘲讽 |
| 死亡 | 水彩滴落声 | **圆润不刺耳**——一招定死的游戏，死一次就一声“啵”，玩家才肯再开一局 |
| 吃补给 | 温暖的“啵” | 与死亡音同源不同调，一暖一凉 |
| 通关 | 完整收尾旋律 | 把一局里没凑齐的音阶补全 |
| 耐力耗尽 | 油尽警示（短促低频） | 提醒但不刺耳 |
| 击杀敌人 | 同风格碎块粒子音 | 轻快，强化“杀一下很便宜” |

### 10.3 音乐动态结构（给音频程序）

- 音乐分 6 层（0 档静音/1-5 档逐层叠加），层与层必须同调性可无缝叠加。
- 落地清零 = 6 层瞬间抽空 + 一声闷响 + 从第 1 层重进。
- 时停期间：音乐抽掉或留极低衬底，只保留效果音。
- 死亡不停止音乐（停音乐放大挫败）`[待定]`。
