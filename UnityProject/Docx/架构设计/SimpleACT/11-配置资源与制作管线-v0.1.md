# SimpleACT 配置、资源与制作管线

日期：2026-10-24；分析稿 v0.1。对应原文 §8及所有功能制作。依据项目tengine-dev的Luban、资源、命名和热更规范，以及当前代码。

## 1. 配置现状与落点

仓库Configs/GameConfig已有luban.conf、Datas表索引、CustomTemplate和生成脚本；当前GameProto内未发现业务Tables/ConfigSystem成品。原文提到的《SimpleACT-数值配置-v1.0.xlsx》未随用户文件提供，因此以下是新增表设计，不能视为现有表已填好。

Excel源放仓库Configs/GameConfig/Datas；生成C#进UnityProject/Assets/GameScripts/HotFix/GameProto/GameConfig，bytes进Assets/AssetRaw/Configs/bytes。虽然配置源在UnityProject外，它属于明确关联的既有配置工程；真正修改时需列入实现范围，本次只写文档。

## 3. 异步配置加载与版本冻结

现有ConfigSystem模板内部LoadAsset同步读取，且GameProto不能引用GameLogic.GameModule。建议GameLogic侧ConfigModule通过GameModule.Resource.LoadAssetAsync<TextAsset>预取所有必需bytes，再把内存读取委托交给生成Tables。生成器模板的构造能力需在实际生成后适配；本文没有声称现成API已经支持新委托接口。

```text
LoadConfigAsync:
  读取配置清单/规则版本
  异步加载全部所需bytes并持有句柄
  以内存ByteBuf构建Tables，完成外键/范围检查
  构建不可变RuleSnapshot与hash
  若已复制所需数据则释放资源，否则持有到ConfigModule退出
```

Session开始后锁定ruleHash和规则数据；热更完成也不在进行中的Attempt中途换参数。二进制格式不默认支持任意加删字段，旧回放需对应旧规则或明确不可兼容提示。

## 4. 资源分类与所有权

| 资源 | 建议目录 | 持有者/释放 |
|---|---|---|
| UI Prefab/图标 | AssetRaw/UI/Prefabs、UI/Atlas | UIModule管理窗口；图标SetSprite |
| 角色/敌人/弹丸 | AssetRaw/Actor/SimpleACT | Level/Run的View装配或已存在对象池 |
| 游戏场景/片段 | AssetRaw/Scenes/SimpleACT | LevelModule经GameModule.Scene加载卸载 |
| 音频stem/SFX | AssetRaw/Audios | FeedbackModule持有stem Clip，释放配对 |
| 水彩材质/着色 | AssetRaw/Materials、Shaders | 表现资源所有者；不静态散落引用 |
| 规则bytes | AssetRaw/Configs/bytes | ConfigModule按解析方式决定释放时点 |
| 粒子效果 | AssetRaw/Effects/SimpleACT | 对象池与Feedback共同约定退出归还 |

资源location按照现有YooAsset收集规则确认，保持唯一；不要假设随便写相对路径都能寻址。业务普通Prefab通过LoadGameObjectAsync；普通Asset通过LoadAssetAsync/UnloadAsset配对。不得把关卡资源放Resources再另建同步加载入口。

## 5. 新对象池的复用边界

最新代码：GameModule.GameObjectPool；IGameObjectPoolModule支持RegisterPool、PrewarmAsync、TrySpawn、Despawn等。GameObjectPoolDefinition使用直接Prefab引用，不自行YooAsset加载。IGameObjectPoolCallbacks规定借出时尚未激活，不能假设Awake/Start已经完成，使用序列化引用或显式初始化。

最小切片可以在GameObjectPoolSetting绑定占位Prefab，等配置与预热就绪后进局。热更资源若动态载入Prefab，需要单独明确资源租约由谁持有：池不能替持有者释放加载句柄。此方案涉及原先“业务不得LoadAsset<GameObject>+Instantiate”的规则边界，实施前选择受批准的池资源适配方式；不在本次新增隐藏的第二套加载路径。

回池必须重置速度、动画、粒子、尾迹、事件、异步令牌和业务ID。PoolSpawnContext.LeaseVersion用于拒绝旧表现回调，不代替稳定逻辑EntityId。子弹寿命按世界Tick结束后请求Despawn，不使用真实秒延迟回收决定子弹何时失效，否则时停期间会凭空消弹。

池容量不足：纯VFX可按批准策略跳过；敌人/子弹等玩法View不能静默消失。逻辑实体始终存在，必需View准备失败应阻止开局或进入可恢复错误，不得因机器资源状态改变模拟。

## 6. 制作工具建议

| 工具 | 解决问题 | MVP时点 |
|---|---|---|
| 配置一致性检查器 | 缺外键、负成本、动作区间、挑战不可完成、权重空池 | 配置导入阶段 |
| 片段导出与挂点工具 | 从可编辑场景提取稳定逻辑几何和ID | S2生成器阶段 |
| 关卡规则报告器 | 输出G1–G7失败位置、主路径和重试原因 | S2 |
| Tick/判定DebugView | 显示动作帧、碰撞候选、时钟域 | S1 |
| 回放差异定位器 | 标出首个不同Tick与状态字段 | S3 |

这不是要求首版开发完整可视化技能编辑器或通用节点系统。使用GameEditor程序集承载Editor代码，GameLogic不依赖Editor类型。
