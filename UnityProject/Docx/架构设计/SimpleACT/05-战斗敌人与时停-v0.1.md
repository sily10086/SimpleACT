# SimpleACT 战斗、敌人与时停

日期：2026-10-24；分析稿 v0.1。对应原文 §4.4–4.8。依赖 03/04，冲突见 D03–D07、D14–D15。

## 1. 系统与实体

RunModule 内设 CombatSystem、EnemySystem、ProjectileSystem、TimeStopSystem。逻辑实体与池化表现对象分离：EntityId 在模拟中稳定分配，池对象的 InstanceID/LeaseVersion 只用于表现引用有效性。

| 逻辑实体 | 数据 | 表现资源 |
|---|---|---|
| 近战敌人 | 位置、朝向、IDLE/TELEGRAPH/ATTACK/RECOVERY/DEAD、阶段帧、攻击实例ID | 冷暗胶囊、武器轨迹、清晰前摇 |
| 远程敌人 | 同上加弹种、瞄准快照、发射时刻 | 前摇方向提示与三角弹 |
| Projectile | 位置/速度、所属攻击ID、寿命Ticks、活动标记 | 三角 Sprite/尾迹 |
| AttackInstance | 发起者、朝向、Active区间、弹刀窗口、命中集合 | 武器视觉与调试框 |

RECOVERY 为实现重复出手所需的建议补充，原文只有四态，恢复时间、巡逻范围、索敌半径和发射频率需补表。近战站桩为最小切片，巡逻扩展不影响框架边界。

## 2. 同帧裁决（推荐，需 D14 确认）

不能一部分死亡在 OnTrigger，另一部分在玩家 Update；统一收集候选，再按确定顺序提交。

1. 接收命令、推进动作与时钟，保留本 Tick 的无敌区间与攻击阶段。
2. 推进运动并收集路径接触：平台、墙、地刺、子弹、武器、敌人身体。
3. 安全落地和档位变更按接触时序处理；同一时刻建议落地优先，决定战斗触发档位。
4. 先裁决攻击对弹丸/武器的有效消除或弹刀，标记已消费威胁。
5. 裁决玩家攻击击杀；一攻击对一敌人只结算一次。
6. 裁决剩余致死候选：无敌则记录免伤成功；非无敌进入死亡待提交。
7. 本帧未死亡且符合档位/未时停时，启动一次时停并回复；同帧多个触发不叠加。
8. 产出挑战事件，先记录已经达成的一般挑战；通关型挑战仅在通关成立时判定。
9. 死亡与终点同时成立建议死亡优先；提交一次终局快照，再发送表现与持久化请求。

更精确的碰撞可按 Tick 内接触时间排序；时间相同才按事件优先级及 stableId。上表不能用来让发生较晚的砍弹消除较早的非无敌致死命中。

## 3. 弹刀、精准闪避与普通闪避

弹刀：玩家武器区域与敌人可弹区域相交，且处于允许窗口。独立 parryRegion 解决“敌人还未有致死框但可提前弹刀”的矛盾。3档以下按原文算普通命中/击杀，不发时停回复；高档弹刀是否同时杀死敌人仍需明确，建议统一击杀以符合一击必杀，但标为待确认。

精准闪避：先发现本会致死的敌方接触，再以 invincible 拦截；同一 DodgeActionId 只奖励一次，无敌期间多个弹丸不各给一次耐力。是否把地刺列为可奖励威胁必须单独配置并确认，不从“任何敌方判定”推导。

普通闪避：不能仅以动作完成判定。建议在闪避后半段记录威胁的预测包络与关联 ID，若玩家脱离危险且未受击才认成功；威胁预测必须来自相同模拟数据，不使用镜头屏幕像素距离。该判定的距离、预测帧数与对移动敌人的适用性需策划定稿。

## 4. 时停的真实行为

世界敌人、弹丸移动和敌方攻击判定冻结；玩家继续使用缩放后的 PlayerStep，仍可击杀被冻结敌人。停止敌方攻击不代表敌人不能被玩家命中。静态地刺是否继续致死原文未统一，建议保留静态危害；这也是时停内死亡解除的有效路径。

```text
TryBeginTimeStop(trigger):
  if active or playerDead or tier < threshold: return Rejected
  duration = rule.duration * trigger.durationFactor
  recovery = rule.recovery * trigger.recoveryFactor
  active = true; remainingGlobalTicks = RoundedDuration(duration)
  AddStamina(recovery)
  emit TimeStopStarted(trigger, duration)

EachGlobalTick:
  if active: remainingGlobalTicks -= 1
  if reaches zero: EndTimeStop()
```

触发 Tick 是否算第1帧固定采用区间 [startTick, endTick)，在下一轮推进前检查是否到 endTick，避免启动当帧又扣一次造成少一帧。原文砍弹0.6倍率为占位，取整规则写入配置转换；不在表现层再计算。

时停期间拒绝再次启动、延长、再次支付时停奖励；击杀仍可重置次数。死亡立即解除时停；落岛按 D01 推荐清零但保留当前时停到期。暂停则冻结所有逻辑时钟，与时停相互独立。

## 5. 敌人前摇与威胁公平性

敌人按难度读取前摇帧数，不根据渲染帧调用 Timer。建议发射时锁定目标方向；若追踪弹另立规则，不默认做成追踪。弹丸移动使用 swept 查询，不能仅检查终点重叠。

生成器负责初始安全区，EnemySystem 还必须在每次攻击时检查逻辑警戒区，防玩家回退导致左侧新威胁。G5 与自由回退的冲突见 D20。镜头 shake、窗口比例和视觉缩放不应改变开火时机。死亡后可继续世界AI作背景表现，但禁止继续给死亡玩家发奖励、耐久结算或输入动作。

## 6. 制作步骤与修改目标

- [ ] 新增 AttackInstance/HitCandidate/CombatResult：稳定 ID 和消费标记解决重复判定。
- [ ] 新增近战FSM：前摇→出手→恢复，先站桩，阶段来自配置；可参考 [UnityHFSM](https://github.com/Inspiaaa/UnityHFSM) 的层级职责，不直接套自动计时。

- [ ] 新增集中裁决器：按时间与优先级单次提交，处理无敌与精准事件。
- [ ] 新增时停控制器：分时间域、不可连锁、死亡释放。
- [ ] 创建 EnemyMelee/EnemyRanger/Projectile View Prefab：引用视觉组件，回池清尾迹和事件，显示调试判定框。
