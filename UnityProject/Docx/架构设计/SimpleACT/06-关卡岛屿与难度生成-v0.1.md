# SimpleACT 关卡、岛屿与难度生成

日期：2026-10-24；分析稿 v0.1。对应原文 §4.6、§5。依赖 03/04，关键决策 D19–D20、D26、D30。

## 1. 制作路线

建议使用“手工设计的安全片段 + 种子驱动的路径拼接 + 可达性约束”，不是全图随机撒地刺。最小切片先固定90秒路线，竖切再加入生成器。程序生成不是实现15分钟重玩体验的唯一方式；手工片段降低不可玩地图概率，也更容易控制教学与节奏。

参考 [Edgar-Unity](https://github.com/OndrejNepozitek/Edgar-Unity) 的图与模板分离；其平台跳跃支持属于 PRO 的说明不能视为免费仓库已提供。参考 [ProceduralToolkit](https://github.com/Syomus/ProceduralToolkit) 的几何工具组织。WFC只提供局部相邻约束，无法替代本游戏耐力/跳跃可达性证明，故不作为主生成器。[WFC参考](https://github.com/mxgmn/WaveFunctionCollapse)。

## 2. 模块与数据

LevelModule 拥有生成器和 View 装配；RunModule 拥有本局岛屿/补给/敌人的运行状态。不能在 Prefab 的 bool 上存储唯一 supplyTaken 状态。

| 数据 | 字段建议 |
|---|---|
| LevelDescriptor | seed、generatorVersion、ruleHash、difficulty、playBounds、visualBounds、start/goal |
| SegmentDefinition | 入口/出口、平台几何、候选挂点、节奏标签、允许难度 |
| IslandDefinition | stableId、位置、尺寸、支撑面、补给挂点 |
| ReachabilityEdge | from/to、允许动作序列、预计耗耐力、净空、最小余量 |
| SpawnDefinition | 稳定ID、敌人/补给类型、坐标、方向、排除区域 |
| LevelRuntimeState | 已拾取集合、敌人状态、当前支撑岛；随 Attempt 重置的部分 |

关卡完整数据在进入战斗前确定。长关卡只流式加载附近 View；加载速度和异步完成顺序不参与随机生成、敌人ID或判定。

## 3. G1–G7 可执行规则

| 原规则 | 具体执行方式 | 失败处理 |
|---|---|---|
| G1 岛间续航 | 主路径相邻安全节点建立有向可达边；用基础配装、低档速度、重力、跳数、耐力成本模拟代表轨迹 | 缩短相邻间距或重生成该片段；不使用全体岛两两距离 |
| G2 数量下限 | 按关长和难度统计最低安全节点数 | 只从允许插入区补岛；不能破坏已证明路径 |
| G3 敌人离岛 | 生成时计算敌人攻击区域与岛缘膨胀安全区，运行时发起攻击也遵守必要缓冲 | 挂点拒绝，换候选点；不把敌人尺寸忽略 |
| G4 必经路不堵 | 保留主路径可达证据；扫掠玩家形状沿轨迹检查地刺/障碍净空 | 重生成片段或使用该难度已批准保底片段 |
| G5 威胁入口 | 模拟空间固定警戒区与发射方向约束，运行时再次约束；见D20 | 取消或延后非法攻击；不跟随实际屏幕抖动判断 |
| G6 边界留白 | visualBounds 在最大拉远、支持宽高比下覆盖视窗；playBounds 独立用于空气墙 | 背景扩边或限制镜头尺寸，避免露空 |
| G7 岛面积 | 设计单位下限经转换，并计入角色足部宽度/安全落点区 | 拒绝过窄模板，不做针尖可达性假象 |

G1不能只用速度×耐力耗尽时间，跳跃次数和重力往往先限制实际滞空。栅格 flood-fill 只能检查几何连通，不能证明角色跳得过去。生成器同时要构造、记录可行路径并复核；原文“生成时满足”和“生成后检查”是互补步骤。

## 4. 种子生成流程与重试上限

```text
Generate(seed, difficulty, ruleSnapshot):
  for attemptIndex in deterministicRetryRange:
    rng = Derive(seed, generatorVersion, attemptIndex)
    route = BuildMainRoute(templates, rng)
    PlaceSafeIslands(route)
    VerifyMovementReachability(route, baselineRules)
    PlaceSpikesOutsideRouteClearance()
    PlaceEnemiesAndSupplyAtAllowedSockets()
    if G1..G7 satisfied: return immutableLevel
  return ApprovedFallback(seed, difficulty, generatorVersion)
```

达到次数上限绝不无限重roll；保底地图仍要遵守硬安全要求并标注 generationResult。若没有获批保底模板则显示可恢复生成失败，不进入坏地图。种子分享要包含生成器版本，否则升级后的回退路径也可能不同。

背景装饰独立 cosmetic RNG；改变云层数量不应使补给或挑战变化。入场资源就绪后再统一激活 View，避免第一帧看不见但能撞到敌人。

## 5. 岛与补给

落地边沿交给04处理资源和档位；岛只描述安全支撑几何。补给以 supplyId 检测接触，一次拾取提交 supplyTaken，再发回复和挑战事件，然后销毁/回收 View。状态先改、表现后动，防同一Tick多个接触重复领奖。

补给密度按配置加权；保底挑战为吃补给时，生成器必须确保存在可达补给，不能只保证“理论上地图可能生成”。挑战和地图不能完全独立抽取：先提供地图能力标签，再筛可实现挑战；同时保留独立RNG流，见08。

## 6. 难度和节奏

四难度统一使用 DifficultyRules：岛密度、初始档、前摇、挑战池、掉落权重引用。其余机制不复制四份代码。首版不做隐形动态难度；原文强调纯随机掉落，不加入连败补偿。

关长由目标时长与实际速度曲线估算，不能用15分钟×某个瞬时速度一次确定。片段至少有教学、休息、战斗、连续滞空和收尾标签；每段危险密度与安全岛间隔联合配置。高难度初始档与落地/重开冲突见D09。

## 7. 制作步骤与资产目标

- [ ] 固定最小切片：制作入口、出口、普通岛、蹬墙和敌人练习点；全部纯色占位。
- [ ] 片段元数据：Editor 工具导出逻辑几何/挂点，避免运行时反向扫描任意层级。
- [ ] 主路径生成器与可达性评估：共用与角色相同的运动规则，保留路径证据。
- [ ] G1–G7约束及失败报告：输出具体片段/规则ID而非仅“生成失败”。
- [ ] LevelAssembler：异步加载模板并映射 EntityId→View，退出释放本局引用。
- [ ] 难度和节奏表：补齐阈值与保底模板，不把占位值作为最终平衡。

未来验收：相同生成版本/seed输出数据哈希相同；所有主路径边可执行；最宽屏和最大拉远不露边；吃补给挑战必有可达目标；失败上限有效；不同加载顺序不改布局。未经授权未执行生成测试或场景操作。
