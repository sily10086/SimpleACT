# SimpleACT 界面、镜头与设置

日期：2026-10-24；分析稿 v0.1。对应原文 §7、§11及局外流程。依赖现有UIModule；镜头冲突D17–D18、输入D28。

## 1. 界面清单与职责

| 界面/Widget（建议新增） | 内容 | 输入与业务接口 |
|---|---|---|
| MainMenuUI | 开始、难度、种子、库存、设置、退出 | 请求GameFlow，不直接LoadScene |
| LoadoutUI | 库存、8槽、分类、耐久、详情、开始 | 请求Profile配装；失败原因可见 |
| RunHUDUI | 耐力、档位刻度、挑战、进度、装备可用状态 | 只读运行快照与已提交事件 |
| ChallengeWidget/ModSlotWidget | 条目显示、状态/冷却 | CreateWidget建立生命周期 |
| PauseUI | 继续、设置、放弃 | 明确放弃结算规则后提交命令 |
| ResultUI | 死亡/通关、奖励、耐久、进度、重试、保存种子 | 等待Profile提交结果后允许依赖存档的操作 |
| SeedLibraryUI | 保存种子列表、输入/复制、难度/版本、成绩 | 解析与兼容性错误提示 |
| SettingsUI | 音量、键位、手柄、画面/震动开关 | Profile保存；功能强度范围需确认 |

不增加敌人血条、伤害数字、连击数字UI。无在线商店、账户登录、内购；现有ILoginUI只是框架示例，不代表游戏需要登录。

## 2. TEngine接入

新增窗口继承UIWindow并标记WindowAttribute，节点绑定遵循m_btn_/m_tmp_/m_img_/m_item_等当前前缀。RegisterEvent使用AddUIEvent，OnCreate创建子Widget，OnRefresh读最新只读快照，OnDestroy取消窗口自有异步并释放手动资产。生成绑定代码不手改。

示意：`await GameModule.UI.ShowUIAsyncAwait<RunHUDUI>(attemptId)`。该ShowUI API存在，RunHUDUI为拟新增。事件接口拟为IRunEvent、IProfileEvent，继承项目生成规则，不硬编码事件ID。

事件不应每Tick为每一个UI元素创建新对象；数值变化通知或复用只读快照即可。头顶耐力位置随相机每渲染帧投影，必要的OnUpdate/LateUpdate是显示需求，不能错误改成低频Timer导致抖动。

## 3. HUD制作布局建议（非已制作Prefab）

以可缩放Canvas和安全区域为边界。耐力与档位显示跟随角色头顶偏移，遇屏幕边缘clamp，避免被挑战栏遮挡；挑战右上、进度顶部、模组状态右下。具体像素尺寸待目标分辨率与视觉稿确认，不伪称已测量Prefab。

建议层级：RunHUDUI → CharacterStatus（StaminaFill、TierTicks）/TopProgress/ChallengeList/ModStatusList/TransientTips。纯装饰Image关闭Raycast Target；只有按钮/拖拽物件接收输入；世界空间耐力条不阻挡Gameplay鼠标命令。

键鼠拖拽与手柄焦点要分别有可见反馈；禁用项显示原因，不能只变灰。切换输入设备不丢失已选槽位。时停/暂停时UI提示继续使用表现时间，不能被全局timeScale=0冻住。

## 4. 镜头算法

建议CameraDirector属于表现层，由Run只读快照驱动。可借鉴 [Cinemachine](https://github.com/Unity-Technologies/com.unity.cinemachine) 的构图和边界职责，项目当前没安装该包；2.x/3.x接口不同，实施时选Unity2022.3兼容发行版本。首版矩形世界可直接使用薄的正交镜头控制器，避免只为一个镜头引入多余依赖。

参数：每档AnchorX、DeadZoneLeft/Right、AnchorY、DeadZoneBottom/Top、ZoomMagnification、FollowDamping、BoundsMargin、特效幅度/时长。原文不同档锚点描述冲突，配置只能保留一套权威值。

```text
snapshot -> 取档位镜头目标
根据基础视窗计算角色归一化位置
仅出死区时计算跟随目标（档位切换可平滑重构图，需确认）
基础位置平滑 -> 叠加特效偏移与倍率
按最终视窗大小clamp到视觉边界
输出Camera.position / orthographicSize
```

边界：halfHeight=orthographicSize，halfWidth=halfHeight×aspect；cameraX范围为[minX+halfWidth,maxX-halfWidth]，Y同理。若关卡小于视窗，使用中心与背景扩展/限制缩放策略，不用倒置的clamp区间。

原文85%表示画面倍率时，size=baseSize/0.85才能拉远；105%表示推近则size=baseSize/1.05。不要直接把百分比赋给size。蹬墙甩镜/抖动在最终边界约束内，关卡边缘不应抖出黑边。

“死区内镜头不动”与“档位变化锚点持续变化”存在控制优先级：建议档位切换允许慢速重构图，普通位移只在出死区时跟随，需确认。渲染镜头和用于威胁公平性的逻辑警戒区分离，防宽屏/震屏改变敌人行为。

## 5. 状态与资源处理

开窗立即读取快照，事件只处理后续变化，避免晚订阅漏初值。HUD携带AttemptId，旧Attempt事件被忽略。窗口隐藏不代表销毁，OnRefresh需刷新全部关键字段；重复打开不能再次注册监听。

异步图标采用SetSprite与窗口取消令牌；列表回收时保证旧加载结果不会覆盖新条目。冷却读当前tick差，不用每个图标各开Timer。种子分享只复制文本，不新增联网分享功能。
