# SimpleACT 模组配装与效果

日期：2026-10-24；分析稿 v0.1。对应原文 §6.1–6.2、§4.2 tierCost。依赖 D23–D25。

## 1. 功能范围与命名

支持局外库存、最多8槽配装、分类限制、永久基础模组、初始库存、报废过滤与局内效果。装备“模组”建议代码命名为 EquipmentMod，避免与 TEngine Module 混淆。原文没有具体模组完整清单，本文不虚构8个可交付技能。

ProfileModule 拥有库存和配装服务；RunModule 在开局收到不可变 LoadoutSnapshot 后创建局内效果。背包UI只请求装备/卸下，不自己移动数据库数组。

## 2. 三层数据

| 类型 | 属性 | 存储与生命周期 |
|---|---|---|
| EquipmentModDefinition | configId、分类、稀有度、效果定义、tradeOff、tierCost、permanent、maxDurability | Luban只读表 |
| EquipmentModInstance | instanceId、definitionId、durability、acquisitionTransactionId | Profile永久库存；同配置不同实例不能共用耐久 |
| EquippedModRuntime | slotIndex、实例引用ID、冻结效果参数、cooldownTicks、运行标记 | Attempt；不将冷却写回配置资产 |

LoadoutSnapshot 保存规则hash、槽位与实例ID、开局耐久及派生属性。记录初始耐久用于结算审计，不能每次实时重读档案导致当前战斗属性改变。ItemId不能取随机数消费掉地图RNG；由档案事务序号生成唯一实例ID。

## 3. 配装校验流程

1. 不在游玩中；目标槽合法；实例存在且未耗尽或永久。
2. 符合槽位分类；跨类溢出未确认前不开放。
3. 同一实例不能多槽占用；相同效果的叠加需显式策略，不能因为是不同实例就允许无限叠。
4. 校验整个配装效果：上限、速度、成本非负，互斥标签不存在冲突。
5. 原子更新配装并提交档案事务，成功后通知 UI。

手柄以“选库存→选槽→确认”替代必须拖拽；键鼠拖拽和按钮装备调用同一个命令，不维护两套规则。

```text
TryEquip(instanceId, slot):
  candidate = currentLoadout.WithReplacement(slot, instanceId)
  result = ValidateOwnershipAndSlotRules(candidate)
  if invalid: return reason
  CommitProfileChange(candidate)
  emit LoadoutChanged
```

## 4. 效果计算与扩展方式

可借鉴 [unity-gameplay-ability-system](https://github.com/sjai013/unity-gameplay-ability-system) 的静态定义/运行实例和成本/效果分离。其样例使用 ScriptableObject、秒制和 Coroutine，本项目不直接搬入；数据改用 Luban，持续效果按 Tick。

首版优先显式 EffectType 枚举加小处理器：属性加值、属性倍率、动作参数修正、触发效果、主动效果。仅有数值差异时共用处理器，不给每张配置表行新建 C# 子类。

建议确定顺序：基础属性 → 同类加值汇总 → 倍率按稳定槽序或明确定义乘积 → override按优先级 → 合法范围clamp。叠加语义必须在配置字段中说明，不能依赖 HashSet/字典枚举。

触发器消费 TickEvent 的值快照；每个效果有 triggerEventId 去重和本Tick触发预算，防“回复触发回复”递归。主动技能必须在 ActionSystem 的统一成本事务中扣耐力/tierCost，成功后才进入冷却，不能效果执行一半才发现付不起。

永久基础模组在初始档案创建时一次发放，不能每次进菜单重新送4个实例。初始赠送12–16个为待定数值，创建档案事务有 initialized 标记；升级存档时不得反复触发新手赠品。

## 5. 报废与重试

每次Attempt结束只扣当次快照中非永久实例；归零放入已耗尽分类，保留ID供历史显示。进入下次Attempt前再次校验配装：已有报废项不能继续按旧快照运作。推荐提示回配装或替换永久基础项，自动替换策略须确认。局内掉落物品进入库存，但当前Attempt不自动装备。

trade-off为策划内容：如增加续航同时降低机动，需具体字段和上下界；本文不把任何示例当最终模组。耐力、速度、消耗组合可能产生无限续航，需在后续参数分析中关注高档叠加，不能仅验证单个模组值合法。

## 6. 制作与修改目标

- [ ] EquipmentMod表与EffectDefinition：明确类别、品质、效果及代价，不混入运行冷却。
- [ ] Profile库存/Loadout服务：唯一实例、槽位校验、失败原因与事务。
- [ ] RuntimeEffectSet：开局冻结、稳定计算、触发去重、退局释放。
- [ ] InventoryUI/LoadoutSlotWidget：键鼠拖拽与手柄同一命令，已耗尽可看不可装。
- [ ] 初始档案数据：4个永久基础项与待定赠品，通过配置建立。

Prefab需求：槽位、库存条目、详情窗和已耗尽标签；图标用框架SetSprite加载。配置数值不放到Prefab里再复制一份。

未来验收：同一实例不能占两槽；关闭UI重开不重复赠送；局内获得物品不改当前属性；报废后重试被正确处理；效果退局不残留；同配置的不同实例耐久独立。未执行。
