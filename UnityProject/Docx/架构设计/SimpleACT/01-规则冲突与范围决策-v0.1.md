# SimpleACT 规则冲突与范围决策

日期：2026-10-24；分析稿 v0.1；读者：主策、程序。原文来源见 15，编号 Dxx 供所有详细方案引用。

“推荐”是供评审的实现基线，未取得规则变更确认。可先完成文档，编码必须先确认会改变玩法的决策。

## 1. 影响核心实现的决策

| ID | 原文证据与问题 | 推荐口径 | 影响与确认时点 |
|---|---|---|---|
| D01 | §4.2 说时停落岛照常清零；§4.5 说不清零；§4.6 再要求清零 | 所有落地清零；已开始的时停不取消 | 档位、镜头、时停、挑战；S0 确认 |
| D02 | §4.3 闪避总时长和 CD 都为 30 帧，又允许 CD 内连按加价；状态锁和空中仅一次使连闪路径不完整 | 第一版不允许动作中自取消；保留缓冲。是否另设提前重闪窗口、CD 起算点，交由策划明确 | 不能按当前文字同时实现所有规则；S0 确认 |
| D03 | “普通闪避后半段成功走位”没有可计算的成功口径 | 建立关联威胁 ID；后半段脱离其危险包络且生还才成功，每次动作最多一次。没有威胁不算 | 需要近失判定范围/时间窗；不能用“闪避结束即重置”代替 |
| D04 | 无敌帧要求跳过任何敌方判定，同时精准闪避必须检测被无敌挡掉的致死攻击 | 先识别接触及威胁，再无敌拦截伤害并生成精准闪避事件 | 战斗同帧顺序；是否地刺也能触发精准奖励需单独确认 |
| D05 | §4.5 弹刀有前后窗口，但武器未 ACTIVE 时是否存在可相交框未定义 | 使用独立的弹刀可交互区域与攻击实例帧轴；致死框仅 ACTIVE 生效 | 避免扩充致死时间；S0 确认 |
| D06 | §3.3 要求逐帧一致，只有种子/难度/输入；§6 模组、§8 配置也改变结果 | 复现键必须加规则版本、生成器版本、配装快照、初始状态及 RNG 算法；严格路线使用受控数值和碰撞 | 同机器、跨机器、跨版本是不同承诺；必须确定目标 |
| D07 | 时停是世界冻结、玩家 0.3 倍；动作帧、无敌帧、输入缓冲、升档是否缩放未定义 | 全局 60Hz；时停倒计时按全局 Tick；世界子时钟停；玩家动作/位移按整数分数子时钟；输入缓冲按全局 Tick | 时停内动作体感改变，需确认；禁止仅改 timeScale |
| D08 | 死亡“保留已击杀的进度”与从起点重开未解释；奖励、挑战槽、挑战计数也混用“局” | Profile 永久；Session 保留种子、挑战集合与已领奖标记；Attempt 重置位置、敌人、补给、连续挑战计数 | 保留击杀统计而非尸体世界是建议；若要世界持久化需另加状态快照 |
| D09 | 高难度开局 2 档，落地清零；§5.2 又说落地后“从 2 档重新爬”；§4.8 重开统一 0 档 | 首次进入按难度初始档；真正落地一律 0；死亡重试起始档需明确，建议同难度初始档 | 不能偷偷将 2 设成档位下限 |
| D10 | 仅挂 3–4 挑战，却有“一局完成 5 个挑战”；隐藏挑战仍待定 | 第一版停用该挑战，不加入抽取池；隐藏挑战作为扩展 | 不补造未定义的领奖点系统 |
| D11 | 原文把固定帧、种子与确定性混同；Unity 物理、浮点、遍历顺序尚无约束 | 固定 Tick 只是必要条件之一；优先受控 2D 运动/碰撞和稳定排序；Unity 物理快速原型单独标注限制 | 物理路线若降为同环境重复，需要明确放宽需求 |

## 2. 内容、经济和表现缺项

| ID | 问题 | 推荐处理/影响 |
|---|---|---|
| D12 | “累计滞空 3 分钟”却落地清零；与单次 60 秒含义重复 | 拆累计与连续指标，先按达成口径视为连续；修改名称待确认 |
| D13 | “耐力没见底”无判定终点 | 通关才达成，任一次降到 0 即本 Attempt 失败 |
| D14 | 同时通关/死亡、击杀/受击、领奖/死亡、升档/落地无全局顺序 | 使用 05 的推荐顺序；同帧死亡与终点建议死亡优先，已满足普通挑战仍可保存 |
| D15 | 敌人胶囊形状却可能碰身体即死，与“致死物永远尖三角”冲突 | 身体不致死、武器/子弹/地刺致死为推荐；或修改形状宪法，二者选一 |
| D16 | 0 档静音、落地从第一层重进、死亡音乐不停互相竞争 | 音频单独状态表；死亡保留当前曲目相位，落地短静音后是否回底层待确认 |
| D17 | 镜头百分比 85% 意为拉远，直接赋 orthographicSize×0.85 会拉近；1–4 档锚点35–40%与线性插值不一致 | 百分比定义为画面倍率，size=base/倍率；采用逐档数据而不同时强制两套锚点规则 |
| D18 | 0 档镜头、不同屏幕比例、竞速计时是否含暂停/时停未写 | 明确 0 档参数；成绩按未暂停全局 Tick，包含时停为推荐；表现不反向影响威胁生成 |
| D19 | G1 写“任意两岛”，大关卡首尾岛不可能都满足局部续航距离；G2–G7 又允许降级 | 改为主路径相邻节点存在可达边；所有安全底线不可降级，只有数量/节奏目标可在获批范围调节 |
| D20 | G5 只靠生成方位不能保证玩家回头时威胁仍从右/上进入 | 用固定逻辑警戒区和发射方向规则约束；屏幕镜头仅表现；回头走位规则待确认 |
| D21 | 耐力每 2 秒升档回 10，空中每秒仅耗 1；有升档正收益与满档续航断层 | 这是占位参数推导而非试玩事实；应评估跳跃重力、动作频率、时停和高档成本共同收支 |
| D22 | 满套 8 个消耗经济默认全部非永久，但有 4 个永久模组；“任何失败有收获”与开场死零奖励冲突 | 按实际非永久装备数重算；不擅加保底。至少展示进度/学习性反馈，是否满足 P5 需主策认可 |
| D23 | 槽位分类、溢出、重复效果、主动模组按键、具体模组清单未定 | 先定义数据与接口；跨类和同效果叠加默认禁止作为方案建议；不编造最终模组 |
| D24 | 报废后不能装备，但死亡重试又锁定原配装 | 开局快照重建前移除报废项，提示回配装或用永久基础项补位；不得自动复制已报废实例 |
| D25 | 同种子随机掉落可反复刷同奖；挑战保留与新 Session 重新领奖未定义 | 同 Session 奖励幂等；新 Session 是否可重复是经济规则。无服务器单机不承诺防篡改 |
| D26 | 新种子要随机产生，又禁止时钟种子 | 新建种子在局外生成一次并保存；模拟内禁止读时钟，算法固定；随机种子入口作为明确例外确认 |
| D27 | 可破坏障碍、开关只在美术形状表出现；无机制规格 | 作为未定义扩展，不放入首版交付，待补交互和生成规则 |
| D28 | 难度解锁、退出/强退、低难度检查点、暂停和设备断开缺规则 | 建议首版各难度同起点重试；不据“高难度无检查点”反推低难度必有检查点。其余见08/09 |
| D29 | 配套数值工作簿未提供，正文声称数值唯一源却又列占位值 | 建立表结构但不称表已存在；禁止把暂定值定稿或生成不经确认的最终表 |
| D30 | px/s 与 Unity 世界单位无转换基准，重力和跳高未定义 | 明确设计像素单位比例，与贴图 PPU 区分；转换在导入时完成 |
| D31 | 原文说程序生成是“唯一答案”、同屏少就“无特殊优化需求” | 都是设计判断而非技术事实；手工片段约束拼接也可满足目标，生成/加载/GC仍需预算 |
| D32 | 0 耐力自由落体“直到落地”与空中升档回耐力可恢复冲突 | 建议 Exhausted 锁存到落地；期间升档是否暂停及其他回复能否解锁必须确认 |
