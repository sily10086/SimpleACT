# SimpleACT 输入与确定性模拟

日期：2026-10-24；分析稿 v0.1。对应原文 §3、§5.3、§11。依赖决策 D06、D07、D11、D18、D26、D30。

## 1. 功能与边界

支持 PC 键鼠与手柄、按动作绑定、按键缓冲、暂停/设备断开、固定 60Hz 模拟、种子重赛。输入回放是证明复现能力的开发基础；可见的幽灵角色、在线排行榜、网络联机不是原文已定义功能。

同种子只决定随机初态，不会自动决定物理、配置、装备或事件顺序。[Kimbatt 的确定性项目](https://github.com/Kimbatt/unity-deterministic-physics)也明确要求创建顺序、更新阶段与数值输入受控。本项目方案据此要求完整初始状态与稳定运算路径，不直接引入其旧 DOTS 物理。

## 2. 输入模块

当前 manifest 没有 Input System，activeInputHandler=0。建议新增官方 Input System 的 Unity2022.3 兼容发行版，锁定包版本后使用其重绑定与手柄能力；目前仅为依赖建议，不安装。[参考仓库与样例](https://github.com/Unity-Technologies/InputSystem)。

| 动作映射 | 数据 | 处理 |
|---|---|---|
| Move | 量化水平轴，范围和死区入配置 | 每 Tick 持续状态，不将手柄浮点噪声原样录制 |
| Jump/Attack/Dodge | press 边沿及必要的 hold/release | 每个边沿拥有输入序号，只能消费一次 |
| Pause/Cancel/Confirm/Navigate | UI 命令 | UI 与 Gameplay Map 互斥，防点击菜单同时出刀 |
| 模组主动技能 | 待定 | 不能在具体模组规则缺失时先规定 8 个快捷键 |

InputModule 在设备更新阶段收集事件；RunModule 在 Tick 开始取已分配 tickIndex 的 InputCommand。某渲染帧产生多个模拟 Tick 时，Press 只入队一次；某渲染帧没有模拟 Tick 时保留输入到下一个 Tick。重绑定用稳定 action ID 存档，不存当前显示的中文按键名。

建议 InputCommand：tickIndex、sequence、moveAxisQuantized、pressedMask、releasedMask、heldMask。暂停时不积累 Gameplay 缓冲；恢复清理旧边沿但重新采样当前按住状态；手柄断开建议暂停并给键鼠接管入口。

## 3. 输入缓冲与动作受理

缓冲帧数来自动作配置，原文占位为 6 帧。缓冲保存命令及 expireTick，动作执行成功才消费；过期移除。耐力不足的反馈节流，但不能把一次失败自动变成每帧反复扣费。

```text
采样边沿 -> 分配下一可受理 Tick -> 放入缓冲
Tick 开始：丢弃过期项
按约定动作优先级选择可执行请求
动作锁/次数/耐力/tierCost 全部通过：
    一次性扣成本并消费输入，创建 ActionInstance
否则：保留至过期或按规则拒绝，不改变余额
```

同时按 Jump/Attack/Dodge 的优先级属于 D14：建议显式配置枚举优先级，录入规则版本；不得依赖按钮回调到达顺序。输入缓冲不是自动连发，持续按攻击是否重复触发需策划定义。

## 4. 固定 Tick 与三个时钟

RunModule 注册单一 Update 驱动，累积 unscaled delta，按 1/60 秒逐个推进权威 Tick；渲染只在两次快照之间插值。每帧最多处理若干 Tick 可用于防止卡死，但不能丢弃已累计时间后还声称回放一致：超预算保留 backlog，必要时降渲染刷新；无法维持实时性则标记该成绩运行异常。暂停不向 accumulator 加时间。

| 时间域 | 正常 | 时停 | 暂停 | 用途 |
|---|---|---|---|---|
| GlobalTick | 每步 +1 | 每步 +1 | 不推进 | 时停剩余帧、输入缓冲、成绩时间（建议） |
| WorldTick | 每步 +1 | 不推进 | 不推进 | 敌人前摇/子弹移动/世界危害 |
| PlayerStep | 每步推进 | 整数比率，如占位3/10 | 不推进 | 玩家动作帧、无敌帧、位移、玩家资源计时（待确认） |

使用整数相位累加器：每 GlobalTick 累加 numerator，达到 denominator 才执行完整 PlayerStep 并扣 denominator。这样避免用浮点扣“0.3帧”。该方式会带来低频模拟，显示需插值；不能假装没有手感影响。若只缩放位移、不缩放动作窗口，需另一个明确规则版本。

挑战的“时停累计秒数”按 GlobalTick 计算；连续滞空按 PlayerStep 还是 GlobalTick 必须配置固定口径，建议 PlayerStep，避免时停无风险白涨档。暂停和时停不能混为一个 bool。

## 5. 碰撞与数值路线

推荐正式方案：受控 2D 几何与定点/整数数值核。角色使用简化 AABB/胶囊近似，静态平台和空气墙使用轴对齐形状，三角形视觉与明确危害区域配套；高速位移采用 swept 检测，稳定求最早接触，平局按 entityId 排序。

定点数学可参考 [FixedMath.Net](https://github.com/asik/FixedMath.Net)，该仓库已归档，仅作为算法候选，实施前需要确定溢出范围、除法舍入与许可证。使用第三方定点类型不等于拥有完整确定性物理。

快速切片替代方案：Unity Physics2D + 固定更新 + 明确查询顺序。它适合尽快调手感，但本次没有跨环境复现证据，不能把它交付为严格确定性方案。切换此路线须确认降低保证范围，不把未来替换成本隐藏起来。

避免 Animator Event、OnTrigger 回调顺序、GameObject InstanceID、Dictionary 遍历顺序驱动权威判定。Unity Collider 可用于制作可视化；正式受控路线中的权威碰撞由导出的几何数据计算。Transform 只由快照写入 View。

## 6. 随机源、种子和版本

独立 RNG 流：Map、Challenge、Loot、Cosmetic；从稳定哈希派生，禁止 string.GetHashCode 和 UnityEngine.Random 全局状态。Cosmetic 不影响逻辑流。固定 RNG 算法和整数取样策略，算法升级增加版本。

```text
RunDescriptor = {
  seed, difficulty, ruleHash, generatorVersion, rngVersion,
  loadoutSnapshot, initialState, simulationVersion
}
mapRng = Derive(seed, "Map", generatorVersion)
challengeRng = Derive(seed, "Challenge", ruleHash)
lootRng = Derive(seed, "Loot", ruleHash)
```

Session/Attempt 的持久化 ID 不参与地图生成；否则分享同一 seed 仍无法获得同图。重试是否恢复 Loot 状态需依 D08/D25 明确，奖励交易使用稳定奖励序号取样以避免存档重试再抽一次。

短种子编码只承载可恢复整数和格式版本，可加校验位；难度/规则版本/配装是成绩条件，不能把“同图”宣传为“公平同配置竞速”。新种子在局外产生一次并记录，回放绝不再次产生种子。

## 7. 制作步骤与伪代码

- [ ] InputModule：建立动作映射与设备适配，输出量化命令，为键鼠和手柄提供统一入口。
- [ ] RunClock/InputBuffer：定义时钟、有效期、序号与单次消费，解决高刷/低刷输入遗漏。
- [ ] RunWorld/CollisionWorld：先完成平台落地、墙面和危害 swept 查询，再增加战斗判定。
- [ ] RandomStreams/RunDescriptor：版本化算法与初始状态，隔离表现随机。
- [ ] ReplayRecorder：记录命令与阶段性状态哈希；不保存 Unity 对象引用。

```text
OnUpdate(realDelta):
  Input.Sample()
  if paused: return
  accumulator += realDelta
  while accumulator >= fixedStep and budgetAvailable:
    command = buffer.Read(globalTick)
    world.Step(command)       // 固定阶段顺序见05
    recorder.Append(command, HashAuthoritativeState())
    accumulator -= fixedStep
  view.Apply(previous, current, interpolationAlpha)
```

制作资源：InputActionAsset、绑定设置页、可视化判定 DebugView、最小测试地图。均为未来目标，当前未生成。

未来验收：同运行版本的录制输入在不同显示帧率下状态哈希一致；暂停不涨档；时停不冻输入；连续 catch-up Tick 不重复消费按键；RNG 可保存恢复；池复用不改变 entityId 顺序。跨机器结论需要实际运行证据，本次未测试。
