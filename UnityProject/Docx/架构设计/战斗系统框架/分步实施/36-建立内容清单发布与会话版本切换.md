## 1. 目标与需求

让动作、配置、表现资源和机制版本成套发布，并在进入下一场时选择兼容快照。

- **R1**：Manifest 引用成套内容与资源版本，不能单独替换一个 JSON 便宣称支持热更。
- **R2**：运行中的会话继续使用既有快照。
- **R3**：发布步骤可追踪到源、编译器、机制与资源清单。

## 4. 具体执行任务

### 36.1 生成完整内容清单

- [ ] **做什么**：生成完整内容清单。
- **为什么**：资源与配置不匹配会出现动作有逻辑却无表现。
- **怎么做**：汇总动作、图、表、view binding 和机制要求，记录 hash；保留稳定排序。
- **关键伪代码**：

```text
manifest = Build(schemaVersion, mechanismVersion, contentHashes, resourceIds)
```

### 36.2 接入既有构建流程

- [ ] **做什么**：接入既有构建流程。
- **为什么**：独立输出目录不一定会被资源系统收集。
- **怎么做**：实施时定位现有 YooAsset/HybridCLR 流程，将战斗产物纳入实际收集；不要新增第二套热更框架。
- **关键伪代码**：

```text
CompileContent -> GenerateTables -> CollectResources -> ExistingBuildPipeline
```

### 36.3 在会话边界切换

- [ ] **做什么**：在会话边界切换。
- **为什么**：战斗中替换动作数组会让运行索引错位。
- **怎么做**：下载/准备候选版本不修改 activeSnapshot；下一场兼容检查成功后使用新快照。
- **关键伪代码**：

```text
next = PrepareCandidateVersion()
BeginNextSession -> Freeze(next)
currentSession keeps old snapshot
```
