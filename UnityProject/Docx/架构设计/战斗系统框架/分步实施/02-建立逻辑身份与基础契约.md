# 步骤 02｜建立逻辑身份与基础契约

版本：v0.1｜阶段：S1｜状态：方案已编写，实施未开始。

> 本文属于已授权的文档细化。所有新增类型、接口及路径是拟实施方案；伪代码用于表达控制流，不是可直接编译的代码。执行本步前确认该批次；完成后填写实际记录。

## 1. 目标与需求

让单位、动作、命令与结果具有稳定且可追踪的身份，阻止对象池复用后旧请求写入新对象。

- **R1**：EntityHandle 包含 battleId、entityId、generation；ActionHandle 每次起手不同。
- **R2**：定义 CommandId、ResultId、拒绝码与动作结束原因；不用 GameObject 实例 ID 作为逻辑身份。
- **R3**：持久 stableId 与运行时索引分离，不把 GetHashCode 当持久 ID。

## 4. 具体执行任务

### 02.1 定义值类型与比较规则

- [ ] **做什么**：定义值类型与比较规则。
- **为什么**：跨系统必须对同一身份有相同判断。
- **怎么做**：字段只读，完整字段参与比较；无效句柄明确表示，不用 null GameObject 表示逻辑不存在。
- **关键伪代码**：

```text
IsSameEntity(a,b) = a.battleId == b.battleId && a.entityId == b.entityId && a.generation == b.generation
```

### 02.2 建立实例号与结果号分配约定

- [ ] **做什么**：建立实例号与结果号分配约定。
- **为什么**：相同动作重放和同帧多个结果必须能区分。
- **怎么做**：编号在所属会话内单调分配，记录溢出处理；ActionId 与 DefinitionId 用不同类型。
- **关键伪代码**：

```text
actionHandle = NewActionHandle(owner, nextActionInstance++)
resultId = { battleId, nextResultSequence++ }
```

### 02.3 定义跨边界负载

- [ ] **做什么**：定义跨边界负载。
- **为什么**：后续队列需要清楚知道哪些数据可保存。
- **怎么做**：命令和结果只含身份、值、紧凑引用和明确参数；表现对象只留在桥接层。
- **关键伪代码**：

```text
IntentCommand = { commandId, actor, primitive, issuedTick, expireTick, epoch }
CombatResultHeader = { resultId, tick, source, target, action }
```

## 5. 本步完整流程伪代码

```text
BeginBattle -> AllocateBattleId()

CommitResult -> AllocateResultSequence()
ReceiveDelayedRequest(handle):

```

## 6. 边界与失败处理

- 跨会话旧句柄直接失效，entityId 相同也不接受。
- epoch 表示命令来源/动作代次，不能替代 entity generation。
