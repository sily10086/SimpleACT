## 1. 目标与需求

先建立 HP、耐力、护盾、削韧和 CD 的权威存储与提交接口，为起手扣费和伤害提交提供统一入口。

- **R1**：属性只由指定提交方写入，AI/UI 只读。
- **R2**：起手失败不扣费；动作成功与扣费、CD 同一提交边界。
- **R3**：属性计算顺序、截断及恢复时间域固定。

## 4. 具体执行任务

### 08.1 建立属性与修饰接口

- [ ] **做什么**：建立属性与修饰接口。
- **为什么**：Buff 以后加入时不能让每个技能自行改攻击力。
- **怎么做**：先实现基础属性；预留按来源修饰的确定顺序，避免此时引入通用表达式系统。
- **关键伪代码**：

```text
final = Clamp(Compute(baseValue, orderedModifiers), min, max)
```

### 08.2 拆分费用预检与提交

- [ ] **做什么**：拆分费用预检与提交。
- **为什么**：扣费之后创建动作失败会留下半次起手。
- **怎么做**：预检只读；动作系统完成全部准备后在无回调的提交段调用费用提交。
- **关键伪代码**：

```text
quote = CheckCost(unit, definition)
CommitCost(quote) only inside action transaction
```

### 08.3 实现冷却与恢复

- [ ] **做什么**：实现冷却与恢复。
- **为什么**：Time.time 不遵守单位时停规则。
- **怎么做**：存 endUnitTick；恢复条件从当前动作/状态读取，按演示每 6 UnitTick 恢复 1。
- **关键伪代码**：

```text
cooldownReady = unitTick >= endTick
if canRecover && recoveryDue: stamina = min(max, stamina + 1)
```

## 5. 本步完整流程伪代码

```text
PreviewStartCost(unit, action):

  return CostQuote or Rejection

```
