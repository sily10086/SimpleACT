# 步骤 20｜接入设备输入与焦点暂停处理

版本：v0.1｜阶段：S4｜状态：方案已编写，实施未开始。

> 本文属于已授权的文档细化。所有新增类型、接口及路径是拟实施方案；伪代码用于表达控制流，不是可直接编译的代码。执行本步前确认该批次；完成后填写实际记录。

## 1. 目标与需求

将项目当前旧输入后端转换成统一原语，支持多逻辑补步、暂停和失焦。

- **R1**：首版复用现有输入后端，不预设安装 Input System。
- **R2**：按键边沿每渲染帧采集一次，分配到下一执行 Tick。
- **R3**：失焦清持续方向，暂停期间是否接收战斗边沿明确规定；首版建议丢弃。

## 4. 具体执行任务

### 20.1 读取边沿与持续值

- [ ] **做什么**：读取边沿与持续值。
- **为什么**：补步不能重复 GetKeyDown 对应的攻击。
- **怎么做**：OnHostUpdate 先采集一次，再由调度器分配队列；逻辑不直接读取 KeyCode。
- **关键伪代码**：

```text
raw = CaptureOncePerRender()
QueueEdges(raw.edges); SetLatestMove(raw.direction)
```

### 20.2 映射并记录命令

- [ ] **做什么**：映射并记录命令。
- **为什么**：回放需要实际采用时点。
- **怎么做**：给命令分配 sequence、actor、下一 SimTick 与 expireTick；记录最终分配而非仅墙钟。
- **关键伪代码**：

```text
command.issuedTick = nextExecutableTick
command.expireTick = issuedTick + 9
```

### 20.3 处理失焦与恢复

- [ ] **做什么**：处理失焦与恢复。
- **为什么**：松键事件可能在失焦期间丢失。
- **怎么做**：失焦置 Move=0，清宿主边沿残留；暂停不积累攻击，恢复等新边沿。
- **关键伪代码**：

```text
OnFocusLost: SetMoveZero(); ClearDeviceEdgeQueue()
OnResume: ResyncDeviceHeldState()
```

## 5. 本步完整流程伪代码

```text
HostUpdate:
  if not Running: discard combat edges
  if focus lost: release sustained inputs
  else if not paused:
    capture device edges and held direction
    map via profile
    enqueue once for next Tick
  advance battle scheduler
Tick P1:
  consume assigned commands through IntentResolver
```
