## 1. 目标与需求

让战斗问题能沿命令、动作、命中和结果追踪，并形成后续可按授权执行的分层检查清单。

- **R1**：记录版本、随机状态、命令分配 Tick、动作迁移和最终结果。
- **R2**：诊断重演与跨平台确定性分开，不夸大日志能力。
- **R3**：检查必须记录真实结果，未执行保持未勾选。

## 4. 具体执行任务

### 37.1 定义最小记录事件

- [ ] **做什么**：定义最小记录事件。
- **为什么**：仅记录 HP 变化无法解释为什么没起手。
- **怎么做**：关联 CommandId→ActionHandle→HitGroup→ResultId，记录拒绝、过载和关键时域变化；限制容量。
- **关键伪代码**：

```text
trace.Append(tick,phase,command,action,target,result,reason)
```

### 37.2 提供只读诊断视图

- [ ] **做什么**：提供只读诊断视图。
- **为什么**：诊断工具不能改变权威顺序。
- **怎么做**：查看器读取导出副本，按 Tick/实体过滤；记录开启成本作为待测项。
- **关键伪代码**：

```text
export = recorder.CopyBoundedSnapshot()
viewer.FilterByEntityOrCommand(export)
```

### 37.3 建立检查层次

- [ ] **做什么**：建立检查层次。
- **为什么**：编译成功不能代替生命周期和玩法检查。
- **怎么做**：分契约/核心逻辑/Unity 接线/玩法/性能，每项引用步骤及具体场景，只有用户要求后运行。
- **关键伪代码**：

```text
Case = {stepIds, given, when, expected, actual:null, evidence:null, status:NotRun}
```

## 5. 本步完整流程伪代码

```text
DuringBattle:
  record bounded high-value transitions and outcomes
OnExportRequest:
  attach manifest, initial state metadata and random state
  export owned copy
WhenUserRequestsChecks:
  run selected layer and cases
  record environment, actual result and evidence
  keep unexecuted cases NotRun
```

## 6. 边界与失败处理

- 若仅录结果只能做表现回放；命令重演还依赖初始状态、随机、运动及内容一致。
- 不默认无限写日志或每 Tick 导出磁盘。

## 7. 完成标准与待执行检查

- [ ] 能追踪一次 A→B 从输入到命中的关联链。
- [ ] 能解释取消前后哪些结果已提交、哪些命令失效。
- [ ] 检查记录清楚区分未执行、通过、失败与阻塞。

这些是将来判断本步是否完成的条件，本次没有执行。用户要求检查时，再按上述场景记录输入、预期、实际结果和证据；没有检查结果不填写“通过”。
