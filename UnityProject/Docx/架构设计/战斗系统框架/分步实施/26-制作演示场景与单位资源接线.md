## 1. 目标与需求

把逻辑链和资源桥接成可操作的单机练习场，形成基础阶段的实际交付物。

- **R1**：一名玩家、一名敌人、静态地面/墙、弹丸和 HUD。
- **R2**：场景中只有一个游戏入口和一个战斗驱动。
- **R3**：Prefab/Scene/池配置通过 Unity CLI 或编辑器制作并记录引用。

## 4. 具体执行任务

### 26.1 建立场景入口和出生点

- [ ] **做什么**：建立场景入口和出生点。
- **为什么**：复制场景易产生第二 GameEntry。
- **怎么做**：保留唯一入口，添加 PlayerSpawn/EnemySpawn/Camera/静态阻挡，初始 Transform 明确记录。
- **关键伪代码**：

```text
scene = {singleEntry, playerSpawn, enemySpawn, camera, obstacles}
```

### 26.2 制作表现 Prefab

- [ ] **做什么**：制作表现 Prefab。
- **为什么**：逻辑判定不能依赖动画回调碰撞器。
- **怎么做**：UnitView 根 Scale1；Visual 挂 SpriteRenderer，VfxAnchor 为挂点；阻挡层与 Hurtbox 逻辑分开。
- **关键伪代码**：

```text
UnitView(root identity)
  Visual(SpriteRenderer)
  VfxAnchor
```

### 26.3 接入池与演示控制

- [ ] **做什么**：接入池与演示控制。
- **为什么**：脚本存在不代表资源引用完成。
- **怎么做**：配置池名、Prefab、预热数，绑定单位定义和 ViewId，接入 HUD 与 J/K/移动演示。
- **关键伪代码**：

```text
PrepareConfiguredPools -> SpawnViews -> BindEntities -> StartBattle
```
