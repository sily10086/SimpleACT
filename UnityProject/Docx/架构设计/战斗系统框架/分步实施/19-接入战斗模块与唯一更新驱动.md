## 1. 目标与需求

用一个 TEngine 业务模块管理会话，并把已有逻辑系统装配到单个 Update 驱动。

- **R1**：通过 GameModule 门面访问模块。
- **R2**：Start/Stop 与监听注册配对，重复调用不产生双驱动。
- **R3**：模块生命周期覆盖 Loading/Ready/Running/Stopping/Disposed 及失败状态。

## 4. 具体执行任务

### 19.1 装配 World

- [ ] **做什么**：装配 World。
- **为什么**：子系统要共享同一注册表、时钟和规则。
- **怎么做**：构造时显式传入依赖；不为每个系统创建全局单例。
- **关键伪代码**：

```text
world = new BattleWorld(sharedRegistry, systems, ruleSnapshot)
```

### 19.2 同步注册驱动

- [ ] **做什么**：同步注册驱动。
- **为什么**：Utility.Unity 延迟添加监听可能在 Stop 后补注册。
- **怎么做**：使用实际 IUpdateDriver Add/Remove 同步接口，经新增门面访问；不修改公共 Utility。
- **关键伪代码**：

```text
Start: driver.AddUpdate(OnUpdate)
Stop: driver.RemoveUpdate(OnUpdate)
```

### 19.3 保护生命周期迁移

- [ ] **做什么**：保护生命周期迁移。
- **为什么**：重复进入游戏不能重复扣每 Tick 的逻辑。
- **怎么做**：Ready 才能 Start；Stop 先禁止输入与推进，再进入完整资源清理。
- **关键伪代码**：

```text
if state != Ready: return InvalidState
state = Running; registered = true
```

## 5. 本步完整流程伪代码

```text
Prepare(snapshot):
  require not Running
  assemble world and bridges
  state = Ready
Start():
  if Ready: register exact delegate once; state = Running
OnUpdate(dt):
  if Running: capture input then clock.Advance(dt, world.Step)
Stop():
  stop accepting commands
  unregister exact delegate if registered
  state = Stopping
  continue cleanup contract from step 27
```

## 6. 边界与失败处理

- 本步门面是新增目标，不把 GameModule.Battle 描述成现有 API。
- RunModule 将来复用同一 World，不添加第二驱动。
