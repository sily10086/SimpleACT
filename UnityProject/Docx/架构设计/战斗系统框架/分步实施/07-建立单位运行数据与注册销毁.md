# 步骤 07｜建立单位运行数据与注册销毁

版本：v0.1｜阶段：S1｜状态：方案已编写，实施未开始。

## 1. 目标与需求

集中持有每个单位的运行状态，提供按完整句柄查找和稳定遍历的能力。

- **R1**：定义共享只读，运行数据每单位独立。
- **R2**：实体增删在明确阶段处理，不在遍历过程中随意修改集合。
- **R3**：逻辑销毁与 View 回池分开，旧 generation 查找失败。

## 4. 具体执行任务

### 07.1 拆分权威数据槽

- [ ] **做什么**：拆分权威数据槽。
- **为什么**：HP、CD 和动作不能在 AI/表现各存一份可写副本。
- **怎么做**：UnitRuntime 包含各领域数据槽，系统获得所需访问权，外部仅取快照。
- **关键伪代码**：

```text
unit = CreateRuntime(definition)
AI receives ReadOnlyUnitContext(unit)
```

### 07.2 实现注册与解析

- [ ] **做什么**：实现注册与解析。
- **为什么**：实体复用必须有可靠失效机制。
- **怎么做**：按完整句柄解析；遍历按稳定 entityId；移除后递增槽代次或不重用 ID。
- **关键伪代码**：

```text
Resolve(handle): match battleId, id, generation and aliveRegistration
```

### 07.3 排队处理生命周期

- [ ] **做什么**：排队处理生命周期。
- **为什么**：命中集合遍历时销毁对象会破坏同帧裁决。
- **怎么做**：死亡先记状态，逻辑移除按约定阶段延期；P7 输出解绑所需结果。
- **关键伪代码**：

```text
Death -> MarkDead -> QueueRemoval
NextLifecycleBoundary -> RemoveRegistryEntry
```

## 5. 本步完整流程伪代码

```text
P0:

DelayedCallback:
  ResolveExact(handle) or reject
```

## 6. 边界与失败处理

- Dead 不必立刻移除注册表，死亡演出期间应明确是否保留只读实体。
- UnitRuntime 不继承 MonoBehaviour；位置权威归 Motor。
