## 1. 目标与需求

在开始战斗前一次完成版本、引用和能力校验，让整个会话使用同一份配置。

- **R1**：manifest 记录 schema、机制版本、内容 hash 和必要资源绑定。
- **R2**：不在 Tick 中加载配置，不在战斗中修改共享定义。
- **R3**：加载失败不进入 Ready；已取得资源按拥有关系释放。

## 4. 具体执行任务

### 04.1 建立版本兼容检查

- [ ] **做什么**：建立版本兼容检查。
- **为什么**：合法 JSON 不等于运行机制兼容。
- **怎么做**：按 schema 和所需 feature 判断；报告 manifest、资源 ID 与缺失能力，不只返回 false。
- **关键伪代码**：

```text
if !Supported(schema, features): return IncompatibleContent(details)
```

### 04.2 构建原子快照

- [ ] **做什么**：构建原子快照。
- **为什么**：一部分新动作与一部分旧伤害表混用会改变规则。
- **怎么做**：所有依赖均准备好才发布 Snapshot；使用局部候选变量，失败保留未运行状态。
- **关键伪代码**：

```text
candidate = Compile(allSources)
PublishReadySnapshot(candidate) only when no errors
```

### 04.3 规定原始资源释放点

- [ ] **做什么**：规定原始资源释放点。
- **为什么**：解析结果不能意外依赖已卸载 TextAsset。
- **怎么做**：冻结后只保留拥有的值数据；资源适配者回收原句柄，记录资源 ID/hash 供诊断。
- **关键伪代码**：

```text
bytes -> ownedDefinitions -> snapshot
ReleaseRawContentLeaseAfterCompile()
```

## 5. 本步完整流程伪代码

```text
LoadSnapshotAsync(source, expectedMechanism):
  manifest = await source.ReadManifest()
  CheckCompatibility(manifest, expectedMechanism)
  raw = await source.ReadAllReferencedContent(manifest)
  report = Validate(raw)
  if report.HasErrors: return Failed(report)
  snapshot = CompileAndFreeze(raw)
  return Ready(snapshot)
// resource leases are released by their owning adapter
```

## 6. 边界与失败处理

- 热更仅在下一场选择新快照；当前场继续持有旧快照。
- 此处 source 为拟新增端口，不是已经存在的 TEngine API。
