## 1. 目标与需求

在确定性或联网成为硬需求时，先建立可证明的模拟契约和替换计划，再进入工程改造。此步交付专项方案，不把网络系统压缩成几个接口。

- **R1**：区分结果回放、同环境命令重演、跨平台确定性和联网回滚。
- **R2**：覆盖数值、随机、碰撞、顺序、快照、输入协议与版本。
- **R3**：60Hz 和整数帧都不是跨平台一致性的证明。

## 4. 具体执行任务

### 41.1 明确承诺等级

- [ ] **做什么**：明确承诺等级。
- **为什么**：记录结果回放不能证明战斗重算一致。
- **怎么做**：为每等级定义输入、输出和允许误差/完全相等字段，列出平台组合。
- **关键伪代码**：

```text
ReplayLevel = ResultPlayback | SameEnvironmentResim | CrossPlatformDeterministic | NetworkRollback
```

### 41.2 列出确定性依赖

- [ ] **做什么**：列出确定性依赖。
- **为什么**：浮点碰撞、集合顺序和异步生成都能造成分歧。
- **怎么做**：逐项确定数值类型、几何查询、随机流、实体生成序、时域与版本快照，标出替换成本。
- **关键伪代码**：

```text
NextState = Step(Snapshot, OrderedCommands, RNGState, ContentVersion)
```

### 41.3 制定验证与迁移顺序

- [ ] **做什么**：制定验证与迁移顺序。
- **为什么**：没有跨环境证据不能承诺网络功能可用。
- **怎么做**：先纯核心同输入摘要比较，再跨平台，再引入网络输入与回滚；记录首次分歧 Tick 和字段。
- **关键伪代码**：

```text
CompareStateHashesPerTick()
OnMismatch -> DumpFirstDivergentState()
```

## 6. 边界与失败处理

- 联网不能直接沿用丢弃宿主时间债务的单机降级策略。
- 回滚必须覆盖 Buff、账本、动作游标、RNG 和命令消费，不只保存 Transform/HP。
