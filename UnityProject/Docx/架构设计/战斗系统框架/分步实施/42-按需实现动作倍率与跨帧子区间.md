## 1. 目标与需求

单独实现动作倍率，使跨过的事件、窗口与几何接触得到一致处理。本步可独立于多通道和复杂 AI 进行。

- **R1**：局部进度采用明确表示，不仅保存整数终点帧。
- **R2**：跨帧不漏事件与窄命中窗口；冻结后不补冻结期间的债务。
- **R3**：倍率与子步预算由配置限制，不能无限增加每 Tick 工作量。

## 4. 具体执行任务

### 42.1 定义进度推进

- [ ] **做什么**：定义进度推进。
- **为什么**：单纯提高动画播放速度会脱离逻辑。
- **怎么做**：动作时间统一使用局部进度，单位冻结时增量为零。
- **关键伪代码**：

```text
nextProgress = oldProgress + allowedRate
if frozen: nextProgress = oldProgress
```

### 42.2 枚举经过的区间

- [ ] **做什么**：枚举经过的区间。
- **为什么**：f10 跳 f12 会漏掉 f11 上的攻击。
- **怎么做**：按事件和窗口边界分段，逐段求值并扫掠；事件游标防止边界重复。
- **关键伪代码**：

```text
segments = SplitAtRelevantBoundaries(old,next)
for segment: EvaluateEventsAndGeometry(segment)
```

### 42.3 限制预算并保持共同裁决

- [ ] **做什么**：限制预算并保持共同裁决。
- **为什么**：局部变速不能悄悄改变互击规则。
- **怎么做**：所有子区间候选仍进入共享 Tick 批次；高倍率或过密边界在导出时拒绝。
- **关键伪代码**：

```text
if estimatedSegments > budget: RejectContent()
CollectSegmentsIntoSharedTickBatch()
```
