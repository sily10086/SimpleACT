## 1. 目标与需求

让玩家与 AI 都提交原语命令，并将边沿缓冲、持续移动和成功消费规则落实为一个入口。

- **R1**：输入缓冲寿命 9 SimTick，expireTick 当 Tick 已失效。
- **R2**：持续 Move 使用最新状态，Attack/Dodge 使用有序边沿。
- **R3**：暂时窗口关闭可缓冲；终态拒绝和过期有唯一回执。

## 4. 具体执行任务

### 09.1 分开边沿与持续输入

- [ ] **做什么**：分开边沿与持续输入。
- **为什么**：把按住移动当边沿队列会造成持续追赶旧方向。
- **怎么做**：边沿按 commandId 入队一次；持续输入替换该来源最新值；焦点丢失可投递 Move=0。
- **关键伪代码**：

```text
Edge -> EnqueueOnce(commandId)
Move -> ReplaceLatest(actor, direction)
```

### 09.2 执行过期与语境解析

- [ ] **做什么**：执行过期与语境解析。
- **为什么**：缓冲期间落地、缴械或目标丢失可能改变语义。
- **怎么做**：P1 清 issuedTick+9 到期项；选中时基于当前 contextVersion 再解析，不缓存过期目标。
- **关键伪代码**：

```text
if tick >= command.expireTick: CompleteExpired(command)
resolved = Resolve(command, currentContext)
```

### 09.3 提供消费与回执契约

- [ ] **做什么**：提供消费与回执契约。
- **为什么**：动作候选失败不能吃掉预输入。
- **怎么做**：Peek 不移除；步骤 11 成功后 Consume；窗口关闭保留，重复回执有状态守卫。
- **关键伪代码**：

```text
Peek -> TryPrepareStart
if committed: Consume(commandId); EmitAccepted(actionHandle)
```

## 5. 本步完整流程伪代码

```text
P1(unit):
  expire old edge commands
  update sustained input state
  resolve valid commands against current context
  produce ordered candidates
P2(unit):
  choose candidate using graph and permissions
  on successful action commit: consume exact command
  on temporary block: retain until expiry
  on terminal rejection: remove and emit reason
```

## 6. 边界与失败处理

- 12 帧连招识别窗口不是所有输入统一延迟 12 帧。
- epoch 变化是否使旧命令失效按来源规则执行，不清除其他来源已提交结果。
