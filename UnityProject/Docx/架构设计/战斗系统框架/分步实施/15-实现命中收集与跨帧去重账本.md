## 1. 目标与需求

统一收集所有有效攻击接触，并在扣血前完成阵营、部位、攻击组与目标的稳定裁决。

- **R1**：先收集全 Tick 候选，再结算，不在查询回调直接伤害。
- **R2**：默认键为 attackInstance + hitGroup + target，账本跨有效帧保存。
- **R3**：同组碰到多个部位按 partPriority 与稳定 ID 选择一个。

## 4. 具体执行任务

### 15.1 采集候选与报告容量

- [ ] **做什么**：采集候选与报告容量。
- **为什么**：碰撞缓冲溢出会漏目标。
- **怎么做**：候选保留目标、部位、命中组和接触参数；查询容量不足明确失败，不只返回截断数量。
- **关键伪代码**：

```text
queryResult = query.Collect(context, candidates)
if queryResult.Overflow: Fault(QueryCapacity)
```

### 15.2 分组和部位选择

- [ ] **做什么**：分组和部位选择。
- **为什么**：Physics 返回顺序不能决定护甲是否生效。
- **怎么做**：按攻击组与目标聚合，过滤无效实体/阵营，再按部位优先级和稳定 ID 选择。
- **关键伪代码**：

```text
group = GroupBy(attack, hitGroup, target)
part = SelectHighestPriorityThenStableId(group)
```

### 15.3 记录去重判定

- [ ] **做什么**：记录去重判定。
- **为什么**：每 Tick 清账会让连续重叠多次扣血。
- **怎么做**：账本存至攻击结束；多段使用不同 pulse/hitGroup；被无敌挡住是否占账由规则显式配置。
- **关键伪代码**：

```text
key = {attackInstance, hitGroup, targetHandle}
if ledger.Contains(key): skip
if resolvedOutcome.ConsumesHit: ledger.Add(key)
```

## 6. 边界与失败处理

- 部位去重默认按目标，不让同一挥击同时打身体和护甲两次。
- 无敌是否消耗攻击机会必须在内容规则中明确；实现前补入基线，不能各技能自行猜测。

## 7. 完成标准与待执行检查

- [ ] A 有效帧持续重叠只产生一次命中伤害请求。
- [ ] 一个组的多个攻击框碰同目标不重复结算。
- [ ] 不同 pulse 可按配置再次命中，多部位选择稳定。
