## 1. 目标与需求

先构建可编辑源数据到运行内容的编译通路，再开发图形界面，避免编辑器 UI 直接变成运行数据。

- **R1**：Authoring DTO 与 Runtime Definition 分离。
- **R2**：Editor 代码仅留编辑器程序集，Schema 引用无循环。
- **R3**：导出具备稳定排序、版本、可定位诊断和明确的时间量化。

## 4. 具体执行任务

### 32.1 确定共享 Schema 放置

- [ ] **做什么**：确定共享 Schema 放置。
- **为什么**：Editor references 为空不能假设能直接访问 GameLogic 类型。
- **怎么做**：优先将无 Unity/业务模块依赖的 DTO 放可共用层，按真实程序集确认引用；不能让 GameProto 依赖 GameLogic。
- **关键伪代码**：

```text
Editor -> SharedSchema <- GameLogic
No cycle; No UnityEditor in Runtime
```

### 32.2 建立编译映射

- [ ] **做什么**：建立编译映射。
- **为什么**：运行时不能解析编辑器每种面板状态。
- **怎么做**：把源节点/轨道转为固定 DTO，排序和索引映射稳定；编辑选中状态不导出。
- **关键伪代码**：

```text
authoring -> Normalize -> Validate -> LowerToRuntimeDto
```

### 32.3 量化并报告错误

- [ ] **做什么**：量化并报告错误。
- **为什么**：秒转帧后零长度窗口不能默默修成一帧。
- **怎么做**：采用明确四舍五入策略，量化后再次验证区间；报告源轨道和字段。
- **关键伪代码**：

```text
frame = Floor(seconds * tickRate + 0.5)
if endFrame <= startFrame: report InvalidQuantizedWindow
```

## 5. 本步完整流程伪代码

```text
Compile(authoring):
  normalize stable identifiers
  quantize source times
  validate all runtime constraints
  if errors: return report without replacing last output
  lower to sorted DTO arrays
  compute content metadata
  return compiled package
```
