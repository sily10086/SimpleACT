## 1. 目标与需求

让敌人通过统一意图入口行动，完成感知、决策、提交一次、等待动作结果和重新评估的循环。

- **R1**：感知每 3 Tick、高层决策每 6 Tick 是演示值；紧急状态可唤醒。
- **R2**：AI Blackboard 只存目标记忆和运行游标，不另存权威 HP/CD。
- **R3**：Attack 节点等待 CommandId/ActionHandle，不每次决策重发攻击。

## 4. 具体执行任务

### 28.1 实现节点状态和最小组合

- [ ] **做什么**：实现节点状态和最小组合。
- **为什么**：Selector 内处处放 Idle 会吞掉真实失败。
- **怎么做**：定义 Success/Failure/Running；根可保底 Idle，内部组合失败向上传递；先不做通用并行。
- **关键伪代码**：

```text
Selector: return first child not Failure
Sequence: return first child not Success
```

### 28.2 接入感知与只读上下文

- [ ] **做什么**：接入感知与只读上下文。
- **为什么**：重复复制 HP/CD 会与战斗权威值失配。
- **怎么做**：距离/视线产生感知结果；目标记忆保存最近位置和过期 Tick，资源从 UnitContext 读取。
- **关键伪代码**：

```text
targetMemory = PerceiveEvery(3)
canAttack = distance<=1.5 && context.PermissionAllowsAttack
```

### 28.3 实现提交与等待

- [ ] **做什么**：实现提交与等待。
- **为什么**：6 Tick 重发攻击会堆满缓冲。
- **怎么做**：Attack 初次 Submit，Buffered 保持等待；Accepted 绑定动作句柄，终止后返回结果；取消后不恢复旧动作。
- **关键伪代码**：

```text
IdleNodeState -> SubmitOnce -> WaitReceipt -> WaitActionTerminal -> Reevaluate
```

## 5. 本步完整流程伪代码

```text
P1:
  update perception when due
  if urgent state change: wake decision
  tick behavior tree when due or waiting receipt arrives
AttackLeaf:
  if no outstanding command: SubmitAttackOnce()
  if Buffered: Running
  if Accepted(handle): wait exact handle
  if Completed: Success
  if Rejected/Expired/Cancelled: clear state; Failure
AfterHitStun:
  re-evaluate context rather than resume cancelled action
```

## 6. 边界与失败处理

- 决策挂起时保留游标不表示保留已经取消的动作句柄。
- 树 expand 深度与循环引用由步骤 35 校验；运行时仍设预算。
