# 步骤 06｜建立世界阶段与命令结果缓冲

版本：v0.1｜阶段：S1｜状态：方案已编写，实施未开始。

> 本文属于已授权的文档细化。所有新增类型、接口及路径是拟实施方案；伪代码用于表达控制流，不是可直接编译的代码。执行本步前确认该批次；完成后填写实际记录。

## 1. 目标与需求

把所有战斗系统放进固定 P0–P7 顺序，先建立空系统接口和阶段缓冲，让后续功能有明确接入位置。

- **R1**：一个 BattleWorld 是唯一逻辑驱动，不允许事件监听重入 Step。
- **R2**：未执行命令与已提交结果分开，阶段间显式传递。
- **R3**：容量不足报告 BattleFault，不静默丢弃伤害或溢出后继续半步运行。

## 4. 具体执行任务

### 06.1 搭建阶段骨架

- [ ] **做什么**：搭建阶段骨架。
- **为什么**：后续模块不应各自注册 Update。
- **怎么做**：先接空实现或具体系统占位；稳定实体顺序由注册表提供，Step 内不做异步 IO。
- **关键伪代码**：

```text
P0.Begin -> P1.Intent -> P2.Prepare -> P3.Execute -> P4.Collect -> P5.Commit -> P6.React -> P7.Publish
```

### 06.2 定义缓冲寿命与写入权限

- [ ] **做什么**：定义缓冲寿命与写入权限。
- **为什么**：清空总队列会误删已经生效的结果。
- **怎么做**：命令按 ActionHandle/epoch 可失效；结果提交后只读，P7 消费完再回收存储。
- **关键伪代码**：

```text
InvalidatePendingCommands(action)
CommittedResults remain immutable until publication completes
```

### 06.3 处理溢出与重入

- [ ] **做什么**：处理溢出与重入。
- **为什么**：中途失败不能被误报为正常完成。
- **怎么做**：容量写入显式返回失败；World 进入 Faulted 并保留诊断。本步故障不宣称支持回滚。
- **关键伪代码**：

```text
if !buffer.TryAdd(item): world.Fail(CapacityExceeded)
if stepping: reject ReentrantStep
```

## 5. 本步完整流程伪代码

```text
Step(context):
  RequireRunningAndNotStepping()
  BeginTickBuffers()
  RunP0ToP4()
  if fault: StopTickAndReportFault(); return
  RunP5Commit()
  RunP6Reactions()
  PublishP7ResultsAndSnapshots()
  AdvanceAllowedClocks()
  RecycleConsumedTransientStorage()
```

## 6. 边界与失败处理

- 若故障发生于部分提交后，停止战斗并明确报告部分提交，不能重试同 Tick 造成重复扣血。
- 事件回调提交的新命令进入下一可执行 Tick，不回到本 Tick P2。
