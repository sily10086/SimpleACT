版本：v0.1｜阶段：S2｜状态：方案已编写，实施未开始。

## 1. 目标与需求

将起手、扣费、占用、输入消费和退出组成完整生命周期，保证一次动作只有一次开始与一次终止。

- **R1**：起手预检失败时不修改旧动作、不扣费、不消费输入。
- **R2**：成功提交一次分配新 ActionHandle；取消只作废旧动作未执行命令。
- **R3**：终止结果区分 Completed 与 Cancelled(reason)，AI 可等待指定句柄。

## 4. 具体执行任务

### 11.1 完成可失败的准备段

- [ ] **做什么**：完成可失败的准备段。
- **为什么**：清掉旧动作后才发现新动作不可用会产生异常空档。
- **怎么做**：查定义、许可、费用、运行槽与必要依赖；准备段不触发外部回调。
- **关键伪代码**：

```text
prepared = PrepareStart(candidate)
if !prepared.ok: return rejection without mutation
```

### 11.2 提交起手

- [ ] **做什么**：提交起手。
- **为什么**：耐力、CD 和命令消费必须与动作真正进入一致。
- **怎么做**：所有可预见失败前置；同步提交段关闭旧动作、写费用/CD、新实例和消费；结果稍后发布。
- **关键伪代码**：

```text
CommitPrepared:
  EndOldIfNeeded(); CommitCost(); InstallNewInstance(); ConsumeInput(); QueueStarted()
```

### 11.3 统一退出与幂等清理

- [ ] **做什么**：统一退出与幂等清理。
- **为什么**：自然结束、受击、死亡和退出不能各写一套清理。
- **怎么做**：按 ActionHandle 标记终止一次；撤销来源标签、命中窗口、未执行命令；保留已经产生的弹丸与结果。
- **关键伪代码**：

```text
if runtime.IsTerminal: return
InvalidatePending(action); RevokeOwnedTags(action); CloseWindows(action)
EmitTerminalReceiptOnce(action, reason)
```

## 5. 本步完整流程伪代码

```text
TryStart(candidate):
  plan = PrepareAllDependencies(candidate)
  if plan.failed: return Rejected(plan.reason)
  // no callbacks or awaits inside the following commit
  EndOldActionIfReplacing()
  ResourceOwner.Commit(plan.cost)
  action = AllocateAndInstall(plan.definition, frame=0)
  input.Consume(plan.commandId)
  QueueResult(ActionStarted(action))
Cancel(handle, reason):
  if current exact handle matches and not terminal:
    CloseOwnedRuntimeResources()
    MarkCancelledAndQueueResult()
```
