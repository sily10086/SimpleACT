## 1. 目标与需求

让连招由节点、出边、条件和窗口驱动，运行器只管理当前节点及必要游标。

- **R1**：nodeId 与 actionId 分离，同动作可在多个节点复用。
- **R2**：稳定顺序选择出边；首版只支持单主动作通道。
- **R3**：限制同 Tick 零时间迁移数量，禁止零时环无限求值。

## 4. 具体执行任务

### 13.1 实现出边选择

- [ ] **做什么**：实现出边选择。
- **为什么**：遍历字典顺序不能决定技能优先级。
- **怎么做**：按显式 priority 和 edgeId 排序；条件只读取快照，不在条件中扣费。
- **关键伪代码**：

```text
candidates = outgoingEdges.OrderBy(priority, edgeId)
choose first whose window, semantic and predicates match
```

### 13.2 连接事务起手

- [ ] **做什么**：连接事务起手。
- **为什么**：选中边不等于下一招已开始。
- **怎么做**：调用步骤 11，成功才推进 nodeId；失败保留原节点，根据拒绝原因决定是否留缓冲。
- **关键伪代码**：

```text
receipt = actions.TryStart(edge.action)
if receipt.Accepted: currentNode = edge.targetNode
```

### 13.3 设置终止和环策略

- [ ] **做什么**：设置终止和环策略。
- **为什么**：动作图允许循环，不代表可以无预算执行。
- **怎么做**：自然结束默认边与输入边有明确顺序；零时迁移计数达到预算报配置错误。
- **关键伪代码**：

```text
while instantTransitionAvailable:
  if ++count > budget: Fault(GraphTransitionBudget)
  ApplyOneTransition()
```

## 5. 本步完整流程伪代码

```text
P2(unit):

```

## 6. 边界与失败处理

- “攻击A→B”的窗口读取当前 Tick 的 ActionFrame，不能使用上一渲染帧缓存。
- 一般行为树的 Running/Success 语义不强套到动作图中。
