## 1. 目标与需求

明确每个配置和表现资源由谁加载、持有、回收，接入已有对象池而不重复实现。

- **R1**：对象池负责复用，资源服务负责加载，二者拥有关系明确。
- **R2**：配置异步加载，必要资源就绪后才能开始。
- **R3**：每个实例只回池一次，晚到资源仍释放。

## 4. 具体执行任务

### 22.1 建立资源清单与租约

- [ ] **做什么**：建立资源清单与租约。
- **为什么**：仅保存资源 ID 无法知道何时卸载。
- **怎么做**：每次获取记录拥有者与释放动作；配置解析完成后可释放原始 TextAsset，表现资源保持到解绑结束。
- **关键伪代码**：

```text
lease = await Acquire(resourceId)
scope.Track(lease, owner)
```

### 22.2 使用当前池接口

- [ ] **做什么**：使用当前池接口。
- **为什么**：现有池不自动从地址加载 Prefab。
- **怎么做**：首版使用已配置 Prefab 池，等待预热；TrySpawn 成功后记录实例，失败返回准备错误。
- **关键伪代码**：

```text
ok = pool.TrySpawn(poolName, position, rotation, parent, out instance)
if ok: sessionInstances.Add(instance)
```

### 22.3 区分回池和卸载

- [ ] **做什么**：区分回池和卸载。
- **为什么**：先卸载资产再回收仍使用它的视图会破坏生命周期。
- **怎么做**：先 Unbind/Despawn 再释放本场资源；不 Shutdown 全局池，动态池提供者另案。
- **关键伪代码**：

```text
UnbindViews -> DespawnOwnedInstances -> ReleaseOwnedLeases
```

## 5. 本步完整流程伪代码

```text
PrepareAsync(manifest):
  acquire content leases
  compile snapshot
  release parsed raw content leases
  ensure required view resources and configured pools ready
  return PreparedResources
SpawnView:
  TrySpawn from known pool
  record exact ownership
Release:
  reclaim all session instances once
  release remaining owned resources
```

## 6. 边界与失败处理

- 取消等待并不保证底层加载不会完成；完成回调仍检查 session token 并释放。
- 不直接把 LoadAssetAsync<GameObject>+Instantiate 当作项目既定加载路径。
