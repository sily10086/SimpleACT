## 1. 目标与需求

让策划维护动作节点、派生边和 AI 定义/实例，保持编辑画布与运行语义分离。

- **R1**：先完成列表/表格方式，节点画布按真实编辑需求选型。
- **R2**：动作图和 AI 树使用不同运行语义，不共用万能节点基类。
- **R3**：节点 ID、动作引用、条件引用和 expand 关系可视化定位。

## 4. 具体执行任务

### 34.1 先制作可用的结构编辑

- [ ] **做什么**：先制作可用的结构编辑。
- **为什么**：引入画布不能替代领域约束。
- **怎么做**：列表支持增删节点、编辑边 priority、窗口引用和目标；所有修改保持稳定 ID。
- **关键伪代码**：

```text
EditEdge(source,target,windowId,priority,condition)
```

### 34.2 区分定义表和实例树

- [ ] **做什么**：区分定义表和实例树。
- **为什么**：节点类型表不应存每棵树的运行游标。
- **怎么做**：定义类型限制参数 Schema，实例记录 nodeId/typeId/children；运行状态不持久写入。
- **关键伪代码**：

```text
TypeDefinition(schema) + NodeInstance(values,children) -> CompiledNode
```

### 34.3 封装可选画布

- [ ] **做什么**：封装可选画布。
- **为什么**：xNode/NodeGraphProcessor 不应成为运行时依赖。
- **怎么做**：只在需要时经评估引入 Editor 画布；转换层导出自有扁平 Schema。
- **关键伪代码**：

```text
CanvasGraph -> AuthoringDTO -> OwnRuntimeGraph
```

## 5. 本步完整流程伪代码

```text
EditGraph:
  select node or edge
  edit stable IDs, references and conditions
  validate locally
EditAI:
  choose registered node type
  edit schema-constrained parameters and children
Compile:
  validate graph semantics separately from AI semantics
  flatten to own runtime DTO
```
