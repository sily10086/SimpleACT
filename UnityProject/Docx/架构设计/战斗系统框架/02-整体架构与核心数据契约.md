# 整体架构与核心数据契约

日期：2026-10-25；v0.1。本文类型均为拟新增设计，除明确标注的 TEngine API 外，项目当前没有这些实现。

## 1. 分层与职责

| 层/对象 | 唯一责任 | 可调用 | 不得承担 |
|---|---|---|---|
| BattleModule | 一场战斗的创建、加载、开始、停止和释放 | Resource、Pool、World、输入桥、结果桥 | 每个技能的详细规则 |
| BattleWorld | 固定 Tick 顺序、单位与实例生命周期、结果提交 | 各战斗子系统 | 异步 IO、直接控制 UI |
| UnitRuntime | 单位权威状态、属性、CD、动作句柄、运动状态 | 所属系统内部操作 | 自己挂 Update、自行发伤害 |
| UnitStateSystem | 许可、迁移和强制反应 | 只读规则、单位状态、取消服务 | 按键识别、伤害公式 |
| ActionGraphRunner | 选择与切换动作节点 | 意图、窗口、条件快照 | 直接扣血或写 Transform |
| ActionTimeline | 执行动作时间轴，输出逻辑命令与表现请求 | 不可变动作数据 | 决定整场 AI 战术 |
| Motor / HitResolver / EffectSystem | 分别拥有位移、命中裁决、效果与数值提交 | 显式数据输入 | 靠全局事件顺序决定权威结果 |
| PresentationBridge / UnitView | 根据结果与快照播放动画/音效/特效 | GameModule 对应基础服务 | 反向决定命中、无敌、死亡 |
| Authoring / Compiler | 制作、引用检查、导出和迁移 | 编辑器资产与 schema | 把 Editor 类型带进运行时 |

首版只增加一个战斗业务模块，不为每个系统添加全局单例。后续若实现 SimpleACT 的 RunModule，由 RunModule 持有同一个 BattleWorld，**不得另建第二个战斗时钟和单位集合**。

## 2. 权威来源

| 数据 | 写入方 | 读取方 |
|---|---|---|
| HP、耐力、护盾、属性修饰器 | EffectSystem 的提交阶段 | FSM、AI、UI 快照 |
| 死亡/硬直/位移控制状态 | UnitStateSystem | 动作图、Motor、AI |
| 位置、速度、朝向、接地 | MotorSystem | 碰撞、语境、表现 |
| 当前动作、局部帧、命中集合 | ActionSystem | HitResolver、View |
| 冷却结束 Tick、技能占用 | AbilityRuntime | 输入校验、AI |
| 目标记忆、最后已知位置、决策游标 | AI Runtime | AI 决策 |
| 配置定义 | 开局构造后不可变 | 全系统共享只读 |
| 窗口许可 | 当前动作时间轴派生，叠加状态/Buff 限制 | FSM、动作图、HitResolver |

ContextSnapshot 是某一阶段的只读事实集合；Blackboard 不再复制并拥有 HP/CD。状态标签允许组合，例如“水中+缴械”，不为组合枚举数十个状态。关键互斥状态用 FSM，正交能力限制用带来源和计数的 TagSet。

## 3. 最小数据契约

| 类型 | 核心字段 | 约束 |
|---|---|---|
| EntityHandle | battleId、entityId、generation | 池对象复用不复用逻辑身份 |
| ActionDefinition | stableId、version、duration、windows、commands、viewTracks | 不存单位当前帧和命中列表 |
| ActionRuntime | instanceId、owner、definitionIndex、nodeId、localFrame、epoch、status | 每次重放同动作产生新 instanceId |
| IntentCommand | sequence、actor、primitive、参数、issuedTick、expireTick、epoch | 不能携带 GameObject 或任意 object[] |
| ResolvedIntent | commandId、semanticId、contextVersion、sourcePrimitive | 消费前确认当前许可与语境仍有效 |
| TransitionRequest | actor、source、target、reason、priority、issuedTick、epoch | 不直接调用 View.Play |
| HitCandidate | attackHandle、hitGroup、target、partId、contactTime、hitboxId | 原始几何结果，不等于有效伤害 |
| DamageRequest | source、target、damageDefId、partId、attackId、倍率快照 | 公式输入来源可追踪 |
| CombatResult | battleId、tick、sequence、source、target、actionId、结果数据 | 提交后不可变；不因来源后来死亡而删除 |
| PresentationRequest | resultId、entityHandle、viewChannel、资源ID、参数 | 结果绑定代次，旧异步结果不能写新对象 |

持久 stableId 使用作者可读字符串或 GUID；导出时构造稳定映射，运行时使用紧凑索引。索引不是持久身份，不能写回存档后期待下个版本仍有效。自定义 int hash 必须有碰撞检查，不能直接把 GetHashCode 当跨版本持久 ID。

## 4. 关键 API 草案

```csharp
// 仅为契约草案，未加入项目，也不是可直接编译的完整代码。
public interface IBattleSession
{
    /// <summary>投递命令；只排队，不在调用栈中修改战斗。</summary>
    CommandSubmitResult Submit(in IntentCommand command);
    /// <summary>完成一个固定逻辑步，返回本步已提交结果的只读视图。</summary>
    BattleStepResult Step(in TickContext context);
    /// <summary>停止接收命令并结束会话；重复结束不重复结算。</summary>
    void Stop(BattleStopReason reason);
}

public interface ICombatQuery
{
    /// <summary>收集本步几何接触；缓冲不足必须报告，不静默截断。</summary>
    QueryResult Collect(in QueryContext context, HitCandidateBuffer output);
}

public interface IActionPresentation
{
    /// <summary>按只读快照采样表现，不发起逻辑命中。</summary>
    void Sample(in ActionViewSnapshot snapshot);
    /// <summary>解除该单位本代次占用的表现资源。</summary>
    void Release(in EntityHandle entity);
}
```

仅在输入源、碰撞后端、表现后端、规则集等真实可替换处设接口。内部的 TimelineCursor、HitLedger 等直接使用具体类型。

## 5. 一次动作的事务边界

```text
TryStartAction(intent):
  找到候选边和动作定义
  检查单位许可、语境、资源、CD与动作占用
  如果失败：返回明确拒绝原因，不消费输入、不扣资源
  在同一提交点：扣资源 + 设CD + 创建ActionInstance + 消费commandId
  退出旧动作并关闭其逻辑命令来源
  进入新动作 localFrame=0，登记第0帧命令
  记录 ActionStarted 结果
```

资源扣除和 CD 开始默认在动作成功进入时。退款为显式规则，不靠播放失败自动猜测。权威资源不应到表现加载完成后才扣除；必要表现资源应在开始前就绪。

## 6. 生命周期

`Created → Loading → Ready → Running → Stopping → Disposed`。BattleId 每场不同；Stop 先禁止输入和步进，再取消该场异步任务、解绑桥、归还 View、释放资源。任何异步完成都检查 BattleId 和 generation；过期资源仍需归还，不能只 return。
