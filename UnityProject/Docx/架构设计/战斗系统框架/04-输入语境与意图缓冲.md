# 输入、语境与意图缓冲

日期：2026-10-25；v0.1。对应原文 07/12/13。

## 1. 设计目的与边界

玩家、AI、回放输入都表达“想做什么”，不直接调用动画或修改 HP。共享消费链不代表玩家与 AI 的按键识别、决策频率和反应延迟相同。

`设备采集 → BindingProfile → IntentPrimitive → IntentResolver → IntentBuffer → UnitFSM许可 → ActionGraph`。AI 从 IntentPrimitive 接入；回放从已经分配 Tick 的命令接入。

## 2. 数据

| 数据 | 字段/内容 | 所有者 |
|---|---|---|
| RawInputEdge | device、control、down/up、采集序号 | 输入适配器 |
| BindingDefinition | bindingId、组合、触发方式、映射原语、冲突优先级 | 配置 |
| PrimitiveCommand | actor、sequence、原语、方向/目标参数、tick、epoch | 单位命令队列 |
| ContextSnapshot | 接地、水中、目标句柄、相对方位、可用资源快照 | World 每阶段构建 |
| ResolveRule | 原语、所需/禁止标签、semanticId、priority | 规则配置 |
| IntentBufferEntry | 原始命令、语义缓存、expireTick、contextVersion | 每单位 |

环境事实由 Motor、感知、状态系统提供，不能再塞入两份独立 Intent.params 并与黑板各自更新。方向、玩家选定目标等“请求参数”与事实有区别，应保留在命令中。

## 3. 两种缓冲及确定规则

- 组合键窗口：原文 12 帧只是示例。若普通攻击等待满 12 帧再响应，会增加约 200ms 延迟。首版推荐修饰键按住+攻击边沿立即触发；只有明确允许宽松顺序组合的绑定才延迟仲裁。
- 动作预输入：默认 9 个 SimTick，`expireTick=issuedTick+9`，有效区间 `[issuedTick,expireTick)`；到期后不能再消费。暂停不增加 SimTick；局部时停时默认仍过期，避免长时间冻结后突然出招。若产品希望时停保留输入，需显式改用 OwnerUnit 时间域。
- Move/瞄准为持续量，采用最新状态；Attack/Jump 为边沿命令。不能把每帧保持攻击自动视为新的攻击，自动连发另设重复策略。

## 4. 选择、重解与消费

```text
PeekCandidate(actor):
  去掉已过期、旧epoch、非法目标的命令
  按priority、issuedTick、sequence确定次序
  若contextVersion改变，用当前快照重新解析原语
  检查UnitFSM许可
  检查动作边窗口、资源和CD
  返回可提交候选（不在查询时消费）

CommitAction(candidate):
  扣费、占用和CD提交成功
  将该commandId标为Consumed
```

原文“Resolver 无匹配吞输入”可保留，但必须输出拒绝原因供调试；不能因碰撞后当前状态变化，把已经拒绝的旧命令复活。语境变化重解仅针对仍在缓冲且尚未拒绝/消费的命令。

例如地面 Jump 在空中等待取消窗口：推荐在消费时按当前环境重解，避免落水后仍执行地面跳。目标失效返回 TargetLost，不自动换成任意新目标。

## 5. 状态迁移和控制失效

死亡、硬直、入水等重大迁移使 actionEpoch 增加，旧缓冲失效。缴械等权限标签变化立即影响 Attack，但是否取消已经开始的动作由 effect.cancelCurrentAction 指定。不要仅因标签任意改变就把所有移动输入清空。

设备切换清设备级组合/长按状态；窗口失焦清按住状态，恢复要求新的按下，防止按键粘住。UI 打开时输入路由切到 UI Context，战斗桥不接受同一按钮的重复事件。

## 6. 项目落点与未来验收

拟新增 `Core/Battle/Input/` 的 IntentResolver、IntentBuffer、InputRuleCompiler；`Module/BattleModule/Adapters/` 放旧 Input 适配器。当前项目 activeInputHandler=0，manifest 未列 Input System；首版不为演示强制迁移输入包。之后采用 Input System 时只替换设备适配器和绑定层。

参考 [Unity InputSystem](https://github.com/Unity-Technologies/InputSystem) 的动作、绑定、重绑定与 UI/游戏输入分流；不要把包自带秒制交互直接作为战斗窗口时钟。
