# M12 Buff与持续效果：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

管理持续状态从施加、叠层、刷新、周期触发到移除的完整生命周期。

**负责的内容**：BuffDefinition/Runtime、聚合键、持续时间域、层数、周期、驱散/死亡移除、来源贡献。

**边界**：不直接修改属性字段或标签底层集合；通过 M03/M05 端口登记贡献，伤害经 M11。

## 2. 原设计分析与需要完善的地方

- 原文没有完整 Buff 方案，这是战斗框架需要补齐的能力。
- 刷新是否重置周期、多个来源同标签怎么移除、到期边界是否再跳一次都必须明确。

## 3. 完善后的设计

Buff 实例拥有唯一 sourceToken。Apply 安装自己的属性/标签贡献，Refresh 按策略调整到期而不重复安装，RemoveOnce 只撤销自己贡献。OwnerUnit/SimTick 明确区分；P0 到期先于周期触发，P5 新 Buff 不回溯影响已有快照。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| BuffRuntime | instance、source、stacks、expire、nextPeriod、clock。 |
| ContributionTokens | 本 Buff 添加的 modifier/tag 引用。 |
| BuffDefinition | 聚合/叠层/周期/死亡规则只读。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `ApplyOrRefresh(request)` | 效果提交时调用，返回施加/刷新结果。 |
| `CollectDueEffects(clockContext)` | 产生周期请求，交 M11。 |
| `Remove(instance, reason)` | 一次性撤销贡献并发布移除事实。 |

**依赖关系**：读取 M01 时间，使用 M03 修饰和 M05 标签端口；M11 发施加请求并接收周期效果。

**如何单独制作**：人工递增 UnitTick，属性/标签使用来源计数替身；可以独立制作刷新、叠层与到期。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M12.1 制作定义与实例

- [ ] **目标与需求**：同定义多来源有明确聚合策略。
- **涉及内容与做法**：定义 Refresh/AddStack/Independent/Reject 和时域，实例不放 ScriptableObject 共享状态。
- **关键伪代码**：

```text
key=ResolveStackKey(def,source,target)
FindExistingOrCreate(key)
```

### M12.2 制作周期和刷新

- [ ] **目标与需求**：连续刷新不能让 DOT 永远不触发。
- **涉及内容与做法**：演示 Refresh 保留 nextPeriod，仅更新 expire；到期边界先移除。
- **关键伪代码**：

```text
if now>=expire: RemoveOnce()
else if now>=nextPeriod: QueueEffect(); nextPeriod+=period
```

### M12.3 制作贡献撤销

- [ ] **目标与需求**：移除一个 Buff 不清掉其他来源。
- **涉及内容与做法**：Modifier/Tag 都带实例 sourceToken，死亡/驱散调用同一 Remove。
- **关键伪代码**：

```text
Remove -> Attributes.RemoveSource(token)
       -> Tags.RevokeSource(token)
```
