# M21 内容编译校验与发布：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

把策划编辑源转换为可安全加载、版本一致的运行内容，并将其纳入项目已有资源发布流程。

**负责的内容**：Authoring→Runtime 编译、时间量化、ID/引用/图约束、能力校验、manifest、原子导出与发布清单。

**边界**：不负责编辑交互，不在战斗中修改正在使用的快照，不另造资源热更框架。

## 2. 原设计分析与需要完善的地方

- 原文 JSON/UAnim 需要导出规范和版本迁移才能成为可靠管线。
- 节点图允许跨 Tick 环，不应简单禁止所有环；零时环/AI expand 递归需要不同检查。

## 3. 完善后的设计

Normalize→Quantize→Validate→Lower→Manifest。错误阻断并保留旧输出；warning 有明确定义。DTO 共用层需避免 GameProto→GameLogic 反向依赖。导出结构按 stableId 稳定排序，资源清单纳入现有 YooAsset 流程。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| CompileReport | severity、asset/node/track/field、原因。 |
| CompiledPackage | 表、图、时间轴的成套版本。 |
| Manifest | schema/mechanism/features/hash/resource引用。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `Compile(authoring, targetCapabilities)` | 返回候选产物或诊断，不半覆盖。 |
| `ValidateAll(contentSet)` | 结构+跨文件+时间+图+能力检查。 |
| `BuildManifest(compiled, resources)` | 生成供 M18 选择的版本清单。 |

**依赖关系**：读取 M19/M20 源数据、M03/M07/M08/M12 等领域 Schema；产物只交 M18 运行加载。

**如何单独制作**：以手写小 DTO 内容集就可制作编译校验，不等待图形编辑器完成。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M21.1 制作共享 Schema 和编译映射

- [ ] **目标与需求**：Editor 类型不得进入运行程序集。
- **涉及内容与做法**：确认实际 asmdef 依赖，将纯 DTO 放可引用层，去除 UI 编辑状态。
- **关键伪代码**：

```text
AuthoringDTO -> RuntimeDTO
No UnityEditor reference in Runtime
```

### M21.2 制作领域校验

- [ ] **目标与需求**：坏数据在进入战斗前被阻断。
- **涉及内容与做法**：ID重复、缺引用、越界窗口、零时环、expand深度8与递归、能力不符分别定位。
- **关键伪代码**：

```text
errors=ValidateAll()
if errors: KeepPreviousOutput(); return report
```

### M21.3 制作清单与原子发布候选

- [ ] **目标与需求**：内容与资源成套交付。
- **涉及内容与做法**：先产生候选再替换本地产物，接现有构建流程；真正对外发布按明确批次执行。
- **关键伪代码**：

```text
CompileAll -> BuildManifest -> ExistingResourcePipeline
```

下列路径相对 `UnityProject/Assets/GameScripts/HotFix/`；另标资源/文档路径的除外。所有新增路径均为方案。

- `GameEditor/GameEditor.asmdef（按实际 Schema 引用调整）`

**独立交付物**：可无 UI 调用的编译器、可定位报告和版本清单。

## 7. 一个具体例子与完成标准

0.004秒窗口量化到60Hz后为零长，导出报错并定位轨道；不能偷偷修成一帧改变策划意图。

- [ ] 错误不覆盖上一有效产物。
- [ ] 相同源内容稳定导出。
- [ ] 运行时只能装载兼容的成套快照。

这些是未来完成标准，本次没有运行检查；只有实际完成实现后才勾选。
