# M15 AI感知与行为决策：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

决定敌人何时移动、攻击、等待或重新选目标，并通过与玩家相同的行动规则执行。

**负责的内容**：感知、目标记忆、AI 定义/实例、最小行为树、决策频率、命令与动作回执等待。

**边界**：不绕过状态许可/取消窗口，不复制 HP/CD 权威数据，不把动作图当 AI 树。

## 2. 原设计分析与需要完善的地方

- 原文 AI 定义表/实例表有复用价值，但 Blackboard 持有资源、AI 无窗口会破坏统一战斗规则。
- 挂起 AI 保留游标不等于已取消动作可以继续，必须用精确回执管理。

## 3. 完善后的设计

AI 只读 UnitContext，Blackboard 保存目标记忆和运行游标。感知/决策可不同频率，演示3/6 Tick。Attack 节点 SubmitOnce，等待 Buffered→Accepted(ActionHandle)→Completed/Cancelled，终止后重评估。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| PerceptionSnapshot / TargetMemory | 目标及最后位置、记忆过期。 |
| NodeRuntime | 状态、子游标、待命令/动作句柄。 |
| AIDefinition | 节点类型 Schema 与实例树，不含运行状态。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `UpdatePerception(context)` | 产生只读感知。 |
| `Decide(context, receipts)` | 输出意图，不直接执行动作。 |
| `Suspend/Resume(reason)` | 清理失效等待并按当前语境恢复。 |

**依赖关系**：读取 M02/M03/M05 的只读事实，用 M09 查询；向 M04 Submit，等待 M06 终止回执。

**如何单独制作**：用固定目标距离和手工回执驱动树，可制作 Selector/Sequence/Attack；不需要完整敌人 Prefab。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M15.1 制作最小节点与类型表

- [ ] **目标与需求**：先让职责和结果语义准确。
- **涉及内容与做法**：Selector/Sequence/Condition/Move/Attack/Idle，内部失败向上传递；根保底可 Idle。
- **关键伪代码**：

```text
Selector -> first non-Failure
Sequence -> first non-Success
```

### M15.2 制作感知与降频

- [ ] **目标与需求**：没有必要每渲染帧全树求值。
- **涉及内容与做法**：使用独立 dueTick，关键状态变化可唤醒；不把资源写回黑板。
- **关键伪代码**：

```text
if perceptionDue: Update()
if decisionDue || urgentWake: TickTree()
```

### M15.3 制作动作回执任务

- [ ] **目标与需求**：避免每6Tick重复排攻击。
- **涉及内容与做法**：节点保存自己的 CommandId/ActionHandle，取消后清等待并重评估。
- **关键伪代码**：

```text
SubmitOnce -> WaitReceipt -> WaitExactActionTerminal -> Reevaluate
```

## 7. 一个具体例子与完成标准

敌人在距离1.5内提交一次攻击，即使决策轮询多次也不再提交；受击取消后硬直结束重新选择行动。

- [ ] 不绕过玩家同样的动作规则。
- [ ] 没有重复命令和失效句柄等待。
- [ ] AI 树与动作图的节点/运行态独立。

这些是未来完成标准，本次没有运行检查；只有实际完成实现后才勾选。
