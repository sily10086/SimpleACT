# M22 运行诊断与回放记录：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

让每次拒绝、取消和命中都能追溯，并为后续模块检查提供输入、预期与真实运行证据。

**负责的内容**：有界 trace、命令/动作/命中/结果关联、版本头、快照/随机记录契约、查看器、模块检查记录。

**边界**：不默认宣称跨平台确定性，不让诊断读取改变执行顺序，不自动开启无限磁盘日志。

## 2. 原设计分析与需要完善的地方

- 原文回放与零 GC 等目标缺少证明路径。
- 只记录结果能播放演出，不能验证命令重算一致；需要区分记录等级。

## 3. 完善后的设计

记录 CommandId→ActionHandle→HitGroup→ResultId 链，加 Tick/Phase/内容版本。开发模式有界缓冲，按请求导出副本；只读查看器过滤。命令重演需要初始状态、RNG、实体顺序和后端一致，跨平台/联网另立专项。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| TraceEntry | tick/phase/actor/command/action/result/reason。 |
| TraceHeader | 内容与机制版本、初始状态标识、随机状态。 |
| CheckRecord | 模块、场景、预期、实际、环境、证据和未执行状态。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `Record(entry)` | 显式诊断调用，受容量与启用开关控制。 |
| `ExportSnapshot()` | 导出拥有的数据副本。 |
| `Inspect(filter)` | 编辑器/开发查看器只读过滤。 |

**依赖关系**：观察 M01/M04/M06/M10/M11 等事实，不能成为它们逻辑必须等待的服务；M21 提供版本信息。

**如何单独制作**：使用人工 trace 制作关联查看器；核心模块可注入空 recorder 完全独立运行。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M22.1 制作记录契约与预算

- [ ] **目标与需求**：诊断有用且不无界增长。
- **涉及内容与做法**：定义关键事件和容量策略，记录被覆盖范围；不在热路径格式化大量字符串。
- **关键伪代码**：

```text
if enabled: buffer.AppendBounded(valueEntry)
```

### M22.2 制作关联查看器

- [ ] **目标与需求**：从现象定位到具体规则拒绝。
- **涉及内容与做法**：按实体/动作/命令过滤，展示阶段链和原因，不修改当前 World。
- **关键伪代码**：

```text
TraceByCommand(id) -> transitions -> hits -> results
```

### M22.3 制作分模块证据模板

- [ ] **目标与需求**：每个模块能独立说明是否完成。
- **涉及内容与做法**：按模块场景记录 Given/When/Expected/Actual；未要求检查不运行，未运行不写通过。
- **关键伪代码**：

```text
record={module,case,expected,actual:null,status:NotRun}
```
