# M09 移动控制与空间查询：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

统一计算单位真实位置、朝向和阻挡，为所有命中提供可信的运动前后几何。

**负责的内容**：Motor、自由/动作/强制位移请求、朝向/接地、阻挡裁剪、几何查询适配。

**边界**：不做伤害、不把 View Transform 当逻辑事实；RootMotion 只能提交位移请求。

## 2. 原设计分析与需要完善的地方

- 原文提到位置纠正与动画位移，但多个系统写位置的冲突需要明确。
- 固定帧不自动保证 Physics2D/浮点跨平台一致，后端必须按需求选择。

## 3. 完善后的设计

Motor 是唯一位置写者。输入、时间轴、受击反应只生成 MotionRequest，经许可和优先级仲裁后扫掠阻挡，一次提交前后姿态。几何适配为真实可替换接口，首版显式查询。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| MotionState | position、velocity、facing、grounded，唯一写入。 |
| MotionRequest | 来源、策略、delta、优先级和时间域。 |
| PoseInterval | 上一/当前姿态供攻击扫掠。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `SubmitMotion(request)` | 收集请求不立即改 Transform。 |
| `Advance(context, geometry)` | P3 仲裁、查询、提交姿态。 |
| `ReadPoseInterval(actor)` | 向命中/表现提供只读区间。 |

**依赖关系**：读取 M04 持续方向、M08 动作位移、M05 强制反应与 M01 冻结；M10 通过几何端口查询。

**如何单独制作**：先用无障碍平面/固定墙的查询替身制作，位置用纯值记录，不需要场景。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M09.1 制作位移请求与拥有权

- [ ] **目标与需求**：移动、闪避、击退不能各写位置。
- **涉及内容与做法**：明确强制位移/动作/自由移动的允许与优先级。
- **关键伪代码**：

```text
desired=Arbitrate(forced,action,locomotion,permissions)
```

### M09.2 制作扫掠和姿态提交

- [ ] **目标与需求**：高速运动要保留经过路径。
- **涉及内容与做法**：保存 prevPose，阻挡裁剪 desired 后写 currentPose。
- **关键伪代码**：

```text
delta=geometry.SweepAndClip(prev,desired)
CommitPose(prev+delta)
```

### M09.3 制作真实查询适配

- [ ] **目标与需求**：保持核心不依赖 Unity 帧回调。
- **涉及内容与做法**：后端明确定义层过滤/同步时点；View 后续只插值。
- **关键伪代码**：

```text
QueryExplicitlyAtP3()
Render = Lerp(prev,current,alpha)
```

## 7. 一个具体例子与完成标准

闪避撞墙后位移被裁剪，18帧动作仍继续；不会因为没有移动距离而永远停在闪避第3帧。

- [ ] 每 Tick 只由 Motor 提交位置。
- [ ] 撞墙和时停不破坏动作时域。
- [ ] 查询使用逻辑姿态而非滞后表现。
