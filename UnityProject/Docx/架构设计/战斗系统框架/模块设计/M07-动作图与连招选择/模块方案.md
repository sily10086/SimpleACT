# M07 动作图与连招选择：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

根据当前招式、输入、窗口和上下文选择下一招，表达连招派生和自动转移。

**负责的内容**：图节点与出边、条件/优先级、连招选择、默认出口、合法循环、迁移预算。

**边界**：不持有动作资源事务、不执行攻击帧、不做 AI 战术决策；图编辑画布属于 M20。

## 2. 原设计分析与需要完善的地方

- 原文 ABT 混合动画与行为树术语，容易误用标准 AI 树执行器。
- “只存当前节点即可零成本循环”忽略子图栈、Decorator 状态与零时间环。

## 3. 完善后的设计

采用自有 ActionGraph，NodeId 引用 ActionDefinitionId；条件纯查询。边按显式优先级/稳定 ID 排序，随机仅发生在声明权重组。M06 接受后才迁移节点；HitConfirmed 默认下一 Tick 读取。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| GraphDefinition | 只读 nodes/edges/conditions。 |
| GraphRuntime | 当前节点、必要调用栈、迁移次数；按单位实例隔离。 |
| EdgeCandidate | 窗口/触发/条件匹配的选择结果。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `SelectNext(context, intents, windows)` | 产生候选，零候选不隐式取消。 |
| `OnStartAccepted(nodeId, handle)` | 与真实动作进入同步节点。 |
| `OnActionEnded(receipt)` | 处理完成/出口候选。 |

**依赖关系**：读取 M04 意图、M05 许可、M08 只读窗口；发候选到 M06，不直接写其 Runtime。

**如何单独制作**：手工定义 A/B/闪避图，用假的窗口上下文和起手回执，即可制作边选择。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M07.1 制作图模型

- [ ] **目标与需求**：节点与动作定义独立复用。
- **涉及内容与做法**：Entry/Action/Selector/Exit 与稳定边；条件引用有类型。
- **关键伪代码**：

```text
node={nodeId,actionId}; edge={trigger,window,priority,target}
```

### M07.2 制作选择与提交协作

- [ ] **目标与需求**：选中边不代表起手成功。
- **涉及内容与做法**：优先级排序后请求 M06，失败保留原节点及合规缓冲。
- **关键伪代码**：

```text
candidate = FirstEligibleEdge()
if StartAccepted(candidate): currentNode=candidate.target
```

### M07.3 制作环与派生边界

- [ ] **目标与需求**：合法跨 Tick 连招环不能被全禁。
- **涉及内容与做法**：导出拒零时环，运行预算兜底；HitConfirmed 使用已提交事实。
- **关键伪代码**：

```text
if instantTransitions>budget: Fault(path)
ReadCommittedHitFactsFromPreviousTick()
```
