# M02 单位实体与身份管理：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

回答“战斗中有哪些单位、这份数据属于哪个单位、它是否仍然有效”，提供逻辑实体身份和运行数据容器。

**负责的内容**：EntityHandle、UnitRegistry、生成/移除、代次、稳定遍历、领域运行槽。

**边界**：不决定 HP 如何计算、不驱动 AI、不持有 Unity View；各字段的内容写入交给领域模块。

## 2. 原设计分析与需要完善的地方

- 原文列出单位结构，但没有完整解释对象池复用、旧回调和会话切换后的身份失效。
- 共享配置与单位当前状态必须分离，否则多个角色会共享当前帧或命中记录。

## 3. 完善后的设计

EntityHandle=(battleId,entityId,generation)，完整匹配才可解析。UnitRuntime 组装属性、状态、动作等运行槽；定义快照共享只读。出生/移除由阶段队列应用，死亡与移除是两件事。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| EntityHandle / Registry | 本模块唯一分配和移除。 |
| UnitRuntime 槽集合 | 持有各领域状态；具体字段由所属模块写入。 |
| 生命周期队列 | 避免遍历中直接修改实体集合。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `Spawn(definitionId, spawnPose)` | 在指定边界建立单位并返回句柄。 |
| `Resolve(handle)` | 完整身份匹配，返回运行访问结果或 StaleEntity。 |
| `QueueRemove(handle, reason)` | 记录移除请求，阶段边界执行。 |

**依赖关系**：读取 M18 的单位定义；M01 驱动生命周期阶段；其他模块按句柄访问所需数据，不遍历场景找角色。

**如何单独制作**：用两个相同定义创建单位、模拟移除和复用即可制作，无需属性公式和 View。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M02.1 定义身份值类型

- [ ] **目标与需求**：跨会话和跨代次不可误识别。
- **涉及内容与做法**：用只读字段与完整比较，定义无效值和编号分配规则。
- **关键伪代码**：

```text
Resolve(h): match battleId && id && generation
```

### M02.2 建立注册表与稳定遍历

- [ ] **目标与需求**：单位数量变化不打断结算。
- **涉及内容与做法**：生命周期请求排队；提供稳定 entityId 顺序和只读枚举。
- **关键伪代码**：

```text
P0.ApplyQueuedLifecycle()
units = StableIterationView()
```

### M02.3 建立领域槽与清理

- [ ] **目标与需求**：每个实体拥有独立运行态。
- **涉及内容与做法**：初始化各槽，销毁时通知拥有模块释放，不能复制可变集合引用。
- **关键伪代码**：

```text
unit = new Runtime(sharedDefinition, freshOwnedSlots)
Remove -> ReleaseSlots -> InvalidateHandle
```

## 7. 一个具体例子与完成标准

View 被池复用后新角色即使使用同一个 GameObject，也有新句柄。旧攻击回调携带旧 generation，会被拒绝。

- [ ] 两单位不共享可变运行数据。
- [ ] 旧句柄不能解析新单位。
- [ ] 死亡当 Tick 不因集合改变漏结算其他单位。

这些是未来完成标准，本次没有运行检查；只有实际完成实现后才勾选。
