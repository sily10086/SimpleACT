# M03 属性资源与冷却：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

统一管理生命、耐力、护盾、攻击、防御、韧性等数值，以及起手费用与冷却，成为数值写入的权威入口。

**负责的内容**：基础/派生属性、可变资源、修饰器来源、费用预检/提交、CD 到期查询。

**边界**：不判命中、不选择连招、不判断哪个 Buff 应过期；伤害结果由 M11 计算，修饰器来源由 M12 管生命周期。

## 2. 原设计分析与需要完善的地方

- 原文数值系统描述不足，缺少属性拥有者、费用原子性与 CD 时间域。
- 上一轮将属性、伤害和 Buff 集中描述不利于独立制作，本模块现在只处理值与资源约束。

## 3. 完善后的设计

Base+Modifier 得到派生属性，HP/Stamina 是 Current 资源而非每 Tick 重算成 Base。写入统一经过 AttributeStore；M06 在起手提交段提交费用，M11 在 P5 提交效果。CD 是 AbilityRuntime 的 endUnitTick，不使用 Time.time。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| AttributeState | Base、修饰器集合、最终值；本模块唯一写入。 |
| ResourceCurrent | HP/耐力/护盾/韧性，按边界截断。 |
| AbilityRuntime | CD 结束时点与占用；本模块维护数值与查询。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `QuoteCost(actor, actionCost)` | 只读预检，返回可支付计划或拒绝原因。 |
| `CommitCost(preparedQuote)` | 仅 M06 成功起手提交段调用。 |
| `ApplyDeltas(batch)` | M11 提供已裁决变化，本模块写值。 |
| `AddModifier/RemoveBySource` | M12 提供来源，重算受影响派生值。 |

**依赖关系**：依赖 M02 的单位槽与 M01 时间上下文；向 M06/M11 提供写入口，向 AI/UI 提供只读快照。

**如何单独制作**：给定单位值和变化请求即可制作；伤害用固定 delta、动作用固定费用替身。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M03.1 定义数值与计算顺序

- [ ] **目标与需求**：基础值、资源与派生值不得混用。
- **涉及内容与做法**：明确中间精度、修饰优先级、截断和非法值处理。
- **关键伪代码**：

```text
derived = ComputeOrderedModifiers(base)
current = Clamp(current,0,max)
```

### M03.2 制作费用与冷却端口

- [ ] **目标与需求**：失败起手不扣费。
- **涉及内容与做法**：所有可失败检查放 Quote；提交段不 await、不触发外部回调。
- **关键伪代码**：

```text
quote = QuoteCost()
if preparedActionReady: CommitCost(quote); SetCooldown()
```

### M03.3 制作来源修饰与恢复

- [ ] **目标与需求**：刷新 Buff 不重复添加属性。
- **涉及内容与做法**：来源 token 定位修饰；恢复按 UnitTick 和许可执行。
- **关键伪代码**：

```text
ReplaceModifierForSource(token)
if recoveryDue && permitted: ApplyDelta(stamina,+1)
```

## 7. 一个具体例子与完成标准

耐力 12 时 A 费用10可进入并剩2，B 费用15应拒绝；失败不能提前取消当前动作或启动 CD。

- [ ] HP/耐力没有第二份可写 AI 副本。
- [ ] 失败无数值变化，成功扣费一次。
- [ ] 移除修饰来源只影响其贡献。
