# M11 伤害与效果结算：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

根据有效命中和规则集计算效果，并在统一提交阶段改变数值、生成后续状态事实。

**负责的内容**：DamageCalculator、CombatRuleSet、护盾分配、效果批次、提交结果、反应事实。

**边界**：不负责接触检测、不拥有属性存储、不决定 Buff 持续时间，也不直接切 UnitFSM。

## 2. 原设计分析与需要完善的地方

- 原文把命中输出送数值系统，但没有明确同帧互击与提交边界。
- HP、部位、Buff 混在一个大系统会导致扩展时彼此覆盖，必须通过各自端口提交。

## 3. 完善后的设计

ResolvedHit 转为效果计划；共同快照确定本批接触资格，稳定顺序分配护盾，M03 写属性，M12/M13 写各自状态。反应事实交 M05，结果交 M17。链式反伤延后为下一 Tick 命令并限制来源深度。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| EffectPlan / DamageRequest | 计算输入与稳定 requestId。 |
| CommitBatch | 本批计划、顺序和提交状态。 |
| CombatResult | 不可变前后值和来源；提交后不撤销。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `BuildPlans(hits, snapshot, rules)` | 纯计算效果计划。 |
| `CommitBatch(plans, writers)` | P5 唯一效果提交协调点。 |
| `QueueDerivedEffect(sourceChain)` | 派生效果排到明确后续阶段。 |

**依赖关系**：读取 M10 结果和 M03 属性；调用 M03/M12/M13 的领域写端口；输出 M05 反应事实、M17 已提交结果。

**如何单独制作**：固定命中请求+固定属性快照+记录型 writer 即可制作公式和批次，不需要真实碰撞。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M11.1 制作规则与纯计算

- [ ] **目标与需求**：玩法公式可以替换而不重写命中。
- **涉及内容与做法**：StandardAct 演示公式明确精度/取整；SimpleACT 作为另一个策略，避免双重扣血。
- **关键伪代码**：

```text
raw=max(0,attack*motionValue+bonus)
damage=floor(raw*100/(100+max(0,defense))*partMultiplier)
```

### M11.2 制作批次提交

- [ ] **目标与需求**：互击与护盾分配都稳定。
- **涉及内容与做法**：所有接触先裁决资格，再按目标/请求 ID 分配护盾及提交；不因先写死亡删除对手计划。
- **关键伪代码**：

```text
plans=BuildAll(snapshot)
for target: CommitOrderedEffects(plans[target])
```

### M11.3 制作结果与反应输出

- [ ] **目标与需求**：结果订阅不得反向改变已完成结算。
- **涉及内容与做法**：记录前后值、攻击、部位、来源；死亡/破韧事实延交状态模块。
- **关键伪代码**：

```text
EmitDamageApplied(before,after)
QueueReactionFacts()
DerivedEffects -> nextTick
```
