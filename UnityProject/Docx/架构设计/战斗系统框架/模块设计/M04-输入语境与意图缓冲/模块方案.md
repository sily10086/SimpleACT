# M04 输入语境与意图缓冲：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

把玩家设备操作与 AI 行动请求变为相同的战斗意图，并在动作暂时不可执行时保存有效预输入。

**负责的内容**：设备适配端口、原语、语境解析、边沿缓冲、持续移动、回执与消费。

**边界**：不决定连招出边，不直接起手或扣费；键位不进入 ActionGraph。

## 2. 原设计分析与需要完善的地方

- 原文区分输入与意图是合理的，但 AI 绕过窗口与统一入口互相冲突。
- 9 Tick 意图寿命、12 Tick 连招识别和渲染采集必须分开，不能统一拖延所有输入。

## 3. 完善后的设计

玩家与 AI 都 Submit(IntentCommand)。Move 保留最新持续值，Attack/Dodge 排边沿；P1 语义化，M06 成功起手才 Consume。issued+9 为排他结束 Tick，消费前按当前语境重新判断。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| IntentCommand | 命令序号、来源、actor、issued/expire、epoch。 |
| EdgeBuffer / SustainedInput | 本模块持有，不随渲染补步重复入队。 |
| ReceiptState | Buffered/Accepted/Rejected/Expired，终态一次。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `Submit(command)` | 入队返回编号，不当场改变世界。 |
| `ResolveCandidates(context)` | 清过期并输出候选语义。 |
| `Consume(commandId, actionHandle)` | M06 提交成功后消费。 |

**依赖关系**：读取 M02/M05 的语境，只向 M07 提供候选；M06 回报接受；M15 与设备适配器都是输入来源。

**如何单独制作**：手工输入 Tick/原语/语境变化即可制作，不必有实体动画或真实键盘。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M04.1 制作原语和来源适配

- [ ] **目标与需求**：玩家与 AI 使用同一命令格式。
- **涉及内容与做法**：旧输入只在适配层读取 KeyCode，边沿每渲染帧采集一次。
- **关键伪代码**：

```text
DeviceEdge or AIRequest -> IntentCommand -> Submit
```

### M04.2 制作缓冲与语境解析

- [ ] **目标与需求**：窗口关闭不能立即吃掉有效预输入。
- **涉及内容与做法**：区分临时阻塞与终态拒绝，过期先于本 Tick 候选选择。
- **关键伪代码**：

```text
if tick>=expire: Expire()
else ResolveAgainstCurrentContext()
```

### M04.3 制作事务消费和暂停策略

- [ ] **目标与需求**：接受失败/失焦不遗留幽灵输入。
- **涉及内容与做法**：成功按 ID 消费，失焦清持续方向，暂停不积累战斗边沿。
- **关键伪代码**：

```text
Accepted -> ConsumeExact(commandId)
FocusLost -> MoveZero
```

## 7. 一个具体例子与完成标准

A 在 T100 开始，T110 按攻击可等到 T114 取消窗口；T105 的同类输入到 T114 已过期。

- [ ] AI 与玩家都受相同许可/窗口约束。
- [ ] 成功才消费，同 ID 不重复接受。
- [ ] 一次按键不会因补步产生四次攻击。
