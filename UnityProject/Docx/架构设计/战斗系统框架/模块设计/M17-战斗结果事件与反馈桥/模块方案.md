# M17 战斗结果事件与反馈桥：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

将已提交事实交给 UI、音效、特效和外部玩法系统，同时保护战斗逻辑不受订阅顺序影响。

**负责的内容**：结果序号/路由、TEngine GameEvent 桥、一次性反馈去重、订阅作用域、HUD 数据投影。

**边界**：不充当第二个战斗调度器，不在事件回调里重新结算或同 Tick 递归起手。

## 2. 原设计分析与需要完善的地方

- 原文强调低分配结构事件，但固定几个 int/float 不足以保证类型安全和可维护性。
- 当前 TEngine 已有泛型事件机制，不应按原文假设再引入一个全局反射替代框架。

## 3. 完善后的设计

内部领域调用使用显式阶段数据；P7 才路由不可变 CombatResult。主动画看最终快照，一次性反馈按 ResultId 去重。对外 GameEvent 使用必要值类型负载，订阅随会话/UI 生命周期释放。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| CommittedResult view | 只读消费；不能撤回。 |
| FeedbackConsumption | 本场结果去重与视图绑定 token。 |
| SubscriptionScope | 本桥拥有的监听和异步请求。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `PublishCommitted(results, snapshots)` | P7 调用，投影到外部通知与表现请求。 |
| `MapToFeedback(result)` | 可配置音效/VFX/HUD 描述。 |
| `DisposeSessionScope` | 清理订阅及失效回调。 |

**依赖关系**：消费 M06/M11/M12/M13 的事实，使用 M16/M18 表现与资源端口；外部回应只能成为下一 Tick 命令。

**如何单独制作**：用手工 Result 列表和记录型反馈 sink 制作，不需要真实音效/特效。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M17.1 制作类型化结果映射

- [ ] **目标与需求**：结果不同于命令。
- **涉及内容与做法**：按结果类别映射必要字段，保留 battleId/tick/sequence/source。
- **关键伪代码**：

```text
CombatResult -> PresentationRequest + ExternalEvent
```

### M17.2 制作反馈去重

- [ ] **目标与需求**：一次伤害不能被重复播放两次。
- **涉及内容与做法**：主动画用最终快照，一次性音效/VFX 按 ResultId 消费。
- **关键伪代码**：

```text
if !seen(result.id): RouteOnce(result)
MainAnimation = finalSnapshot
```

### M17.3 制作会话/UI订阅清理

- [ ] **目标与需求**：退出后监听不能继续通知新场。
- **涉及内容与做法**：IBattleEvent 经现有生成流程；HUD 使用 AddUIEvent 和只读快照。
- **关键伪代码**：

```text
Stop -> unsubscribe owned scope
StaleAsync -> release returned resource
```
