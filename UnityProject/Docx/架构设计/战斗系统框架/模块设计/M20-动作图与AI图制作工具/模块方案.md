# M20 动作图与AI图制作工具：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

为两种不同运行语义提供编辑入口：一类编排连招边，一类编排 AI 决策树。共用基础编辑能力，但使用独立领域面板与编译契约。

**负责的内容**：ActionGraphEditor、AITreeEditor、节点/边/类型参数、引用定位、子图引用；两面板可分别交付。

**边界**：不把 AI 和动作图做成同一个万能运行器，不在画布节点中保存单位运行状态。

## 2. 原设计分析与需要完善的地方

- 原文 ABT 与 AI 定义表容易在术语上混淆；编辑工具必须明确它们不同的节点与连接约束。
- xNode/NodeGraphProcessor 提供画布，不提供本框架的取消和回执语义。

## 3. 完善后的设计

工具域内部拆 ActionGraphEditor 与 AIDefinitionEditor，两者共享选择/诊断等无玩法组件，分别导出各自 DTO。首版列表/表格可先交付，真实需要画布时再封装第三方 Editor 库。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| GraphAuthoring | nodeId、edgeId、actionRef、窗口/条件。 |
| AITreeAuthoring | typeId、schema参数、children、expand。 |
| CanvasLayout | 编辑坐标等只属作者数据，不进入热路径。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `EditActionGraph(source)` | 约束派生边、动作引用与窗口。 |
| `EditAITree(source)` | 约束节点类型参数和子节点数量。 |
| `ExportAuthoringDTO(kind)` | 交 M21 对应编译器。 |

**依赖关系**：M07/M15 提供各自 Schema；M21 提供校验/编译；不要求两种面板同时实施。

**如何单独制作**：动作图先用 A/B 定义制作；AI 面板先用 Selector/Attack 类型表制作。各自都可使用固定类型目录替身。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M20.1 先制作动作图面板

- [ ] **目标与需求**：支持连招维护。
- **涉及内容与做法**：节点/边增删、窗口引用、优先级和条件；删除节点显示受影响边。
- **关键伪代码**：

```text
EditEdge(from,to,window,priority)
OnDeleteNode -> ShowAffectedReferences
```

### M20.2 独立制作 AI 面板

- [ ] **目标与需求**：支持类型表约束下的决策内容。
- **涉及内容与做法**：类型 Schema 决定参数编辑，实例树只存具体值与连接。
- **关键伪代码**：

```text
NodeType(schema) + Instance(values,children) -> AuthoringNode
```

### M20.3 封装画布与诊断

- [ ] **目标与需求**：编辑实现可替换。
- **涉及内容与做法**：领域数据不依赖第三方 GetValue/object 执行器，诊断跳回节点/字段。
- **关键伪代码**：

```text
Canvas -> OwnDTO -> Compiler
Diagnostic -> SelectNodeAndField
```
