# M05 单位状态权限与受击反应：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

集中回答单位现在能做什么，以及死亡、破韧、击退、普通受击同时出现时进入哪个状态。

**负责的内容**：主状态、正交限制标签查询、许可矩阵、强制迁移、反应优先级、硬直结束。

**边界**：不计算伤害，不持有 Buff 寿命，不等待动画混合完成来恢复许可；标签来源容器是本模块的低层能力，M12 只登记/撤销贡献。

## 2. 原设计分析与需要完善的地方

- 原文 UnitFSM 方向合理，但状态与动画过渡锁混在一起。
- 霸体、强制不可抵抗与请求排队描述不一致，需要按迁移类别明确规则。

## 3. 完善后的设计

主状态 Active/HitStun/Knockdown/Dead 互斥，环境和标签正交。P2 处理既有强制请求，P6 从数值事实选最高反应：死亡优先。迁移请求与提交分离，M06 负责动作取消；视觉仅消费最终快照。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| PrimaryState / endUnitTick | 本模块唯一写入。 |
| TagSourceSet | 按来源计数；动作和 Buff 通过端口贡献。 |
| TransitionRequests | 理由、类别、优先级、稳定序号。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `GetPermission(actor, semantic)` | 状态与标签合成许可。 |
| `RequestTransition(request)` | 排队，不直接修改 View。 |
| `ResolveReactions(facts)` | P6 仲裁并提交唯一状态结果。 |
| `GrantTag/RevokeSource` | 记录来源贡献，不能清掉其他来源。 |

**依赖关系**：读取 M03 数值和 M11 事实；通过 M06 Cancel 关闭旧动作，输出强制位移给 M09；不从事件监听递归起手。

**如何单独制作**：用 HP/Poise 事实和假的 CancelService，即可制作迁移及权限矩阵。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M05.1 制作状态与许可矩阵

- [ ] **目标与需求**：避免枚举状态组合爆炸。
- **涉及内容与做法**：主状态、环境、标签分别建模；明确默认拒绝与错误诊断。
- **关键伪代码**：

```text
permission = StatePolicy ∩ EnvironmentPolicy ∩ TagRestrictions
```

### M05.2 制作迁移仲裁

- [ ] **目标与需求**：多击同时发生不能由遍历顺序决定反应。
- **涉及内容与做法**：收集事实后按死亡/破韧/强制/普通规则选择；稳定 tie-break。
- **关键伪代码**：

```text
winner = Death ?? Break ?? HighestAllowedReaction
```

### M05.3 制作结束与来源撤销

- [ ] **目标与需求**：逻辑立即生效且可正确恢复。
- **涉及内容与做法**：取消动作后写状态，硬直按 UnitTick 到期；来源标签单独撤销。
- **关键伪代码**：

```text
CancelCurrent(reason); CommitState(winner)
OnStunExpiry -> Active
```

## 7. 一个具体例子与完成标准

霸体单位普通受击可掉 HP/韧性但不进入普通硬直；同 Tick HP 与韧性都归零时只进入死亡。

- [ ] 死亡不受取消窗口限制。
- [ ] 视觉混合不增加控制锁。
- [ ] 同单位同批反应稳定且死亡事件一次。

这些是未来完成标准，本次没有运行检查；只有实际完成实现后才勾选。
