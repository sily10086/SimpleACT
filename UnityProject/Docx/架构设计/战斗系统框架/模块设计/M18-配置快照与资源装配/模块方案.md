# M18 配置快照与资源装配：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

在开战前提供一致版本的玩法数据和已准备的表现资源，并明确整场资源的拥有与释放。

**负责的内容**：Luban/UAnim 转换、manifest 校验、只读快照、资源租约、对象池适配、Ready 产物。

**边界**：不在 Tick 加载内容，不编辑策划源，不实现另一套对象池或热更框架；导出由 M21。

## 2. 原设计分析与需要完善的地方

- 原文强调 JSON 热更，但缺少机制版本、跨文件一致性和原生资源版本配套。
- 当前池负责复用，不负责加载；必须明确池实例和资产句柄由谁拥有。

## 3. 完善后的设计

内容分层：Luban 拥有标量，UAnim 拥有时间轴/图，manifest 绑定版本与资源。Load→Validate→Compile→Freeze 原子完成；资源适配层持有租约，M01 只有拿到 PreparedBattle 才 Ready。首版静态池复用现有配置。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| BattleManifest / DefinitionSnapshot | 版本、hash、ID映射；开场冻结。 |
| ResourceScope | 每个句柄、实例与释放责任。 |
| PreparedBattle | 全套依赖成功后的装配结果。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `PrepareAsync(profile, sessionToken)` | 读取内容与资源，失败返回可定位原因。 |
| `GetDefinitionSnapshot` | 只读，战斗中不换索引。 |
| `AcquireView/ReturnView` | 封装现有池契约并跟踪本场实例。 |
| `ReleaseScope` | 先解绑回池，再卸载本场资产。 |

**依赖关系**：消费 M21 编译产物，使用 TEngine Resource/Pool；给 M01/M02/M16 提供准备结果。

**如何单独制作**：用内存内容源和假租约先做版本/引用/拥有关系；实际资源适配后接。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M18.1 制作数据所有权和加载

- [ ] **目标与需求**：避免两份窗口规则。
- **涉及内容与做法**：固定 Luban/UAnim 分工；通过业务适配转换，GameProto 不反向依赖 GameLogic。
- **关键伪代码**：

```text
tables + uanim -> Validate -> FrozenDefinitions
```

### M18.2 制作资源与池租约

- [ ] **目标与需求**：每个获取有对应释放。
- **涉及内容与做法**：保留已存在的 await 预热，用实际 TrySpawn/Despawn，失败不进入 Ready。
- **关键伪代码**：

```text
PrepareResources -> PrewarmExistingPools -> TrackBorrowedInstances
```

### M18.3 制作取消与版本切换

- [ ] **目标与需求**：晚到加载和热更不污染当前场。
- **涉及内容与做法**：token 失效回收自己的产物；新版本只在下一场选择。
- **关键伪代码**：

```text
if staleToken: ReleaseAcquired(); return
nextSession uses nextSnapshot
```

## 7. 一个具体例子与完成标准

动作表新版本引用不存在伤害 ID 时整份候选内容被拒绝，不能让角色带半套新配置开始战斗。

- [ ] 无半成品快照对外可见。
- [ ] Tick 内无 IO。
- [ ] 退出只释放本场资产，不关闭全局池。
