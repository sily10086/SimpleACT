# M16 动画后端与单位视图：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

将动作和位置快照表现为玩家能看到的 Sprite、骨骼或 3D 动画，支持替换素材后端而保持战斗规则一致。

**负责的内容**：UnitView 绑定、Sprite 采样、后端接口、姿态插值、视觉混合、表现资源释放。

**边界**：不发起命中、不写逻辑位置、不决定输入何时解锁；音效/命中 VFX 的事实路由属于 M17。

## 2. 原设计分析与需要完善的地方

- 原文希望所有动画统一为骨骼 JSON，但 Spine 皮肤/插槽/约束与 Sprite 不是简单扁平轨道可替代。
- 视觉过渡阻止逻辑输入会把动画细节变成战斗规则，应分离。

## 3. 完善后的设计

统一 IActionPresentation 的采样契约，首版 Sprite，3D/Spine 使用原生后端适配。逻辑 ActionFrame 决定采样时点，Motor 决定位置；View 绑定完整实体句柄和 token，晚到结果不可写新代次。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| ViewBinding | entity handle、token、backend、资源句柄。 |
| SpriteExposureMap | 图片到逻辑帧区间的映射。 |
| PresentationState | 只影响视觉的混合/局部资源，不作为权威状态。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `Bind(entity, resourceBinding)` | 初始化本代次视图。 |
| `Sample(actionSnapshot, poseInterval, alpha)` | 按快照显示，不产生逻辑命令。 |
| `Unbind/Release` | 停止局部表现并释放所持资源。 |

**依赖关系**：读取 M06/M08 动作快照、M09 姿态；M18 提供资源，M17 可路由附加反馈；不回调修改战斗。

**如何单独制作**：用固定快照序列和少量 Sprite 即可制作，无需命中或 AI。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M16.1 制作 View 绑定与采样端口

- [ ] **目标与需求**：不同后端共用外层时间语义。
- **涉及内容与做法**：IActionPresentation 只暴露 Sample/Release，绑定完整逻辑身份。
- **关键伪代码**：

```text
Bind(handle,token)
Sample(snapshot) only if exact binding matches
```

### M16.2 制作 Sprite 后端

- [ ] **目标与需求**：图片张数与逻辑帧数独立。
- **涉及内容与做法**：以 exposure 区间找图片，位置只插值，禁止另起 delta 动作时钟。
- **关键伪代码**：

```text
sprite=MapFrame(snapshot.actionFrame)
pose=Lerp(prev,current,alpha)
```

### M16.3 制作解绑与后端扩展契约

- [ ] **目标与需求**：池复用不能带入旧视觉状态。
- **涉及内容与做法**：清临时材质/动画/挂点；后续原生后端按能力声明接入。
- **关键伪代码**：

```text
Unbind -> invalidate token -> stop owned visuals -> clear references
```
