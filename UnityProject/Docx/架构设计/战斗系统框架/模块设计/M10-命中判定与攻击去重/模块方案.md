# M10 命中判定与攻击去重：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

将几何接触变成一次有明确目标、部位和防御分类的有效命中，防止同一攻击重复结算。

**负责的内容**：Hitbox/Hurtbox、候选采集、阵营过滤、部位选择、无敌/弹反/格挡分类、命中账本。

**边界**：不计算或写 HP、不切状态、不播放受击特效。

## 2. 原设计分析与需要完善的地方

- 原文集中 HitResolver 是正确方向，但只按帧去重会让挥击有效期每帧扣血。
- 多个攻击框/部位同时接触的选择以及缓冲溢出没有完整规则。

## 3. 完善后的设计

P4 收集全批候选；P5 按 attackInstance+hitGroup+target 稳定分组，选部位后判断防御与跨帧账本。多段通过 pulse/group 区分。无敌是否占账设显式策略，不能依赖实现偶然顺序。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| HitCandidateBuffer | 本 Tick 接触，只是候选。 |
| HitLedger | 攻击生命周期持有，非每 Tick 清空。 |
| ResolvedHit | 分类、目标、部位、来源、快照数据。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `Collect(activeShapes, poses)` | 输出候选和容量状态。 |
| `Resolve(batch, defenseSnapshot)` | 输出命中/格挡/免疫等事实。 |
| `ReleaseAttackLedger(handle)` | 攻击归属结束时清理对应账本。 |

**依赖关系**：M08/M14 提供攻击源，M09 提供空间查询，M05/M13 提供防御/部位只读事实；输出给 M11。

**如何单独制作**：用预制接触列表代替几何查询，先制作过滤/分组/去重；再接真实形状查询。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M10.1 制作候选契约与采集

- [ ] **目标与需求**：检测到接触不立刻扣血。
- **涉及内容与做法**：收集目标、部位、组、路径参数；容量不足必须报告。
- **关键伪代码**：

```text
query.Collect -> CandidateBuffer
if overflow: BattleFault(QueryCapacity)
```

### M10.2 制作稳定裁决

- [ ] **目标与需求**：碰撞返回顺序不决定护甲效果。
- **涉及内容与做法**：按组与目标聚合，按 priority 和稳定 partId 选部位，读取同一防御快照。
- **关键伪代码**：

```text
part=SelectHighestPriority(group)
outcome=ClassifyDefense(snapshot)
```

### M10.3 制作跨帧账本

- [ ] **目标与需求**：一挥多帧重叠只算一次。
- **涉及内容与做法**：按攻击实例/组/目标记账，是否占账由 outcome 策略决定。
- **关键伪代码**：

```text
if ledger.Contains(key): skip
if outcome.ConsumesOpportunity: ledger.Add(key)
```

## 7. 一个具体例子与完成标准

A 的6–9帧持续碰同一目标，默认只输出一份有效命中；同时碰身体与护甲时只选优先级更高部位。

- [ ] 持续重叠不逐帧伤害。
- [ ] 同组多框和多部位不会重复伤害。
- [ ] 不同 pulse 可明确再次命中，溢出不静默截断。

这些是未来完成标准，本次没有运行检查；只有实际完成实现后才勾选。
