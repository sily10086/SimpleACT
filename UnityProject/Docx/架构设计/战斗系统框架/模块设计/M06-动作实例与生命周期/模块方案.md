# M06 动作实例与生命周期：分析、完善与制作方案

日期：2026-10-25｜方案版本：v0.2｜实现状态：未开始。模块编号表示功能归属，不表示全局开发步骤。

## 1. 模块是什么，解决什么问题

管理一次动作从准备、进入到完成/取消的全过程，保证费用、占用和输入消费一起成功或一起不发生。

**负责的内容**：ActionRuntime、起手事务、实例 ID、动作占用、终止回执、统一取消和来源清理。

**边界**：不选连招边、不解释各时间轴轨道、不计算命中；这些分别属于 M07/M08/M10。

## 2. 原设计分析与需要完善的地方

- 原文围绕动画 ID 组织执行，缺少一次施放实例与图节点的明确区分。
- 取消时清全部事件会误删已提交伤害；需要按动作来源作废待执行命令。

## 3. 完善后的设计

定义 ID、图节点 ID、动作实例 ID 分开。Prepare 完成所有可失败检查，Commit 在无 await/无外部回调段关闭旧动作、提交费用、装入新实例、消费命令；Completed/Cancelled 都走一次性 End。

| 本模块拥有的数据 | 用途及写入规则 |
|---|---|
| ActionRuntime | owner、definition、instanceId、frame、epoch、terminal。 |
| PreparedStart | 定义/权限/成本/容量的已准备计划。 |
| OwnedContributions | 动作临时标签、窗口、占用与未执行命令来源。 |

## 4. 对外接口与协作边界

| 拟新增契约 | 输入与输出、调用时点 |
|---|---|
| `PrepareStart(candidate, context)` | 只读/预留检查，返回计划或拒绝。 |
| `CommitStart(plan)` | 写当前动作并回 Accepted(handle)。 |
| `End(handle, reason)` | 按精确实例清理并产生唯一终止结果。 |

**依赖关系**：从 M07 获得候选，读取 M05 许可并调用 M03 费用端口；回执给 M04/M15，M08 读取实例执行。

**如何单独制作**：使用固定候选、假许可与记录费用变化的属性替身，可以独立完成事务与取消；无需动作图编辑器。

以上为拟新增契约，不是项目现有 API。先固定输入输出，再替换开发替身为真实相邻模块；替身只用于模块开发，不代表整个战斗已集成。

## 5. 本模块内部的制作步骤

### M06.1 制作实例和起手准备

- [ ] **目标与需求**：失败不改变当前动作。
- **涉及内容与做法**：定义实例 ID、PreparedStart 与拒绝原因；容量和引用先校验。
- **关键伪代码**：

```text
plan = Prepare(candidate)
if failed: return without state changes
```

### M06.2 制作原子进入

- [ ] **目标与需求**：资源、动作和消费共同提交。
- **涉及内容与做法**：提交段不触发订阅者，结果进入 P7；当前实例统一切换。
- **关键伪代码**：

```text
EndOldIfNeeded -> CommitCost -> InstallNew -> ConsumeInput -> QueueStarted
```

### M06.3 制作统一终止

- [ ] **目标与需求**：任意中断都能清理且不重复。
- **涉及内容与做法**：按实例撤销未执行命令和临时贡献，保留独立弹丸和已提交结果。
- **关键伪代码**：

```text
if terminal: return
InvalidatePending(handle); RevokeOwned(handle); EmitTerminalOnce()
```

## 7. 一个具体例子与完成标准

A 起手消耗10，后在有效帧前被打断：费用默认不退，未发生攻击不执行，A 只收到一次 Cancelled。

- [ ] 失败不扣费、不清当前动作、不消费意图。
- [ ] 同定义重复执行拥有不同实例号。
- [ ] 取消不删除已提交伤害。

这些是未来完成标准，本次没有运行检查；只有实际完成实现后才勾选。
