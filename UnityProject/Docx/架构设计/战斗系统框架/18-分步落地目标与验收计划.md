# 分步落地目标与验收计划

日期：2026-10-25；v0.1。**全部代码、资源和验证目标尚未执行。** 文档完成不勾选实现目标；用户确认具体批次后，再按该批次实施。下列为各步全部计划修改目标，新增范围应同步更新本清单。

## 总体策略

本篇保留阶段总览。**具体执行以 [分步实施总索引](分步实施/00-执行总索引.md) 及其 43 篇独立步骤文档为入口**：每篇列出目标与需求、前置依赖、全部拟修改文件、逐任务原因/做法/伪代码、整步流程、边界、完成标准和实际记录。文档细化不代表代码实施或验证完成。

先打通无编辑器依赖的最小战斗链，再接入真实资源和制作工具，最后扩展复杂内容。执行顺序：S0规则与范围 → S1数据/时钟 → S2输入/FSM/动作 → S3命中/结算 → S4视图/项目接入 → S5AI/Buff/部位 → S6编辑器 → S7玩法与后端扩展。

MVP完成线是S1–S4达到可操作单机切片；框架完整演示还需要S5–S6。S7按需求选择，不是为了“完善”就全部实现。工期取决于人员、素材、平台和检查范围，本案没有依据给出精确天数。

## S0：实施前冻结关键契约

- [ ] **确认主后端与平台**。为什么：影响动画、物理、内存和输入。怎么做：确认首版是否采用2D/Sprite单机练习场，列最低目标设备与同屏单位预算。伪代码：`BuildProfile = Platform + Backend + Limits`。
- [ ] **确认确定性等级**。为什么：普通Physics2D单机与跨平台固定数值模拟的成本明显不同。怎么做：选择仅可诊断重演/同环境重演/跨平台确定性，并据此固定ICombatQuery与Motor实现。伪代码：`SimulationBackend = Resolve(ReplayRequirement)`。
- [ ] **确认玩法规则集与同帧语义**。为什么：一击必杀与HP制不能混算。怎么做：选择StandardActDemo或SimpleAct；确认批次互击、取消退款、Buff时间域。伪代码：`world = Create(ruleSnapshot, ruleSet)`。
- [ ] **建立正式实施记录**。为什么：本案为提案。怎么做：保留本版并建立批准批次、修改文件和实际进度，不把未确认项改成已确认。伪代码：`ApprovedBatch = S1...`。

建议默认：单机2D/Sprite、StandardActDemo、Tick批次互击、取消不退款；跨平台确定性不作首版承诺。若以已有SimpleACT确定性要求为硬目标，应在S0调整，不能拖到做完碰撞再决定。

## S1：数据、身份与时钟

- [ ] **新增Data定义**：`Core/Battle/Data/` 中EntityHandle、ActionDefinition、WindowDefinition、Command/Result契约。原因：后续系统共用边界。做法：不可变定义+独立Runtime；稳定ID与索引分开。伪代码：`snapshot = Compile(definitions); runtime = Create(snapshot)`。
- [ ] **新增World和Clock**：`Core/Battle/Simulation/BattleWorld.cs`、BattleClock、TickContext、TimeDomain。原因：所有逻辑一个执行顺序。做法：按03定义阶段与计数，先速度1。伪代码：`while budget: world.Step(tick++)`。
- [ ] **新增命令/结果缓冲与容量失败策略**：`Core/Battle/Event/`。原因：取消和溢出可定位。做法：预分配、强类型、BattleFault，不静默截断。伪代码：`if !TryWrite: StopWithFault(capacity)`。
- [ ] **新增内容载入契约**：Data中的Manifest/VersionValidator。原因：新旧数据不混跑。做法：schema、hash、机制版本一次检查后冻结。伪代码：`ValidateVersion -> FreezeSnapshot`。

交付物：可由普通C#调用的Step核心与示例数据。未来验收：frame0、半开区间、暂停、4步调度上限、旧实体代次、容量耗尽。**未运行。**

## S2：输入、状态和动作生命周期

- [ ] **新增IntentResolver/Buffer**：`Core/Battle/Input/`。原因：玩家AI统一入口。做法：9Tick预输入、语境重解、成功后消费、拒绝码。伪代码：`Peek -> Validate -> Commit -> Consume`。
- [ ] **新增UnitStateSystem/ReactionResolver**：`Core/Battle/State/`。原因：禁攻和受击统一权威。做法：互斥主状态+正交标签，绝对/反应/普通迁移分类。伪代码：`Arbitrate(requests); CommitTransition(winner)`。
- [ ] **新增ActionGraphRunner/Timeline/CancelService**：`Core/Battle/Action/`。原因：连招与取消不分散。做法：单主通道、稳定出边、帧窗口、清理来源、动作回执。伪代码：`ChooseEdge -> TryStart -> EvaluateFrame -> EndOnce`。
- [ ] **新增临时数据样例**：文档约定的A/B/Dodge定义，放开发专用示例数据层，不伪装Luban生成物。原因：编辑器未完成也能验证核心结构。伪代码：`DemoDefinitionBuilder.Build()`。

交付物：命令驱动的A→B与受击取消链。未来验收：17案例一/二、同Tick重复命令、零时间环保护、扣费原子性。**未运行。**

## S3：运动、命中与基础数值

- [ ] **新增Motor与查询适配契约**：`Core/Battle/Motion/`。原因：位置唯一写者。做法：显式位移优先级、前后姿态、墙体阻挡；根据S0选择查询实现。伪代码：`desired = ArbitrateMotion(); actual = Sweep(desired)`。
- [ ] **新增HitCollector/Resolver/Ledger**：`Core/Battle/Hit/`。原因：统一命中去重和多部位选择。做法：先收集所有候选，再稳定分组和提交。伪代码：`Collect -> Filter -> SelectPart -> Deduplicate -> Resolve`。
- [ ] **新增ProjectileSystem**：`Core/Battle/Projectile/`。原因：弹丸独立生命周期与扫掠。做法：独立身份、来源快照、穿透次数、寿命域。伪代码：`MoveSweep; Hit; DecreaseLifetime; Remove`。
- [ ] **新增Attribute/Effect最小链**：`Core/Battle/Attribute/`、`Effect/`。原因：HP/耐力唯一提交方。做法：演示公式、护盾、伤害与死亡，暂不完整Buff。伪代码：`ComputeAll -> ApplyBatch -> ResolveDeath`。

交付物：逻辑可完成真实攻击、命中、硬直、死亡。未来验收：连续重叠不重复伤害、批次双死、无敌边界、弹丸穿过薄目标、同组多框。**未运行。**

## S4：接入TEngine与可操作演示

- [ ] **新增BattleModule/门面**：`Module/BattleModule/`、修改GameModule.cs。原因：统一生命周期和驱动入口。做法：新增Battle门面及IUpdateDriver门面；模块同步注册一次Update并配对释放。伪代码：`Ready -> AddUpdate -> Running; Stop -> RemoveUpdate`。
- [ ] **扩展GameApp就绪链**：修改GameApp.cs或同类partial文件。原因：资源就绪后开始战斗。做法：保留现有await对象池预热，在其后启动演示/菜单入口。伪代码：`await ExistingPoolStart; await BattlePrepare; Start`。
- [ ] **新增旧输入适配器与事件桥**：Adapters/、Bridges/、IEvent/IBattleEvent.cs。原因：项目入口与核心解耦。做法：键位转原语，结果经GameEvent通知；不手写生成文件。伪代码：`KeyEdge -> Submit; Results -> GameEvent`。
- [ ] **新增SpriteActionPresenter/UnitView**：`Core/Battle/View/`。原因：让逻辑结果可见。做法：预载Sprite绑定、快照采样、generation防过期。伪代码：`if bindingMatches: Sample(snapshot)`。
- [ ] **创建Demo场景/Prefab/池配置**：13列出的AssetRaw位置，通过Unity CLI/编辑器制作。原因：交付真实可操作切片。做法：Player/Enemy/Projectile、必要阻挡、相机、池预热。伪代码：`PrepareResources -> TrySpawn -> BindEntity`。
- [ ] **新增演示HUD**：UI/BattleDebugUI.cs及Prefab。原因：直观看到状态/帧/拒绝码。做法：遵循UIWindow/AddUIEvent及生成绑定流程。伪代码：`OnCommittedResult -> RefreshReadOnlyState`。
- [ ] **完成退出清理**：BattleModule/资源桥。原因：重进不残留。做法：停止驱动、取消任务、解绑、回池、卸载本场资源；不关全局池。伪代码：`Stop -> Cancel -> Unbind -> Despawn -> Release`。

交付物：一名玩家与敌人的Sprite战斗练习场。未来验收：17案例一/二/六、反复进出、失焦/暂停、资源失败不Running。**未运行。**

## S5：AI、Buff与部位完整示范

- [ ] **新增AI最小运行器**：Core/Battle/AI/。原因：证明玩家AI共享机制。做法：Selector/Sequence/Condition/Attack/Move/Idle、回执等待、降频和唤醒。伪代码：`Decide -> SubmitOnce -> AwaitReceipt -> Reevaluate`。
- [ ] **补全BuffSystem和Tag来源管理**：Effect/。原因：持续效果可正确刷新移除。做法：叠层策略、时间域、周期规则、来源计数。伪代码：`ApplyOrRefresh; TickPeriod; Expire; RemoveOnce`。
- [ ] **新增PartSystem**：Part/。原因：部位破坏不是单耐久字段。做法：一次性状态变化、倍率、反应与结果。伪代码：`durability-=amount; CrossZero -> BreakOnce`。
- [ ] **加入演示内容配置**：Luban定义/数据与UAnim引用按数据所有权制作。原因：把硬编码演示迁为内容。做法：对齐16的字段，不手改生成C#。伪代码：`TableData -> RuntimeSnapshot`。

交付物：敌人主动进攻、Buff刷新、护甲破坏。未来验收：17案例三/四、内部Selector失败、挂起恢复、Buff末帧与Tag多来源。**未运行。**

## S6：编辑器与内容发布管线

- [ ] **新增Authoring数据和导出器**：GameEditor/BattleAuthoring/，必要时更新GameEditor.asmdef引用。原因：可持续制作内容。做法：明确DTO与运行类型分离。伪代码：`Authoring -> Validate -> Compile -> Manifest`。
- [ ] **新增复合动作编辑窗口**：同目录Timeline/。原因：策划配置动作帧与框体。做法：片段、相位、窗口、命中、事件轨道，复用运行求值器预览。伪代码：`Seek(frame) -> Timeline.Evaluate -> Preview`。
- [ ] **新增动作图/AI表编辑面板**：同目录Graph/。原因：维护节点引用与条件。做法：先表格/列表，确认需求后选择xNode或NodeGraphProcessor作为画布。伪代码：`GraphAuthoring -> FlatNodesAndEdges`。
- [ ] **新增静态检查与诊断**：Validation/、RuntimeDebug/。原因：阻止坏数据进入战斗。做法：区间、ID、引用、能力、零时环、expand深度、参数schema。伪代码：`errors = ValidateAll(); if any: blockExport`。
- [ ] **新增资源清单和版本发布步骤**：AssetRaw/Configs/Battle及构建流程文档。原因：热更可追踪。做法：配置/资源/机制版本匹配，下场切换快照。伪代码：`PublishBundleAndManifest -> LoadNextSession`。

交付物：策划能独立新增一招并接入连招；不是只会运行开发者硬编码示例。未来验收：相同源稳定导出、错误定位、Undo/Redo、预览与逻辑帧一致、旧版本拒绝。**未运行。**

## S7：按需求扩展

- [ ] **SimpleACT规则集**：接RunModule/速度档/精准事件/时停，单一World驱动。原因：与已有玩法提案结合。做法：先确认旧方案待定规则，再实现RuleSet。伪代码：`CombatFact -> ModeRule -> TimeDomainRequest`。
- [ ] **3D或Spine后端**：View/对应Adapter，资源能力声明。原因：复用机制支持新素材。做法：保留原生Runtime；手动驱动与资源生命周期。伪代码：`ActionTime -> Backend.Sample`。
- [ ] **多通道、倍率和复杂AI**：按明确内容需求逐项增加。原因：成本较高，避免提前通用化。做法：定义通道写入权、子步和取消策略后再编码。伪代码：`ArbitrateChannels -> EvaluateSubsteps -> MergeResults`。
- [ ] **强确定性/联网**：另立方案。原因：需要固定数值、碰撞、输入同步、快照和纠错；不能靠整数帧自动达成。伪代码：`Snapshot + Commands + RNG -> DeterministicStep`。
