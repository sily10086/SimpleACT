# 原文逐章解析与问题清单

日期：2026-10-25；v0.1。原文是持续追加的设计记录，不能把每章同时视为最终规范。以下“建议”是本次方案，不是对原作者意图的断言。原文链接集中在 [19](19-来源覆盖与交付记录.md)。

## 1. 逐章理解

| 原章 | 实际功能与设计意图 | 本方案的处理 |
|---|---|---|
| 00 总体 | 机制共享、内容配置化、意图统一、帧制、UAnim；后追加 UnitFSM | 保留方向，补权威数据和固定阶段管线 |
| 01 复合编辑器 | 把前摇/攻击/后摇、事件、判定框和窗口组成动作资产 | MVP 先顺序片段和轨道；条件分支归动作图 |
| 02 UAnim | 动画数据归一、编辑期秒转帧、运行时加载一次 | 统一动作描述，保留原生动画后端；补版本与资源清单 |
| 03 SpriteSequence | 直接换图，配置总帧数与尾部过渡 | 保留；定义非整除分配，取消窗口不自动强制跳过尾部 |
| 04 HitResolver | 上报碰撞对、集中去重与数值/特效/反应输出 | 扩展为候选→验证→仲裁→提交；去重持续到攻击实例结束 |
| 05 事件 | struct、环形队列、整数路由、帧末通知 | 内部命令与外部结果分流，复用 TEngine 对外通知 |
| 06 ABT | 数据化出边、取消、权重、自动链、并行、共享节点和环 | 更准确称 ActionGraph；与标准行为树分开 |
| 07 输入 | 设备→绑定→语境→意图，两种缓冲 | 统一原语入口；补上下文失效、消费与设备切换规则 |
| 08 AI 派生 | 高层决策节奏，动作边负责具体招式 | 保留；不同角色使用配置覆盖，避免手感一起被误改 |
| 09 帧计时 | 固定逻辑步长、动画与判定同步、回放愿景 | 补调度器、时间域、事件跨越；帧制不等于确定性 |
| 10 打断 | 受击优先于动作，霸体转削韧 | 采纳 13 章修正，由 UnitFSM 统一迁移 |
| 11 数据/验收 | 汇总类型与性能、回放要求 | 改成可观察的条件和证据，不能把愿景当性能事实 |
| 12 AI 状态树 | 定义表+实例树、expand、黑板、降频与挂起 | 保留数据复用；修复状态归属、失败传播和恢复条件 |
| 13 UnitFSM | 状态权威、许可矩阵、重入 ABT、清上下文 | 核心保留；分离逻辑迁移和视觉混合，明确强制迁移分类 |

## 2. 必须解决的问题

|---|---|---|---|
| A01 / P0 | 01/02 宣称后端差异编辑期全部消除 | 单个骨骼轨道 JSON 无法自动保留 Humanoid 重定向、Spine 约束/附件/皮肤/蒙皮 | UAnim 统一时间轴与引用，动画由 Adapter 执行；不重写骨骼引擎 |
| A02 / P0 | 00/05 的命中开启与结算均称帧末 | Hitbox 在查询后才打开，命中晚一帧 | 时间轴命令在碰撞前生效，结果提交后才广播 |

| A04 / P0 | 09 60Hz 与“每秒只渲染一帧就只加一帧”混用 | 游戏速度与渲染绑定，慢机窗口异常变长 | 累积器固定步长，限制每渲染帧工作量；明确慢放降级 |

| A20 / P1 | 08 改玩家手感敌人自动跟随 | 无意改变全体敌人的前摇和公平性 | 共享机制，数据显式共享/覆盖；改共享资产展示引用影响 |

## 3. 不应未经证据继承的说法

- 原文关于“旧事件系统必须重做”的判断不能套到当前 TEngine。当前代码已有泛型委托和生成接口，不等同于字符串反射调用。
- 原文列出的怪物招式、无敌帧和武器后摇数字没有指定游戏版本和来源。本案仅把它们视为作者举例，不作为真实游戏数据；演示数值另标为自拟。
- “程序机制永不复制”“调手感零代码”应理解为目标：已有机制组合能配置，新交互机制仍可能需要程序扩展。
- “环零成本”不成立：跨 Tick 回边成本可控，同 Tick 自动跳转仍需预算，expand 调用还需要栈。

## 4. 推荐决策

保留配置驱动的动作框架，拒绝“首版同时造通用动画引擎、完整行为树编辑器、跨平台帧同步”这一范围。首先完成真实战斗闭环，再做制作工具和更多后端。平台、联网和最终玩法尚未确认，相关选择列在 [18](18-分步落地目标与验收计划.md)。
