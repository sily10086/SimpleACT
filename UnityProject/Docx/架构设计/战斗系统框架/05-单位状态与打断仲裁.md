# 单位状态与打断仲裁

日期：2026-10-25；v0.1。对应原文 10/13，采用 UnitFSM 权威这一后续修正。

## 1. 状态如何划分

互斥主状态建议 `Active / HitStun / Knockdown / Dead`；运动模式 `Ground / Air / Water / Climb` 独立由 Motor 管理；`Disarmed / Silence / Invulnerable / SuperArmor` 等为带来源的限制或能力标签。BossPhase 属战斗状态数据。避免“水中缴械受伤愤怒”等组合爆炸。

UnitFSM 决定行为许可，ActionGraph 选择已获准的动作，表现层采样动作。不把每一个普通攻击同时做成一份 UnitFSM 状态和一份动作图状态。

## 2. 权限组合

最终许可 = 主状态许可 ∩ 环境约束 ∩ 装备能力 ∩ Buff/标签约束。默认禁止优先；降级/改写只能在仍允许的范围内执行。语义转换如 Jump→SwimUp 放 Resolver，UnitFSM 负责验证转换后的动作，不再重复做一套环境翻译。

| 状态/标签 | Attack | Move | Defend | 备注 |
|---|---|---|---|---|
| Active | 按资源/CD | 允许 | 按配置 | 动作窗口再决定何时执行 |
| Disarmed | 禁止武器攻击 | 允许 | 按武器依赖 | 可允许徒手技能，但需要明确标签 |
| HitStun | 禁止 | 禁止主动移动 | 禁止 | 击退为外部运动，不等于 Move 意图 |
| Knockdown | 禁止 | 禁止 | 禁止 | 起身完成回 Active |
| Dead | 禁止 | 禁止 | 禁止 | Idle 也不能绕过死亡进入活体待机 |

## 3. 迁移请求分类

1. **绝对迁移**：死亡、场景移除；不能被霸体或取消窗口拦截。
2. **战斗反应**：普通受击、击飞、击退；先经免疫/霸体/韧性规则处理，再产生实际迁移。只有通过仲裁的迁移才不可拒绝。
3. **普通行为迁移**：主动切姿态等；可在窗口等待，排队请求携带 epoch、到期时间和前提，执行前复查。

原文 100/90/80/70 可用作初始反应优先级，但不能只看数字：死亡先，命中免疫已在命中阶段判断；霸体一般免普通硬直，不等于免伤；能否击飞霸体由反应标签配置。

同级硬直默认取 `max(当前剩余,新硬直)`，不默认相加；击退选择强度最大、同强度按稳定来源 ID，不依赖遍历先后。所有这些都是提案，需策划确认。

## 4. 迁移提交

```text
CommitTransition(request):
  检查本单位代次和请求前提
  if Absolute or ReactionAccepted or OrdinaryWindowAllowed:
    记录旧动作取消原因
    CancelAction(oldAction)  // 关hitbox、清动作标签、清占用
    actionEpoch += 1
    废弃旧epoch的意图和未执行动作命令
    Exit旧主状态；写新主状态；Enter新主状态
    按新状态绑定选择反应动作或入口动作图
    发StateChanged已提交结果
```

不能删除整个世界队列，也不能删除旧动作已经提交的 DamageApplied/PartBroken。取消应按 `owner + actionInstance + epoch` 定位。

## 5. 逻辑迁移与视觉混合

逻辑在迁移提交时立刻生效；画面允许旧姿态向新姿态混合。原文滑出12帧后才播新态会使状态已变而画面仍挥剑，建议新态立即成为目标姿态，旧姿态仅作为混合输入。

`VisualBlendTicks` 与 `ControlLockTicks` 分开：缴械可以立即移动；受击的控制锁来自硬直帧；死亡无输入。Sprite 不支持骨骼淡入时可硬切/叠影，不能凭空声称无姿态跳变。

“同帧播放一次”改为“每单位每表现通道提交一次最终目标”。逻辑可以在本 Tick 开始攻击又在结算被打断，最终只展示受击；动作开始和取消仍留在结果日志，避免吞掉资源事实。

## 6. 实现目标与用例

拟新增 `Core/Battle/State/UnitStateSystem.cs`、PermissionEvaluator、ReactionResolver；数据 UnitStateDefinition、TransitionDefinition；状态变化统一走一个入口。

未来用例：霸体受伤不硬直；死亡无条件覆盖霸体；缴械禁止新武器攻击；延迟迁移目标已失效；受击同时触发多个来源；取消动作后无残留命中框。参考 [UnityHFSM](https://github.com/Inspiaaa/UnityHFSM) 的层级与延迟退出思想，不直接套用其秒制计时作为战斗时钟。
