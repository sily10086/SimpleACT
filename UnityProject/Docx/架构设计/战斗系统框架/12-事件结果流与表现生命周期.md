# 事件结果流与表现生命周期

日期：2026-10-25；v0.1。对应原文05，适配项目现有TEngine。

## 1. 三种数据流不能混为一个总线

| 流 | 例子 | 消费方式 |
|---|---|---|
| 请求/命令 | Attack、SpawnProjectile、ApplyEffect | 指定战斗阶段检查并执行，可拒绝 |
| 已提交事实 | DamageApplied、ActionCancelled、UnitDied | 只读通知，不允许监听者回滚事实 |
| 表现请求 | 播放剑光、飘字、相机反馈 | 可降级/丢非关键表现，不改变战斗 |

战斗内部依赖使用显式调用与阶段缓冲，结果在P7桥接到GameEvent；UI用AddUIEvent注册。无需把原文EventCenter完整复制为第二个全局服务。

## 2. 队列设计

固定容量或分块缓冲，强类型结构体；每个结果至少能定位BattleId、Tick、Sequence、EntityHandle和ActionId。原文“两int两float”可用于某个小事件，不能作为所有事件的唯一包结构。

按用途分开 `ActionCommandBuffer`、`HitCandidateBuffer`、`CombatResultBuffer`、`PresentationBuffer`。队列容量耗尽返回明确状态：逻辑队列进入BattleFault或受控扩容流程；表现队列可合并飘字或丢最低优先级并计数。

```text
P7 Publish:
  Freeze本Tick结果批次
  用缓存委托逐条桥接GameEvent
  监听器若请求新战斗操作 -> 入下一Tick命令队列
  清已消费批次，交换双缓冲
```

这里的“延迟派发”是同步主线程里的阶段调度，不等于开后台线程或async任务。结果列表若下Tick会复用，订阅方只能在回调中读取；要长期保存须复制必要值或使用拥有生命周期的快照。

## 3. 取消与代次

动作取消作废该动作未执行命令；已提交伤害和死亡保持不变。监听器收结果时目标View可能已回池，所以必须检查EntityHandle及View绑定generation。需要飘字时结果携带命中位置快照，不到已经复用的Transform取位置。

异步VFX加载完成若旧battleId/generation失效，释放返回的资源，不挂到新单位。取消token只表达请求，不能保证资源没有返回。

## 4. 表现生命周期

| 表现 | 开始 | 结束 |
|---|---|---|
| 挥刀尾迹 | ActionPresentation marker | 动作退出/取消统一清理 |
| 命中特效 | 已提交HitResult | 特效自身生命周期结束回池 |
| 持续光环 | BuffApplied结果 | 对应BuffRemoved或单位释放 |
| 伤害数字 | DamageApplied | UI播放完回收，不持有单位对象 |
| 受击动画 | UnitFSM最终反应快照 | 后续反应/自然完成 |

先查必要资源是否就绪，再开始战斗。非关键效果缺失可以记录一次告警并跳过；角色View或必要动作资源缺失则禁止进入Running，不能把玩家变成不可见仍可攻击的单位。

## 5. 性能目标的正确写法

目标：**预热完成后，在约定实体/命中/事件上限内，战斗Step热路径无可避免的托管分配**。加载、导出、错误诊断和UI不包含在此目标中。结构体进入object接口可能装箱，LINQ、闭包、字串日志、集合扩容和排序比较器都需要实测；本次没有性能数据，不能称“零GC已经实现”。

参考 [MessagePipe](https://github.com/Cysharp/MessagePipe) 的类型化消息、作用域订阅和泄漏诊断；当前项目继续用TEngine，以减少重复基础设施。新增类型/泛型组合若进入IL2CPP/HybridCLR发布，应加入后续AOT验证范围。

拟新增 `Module/BattleModule/Bridges/BattleEventBridge.cs`、`Core/Battle/Event/` 与 `View/PresentationLease`。未来检查：监听解绑、回调只能下一Tick命令、取消不丢已提交事实、旧异步结果不污染新实例、队列满可观测。本次未执行。
