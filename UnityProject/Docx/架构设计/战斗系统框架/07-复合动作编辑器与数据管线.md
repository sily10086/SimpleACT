# 复合动作编辑器与数据管线

日期：2026-10-25；v0.1。对应原文 01/02/03。这里统一的是动作语义和时间轴，不是重新实现三种动画引擎。

## 1. 策划制作内容

创建 ActionDefinition → 拖入源动画 → 按顺序拼接 → 标前摇/有效/后摇 → 配 Hitbox 与 Hurtbox → 配取消/无敌/霸体窗口 → 配逻辑命令和表现事件 → 绑定动作图节点 → 导出。

编辑器分资产库、预览、时间轴、属性面板。时间轴至少支持：帧尺、拖拽、吸附、逐帧步进、撤销重做、复制片段、框体预览、错误定位和引用查询。运行预览应调用相同 Timeline 求值器，避免编辑器另写一套“看起来相同”的规则。

## 2. 功能分期

| 功能 | 首版 | 后续及原因 |
|---|---|---|
| 顺序拼接 | 支持 | 动作闭环必需 |
| 相位/窗口/事件/判定框轨道 | 支持 | 策划能独立调整一招 |
| 相位变速 | 先导出重定时为整数帧 | 运行时倍率待跨帧事件规则完成 |
| 条件分支 | 交给动作图 | 避免时间轴内再造第二路由器 |
| 循环蓄力 | 显式循环段+退出条件 | 首版只支持一个受控循环，不支持任意嵌套 |
| 分层遮罩、叠加 | 暂缓 | 依赖骨骼后端和通道资源仲裁 |
| 跨后端同时混合 | 不作为首版目标 | 不同骨架/材质不存在自动姿态插值 |

原文要求“拖入就能播放”可作为默认体验；但 missing binding、负长度、同名ID、缺资源必须提示并阻止发布，不能为了便利导出半成品。

  "contentVersion": "combat-demo-001",
  "tickRate": 60,

## 4. 编译管线

```text
编辑源资产
  → DTO（保留稳定ID与原始时间）
  → Validate（类型、引用、区间、循环、兼容能力）
  → QuantizeAndRetime（记录量化策略和警告）
  → BuildIndexes（稳定ID映射、按帧排序、邻接表）
  → Export JSON + manifest + content hash
  → 可选构建期二进制缓存
  → 加载阶段 Decode → 不可变运行快照
```

源时间秒转帧默认采用明确的 round-half-up，`floor(seconds*60+0.5)`（非负时间）。区间和事件均显示量化前后值；如果有效区间被压成0帧，导出失败并要求修改，不能悄悄扩成一帧。原文所谓亚帧修正只有在明确子帧模拟需求时再引入，不能同时承诺所有时间纯整数。

拼接/变速后按 source→action 映射重算事件和窗口。同一事件在两个重叠片段中是否复制由事件 trackId+keyId 决定，去重不是按时间相同随意删除。

## 5. schema 与热更

Manifest 记录 schemaVersion、内容hash、需要的机制版本、资源ID和动作图引用。加载只接受兼容版本；不认识的逻辑命令禁止开局，不能忽略后继续战斗。解析错误返回资源名+字段路径+原因。

一场战斗固定内容快照；新数据在下一场生效。编辑器可提供显式 RestartWithNewData，首版不做战斗中热替换动作定义。新动画资源仍需走 YooAsset 发布流程；新逻辑类型可能需要热更代码/AOT准备，JSON不能绕开这些边界。

Luban 适合单位、伤害、Buff、许可和数值配置；UAnim适合时间轴、图和表现绑定。两者引用共用稳定ID注册表，导出时交叉校验，不维护两份伤害公式。

## 6. 真正接入项目的制作步骤

1. `GameEditor/BattleAuthoring/` 增加 DTO 编辑器、时间轴视图、导出器；先用基础 Inspector/列表完成数据制作，后追加画布。
2. `GameLogic/Core/Battle/Data/` 放运行时不可变类型；编辑器程序集按需要显式引用运行时 schema；运行时不能引用 GameEditor。
3. 编辑源建议 `Assets/GameData/BattleAuthoring/`；导出产物 `Assets/AssetRaw/Configs/Battle/`；将产物纳入资源收集配置。路径为提案，未创建资产。
4. 图编辑参考 xNode/NodeGraphProcessor，但只输出自己的运行数据，运行时不依赖编辑器节点对象。
5. 首版导出检查与错误面板先完成，再扩展拖拽美观效果。

未来验收：缺资源、ID重复、窗口越界、循环无退出、无权限后端、数值引用缺失均可定位；相同源数据重复导出稳定；预览与实际步进一致。未执行。
