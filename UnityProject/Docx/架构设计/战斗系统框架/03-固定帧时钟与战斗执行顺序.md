# 固定帧时钟与战斗执行顺序

日期：2026-10-25；v0.1。对应原文 00/05/09/13。本页规定推荐语义，尤其不能把渲染帧数、逻辑 Tick 和动作局部帧混用。

## 1. 时间模型

| 时间 | 用途 | 暂停/时停 |
|---|---|---|
| 宿主实际经过时间 | 调度器决定应执行几个 Tick；UI、下载超时 | UI 可继续；不直接关闭战斗窗口 |
| SimTick，60 次/模拟秒 | 世界阶段、输入命令时间戳、全局效果 | 全局暂停不推进；局部时停仍推进 |
| UnitTick | 单位 CD、Buff、硬直的默认时间域 | 该单位冻结则不推进 |
| ActionFrame | 当前动作的相位、窗口、攻击框、动作事件 | 冻结或暂停不推进；速度倍率改变推进量 |
| PresentationTime | 渲染插值、UI、混合 | 不参与命中裁决 |

时停持续时间用 SimTick，不能用被冻结者的 UnitTick，否则永远不会结束。每种 Buff 必须声明时间域；默认 OwnerUnit，世界危害可用 SimTick。全局暂停清除调度器暂停期间积累的宿主时间，恢复不补暂停期间的战斗帧。

Unity 当前项目 `TimeManager.asset` 的 Fixed Timestep 为 **0.02（50Hz）**。因此不能直接说现有 FixedUpdate 已是 60Hz。推荐 BattleModule 用单个 Update 驱动固定步长累积器，首版逻辑碰撞采用显式查询；不同时依赖自动 Physics Tick 推进同一战斗。

Unity 的 FixedUpdate 在一个渲染帧中可能执行多次，存在最大时间步限制；原文“1FPS 固定只推进一帧”不是固定步长的必然行为。[Unity 2022.3 时间说明](https://docs.unity3d.com/2022.3/Documentation/Manual/TimeFrameManagement.html)

## 2. 调度器建议

```text
OnHostUpdate(unscaledDelta):
  采集设备边沿到原始输入队列
  if paused: accumulator=0; return
  accumulator += unscaledDelta
  steps=0
  while accumulator >= 1/60 and steps < MaxStepsPerRender:
    Step(SimTick)
    SimTick += 1
    accumulator -= 1/60
    steps += 1
  if accumulator超过允许积压:
    记录Overload，限制积压；模拟进入可观察慢放
  RenderInterpolation(clamp(accumulator / step, 0, 1))
```

演示建议每渲染帧最多 4 步、积压最多 4 步；是待压测配置，不是已验证性能指标。截掉的是宿主时间债务，**不是跳过 SimTick 或跳过动作事件**。联网模式不能默默使用这种降级，需要服务器时间/追赶策略另案设计。

设备边沿只入队一次；一个渲染帧执行四个 Tick 不能把同一次按下变成四次攻击。命令分配至下一可执行 Tick，记录实际分配结果用于回放。

## 3. 一个 Tick 的固定阶段

所有单位按稳定 EntityId 处理，不采用每对象 MonoBehaviour.Update 的任意顺序。

| 阶段 | 工作 | 生效边界 |
|---|---|---|
| P0 开始 | 接收外部命令；按到期规则移除效果；合并上帧延期请求 | 形成当前状态基线 |
| P1 意图 | 必要感知更新、AI 决策、原语语义化、清过期输入 | 读取同一语境快照 |
| P2 动作准备 | 预先存在的强制迁移优先；许可；候选动作事务提交 | 进入动作时执行 frame=0 命令 |
| P3 时间轴与运动 | 计算当前局部帧窗口、命令；推进 Motor；构建运动前后几何 | 攻击框先于碰撞生效 |
| P4 收集 | 收集所有碰撞候选，稳定排序与分组 | 不扣 HP，不播放受击 |
| P5 结算 | 无敌/弹反/格挡/命中去重，计算伤害和效果，批量提交 | 使用本 Tick 战斗快照确定同时关系 |
| P6 反应 | 死亡、削韧破防、击退迁移；关闭旧动作；追加取消结果 | 不再回到 P3 重复造命中 |
| P7 完成 | 已提交结果桥接、保存快照；推进各时间域计数与动作游标 | 下一 Tick 使用新状态 |

当 P6 改变了动作，当前 Tick 的最终表现请求取新状态最高优先级者；被替换的 P2 播放请求不必真的显示。新反应的逻辑 frame=0 在 P6 只做安全初始化，碰撞相关执行从下一 Tick 的 P3 开始。整套系统不通过监听顺序回到同 Tick 重入。

**同时互击推荐**：同一 Tick 已进入 P4 的有效接触均按结算快照判定；P5 同时计算，P6 处理双死。若已有精确接触时间，可按子时刻分组；较早的死亡可排除后组攻击，但必须全系统统一，不能只给玩家特殊提前结算。首版选择 Tick 批次互击，精确子时刻作为后续能力。

## 4. 帧区间唯一约定

所有区间使用 `[start, end)`：start 生效，end 不生效。动作 24 帧的有效索引为 0–23；在帧 24 边界自然结束。取消窗口 `[14,20)` 允许 f=14…19；进入下一动作从 f=0 开始。第0帧事件必须独立处理，不能只用 `previous < eventFrame <= current` 从 0 开始而漏发。

终止/取消后不补发被跳过的攻击事件；但必须通过统一 Cancel 路径关闭 Hitbox、撤销动作临时标签和释放占用。不要把关闭碰撞框仅做成最后一帧事件。

## 5. 变速、卡肉与时停

首版动作速度固定 1，先完成冻结和暂停。扩展倍率时使用有理数/定点累积局部帧进度；从 f=10 到 f=12 必须处理跨过的 f=11 事件与窄命中窗口，不能仅采样终点。拆分子步/扫掠区间后再进入统一结算，超大倍率应在配置校验阶段限制。

HitStop：冻结指定单位 ActionFrame 和 Motor；单位 Buff/CD 是否冻结由时间域决定，默认同 UnitTick。TimeStop：冻结敌方单位推进和攻击输出，但是否可被玩家命中另设规则，不能等同于销毁其 Hurtbox。暂停则冻结整个 BattleWorld。

## 6. 回放承诺范围

首版目标是可诊断的固定顺序执行，不声称已经确定性验证。重演至少记录：规则与资源版本、初始状态、命令及分配 Tick、随机种子/状态、实体生成顺序、时间域变化。Unity 物理和浮点运动需另行确认稳定性。若只记录权威结果播放，可做演出回放，但不能据此验证战斗逻辑。

未来目标：BattleClock、TickPipeline、TimeDomain、ReplayHeader。验收用例：30/60/144FPS 同输入；一帧跨两个事件；第0帧；暂停恢复；局部冻结到期。均为未来计划，本次未运行。
